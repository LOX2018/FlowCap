## 0. 用户原话（判据来源）

> 「首先这些发送的话术有很大问题，部分弹幕已经说了骨折，生成回复还让别人说伤情。
> 『鼻骨骨折鼻中隔骨折，保守治疗』明显是问等级，生成的却是赔偿的内容。而且对于弹幕的内容
> 不要直接说有等级/没等级，直接让发病例，先引导对话，不要直接给答案。另外很多会话确实
> 投递成功了，但投递成功不代表传递送达，发送 40 条实际送达只有 13 条左右，更关键的是
> 实时弹幕区域有区域限制，只显示 20 条左右后续的弹幕都不显示，把该区域设为滚轮式」

## 1. 三缺陷取证（只读取库快照 + 源码，全部实测）

### D-1 话术：三处输入侧缺锚 + 一条绕过护栏的快捷路径

| # | 根因 | 证据 |
|---|---|---|
| ① | **命中库是最高优先级短路分支**（命中即回、零 token、**绕过全部出口护栏**），而库内 **28 条全部 `source=auto`**（自动学习碎片）。含 `Q「没有保守治疗」→ A「有等级，工伤10级」`、退化的 `Q「拿到认定结果了吗」→ A「拿到认定结果了吗」` | 库快照 `ai_reply_chat_replies` 逐条读出 |
| ② | **直播与私信共用同一个 Agent prompt**，其第 ① 条原文要求「拿到伤情就给判断…**给出等级的初步口径与依据**」——**方向与用户新要求相反**；`generate_dm_for_live` 只追加了一句「这是第一条私信…紧扣公屏发言」，**无任何「不判等级 / 先引导」的专用规则** | `ai_agents.ag_88387f9ee4e34dc1` 原件 + `ai_reply.py` 场景追加段 |
| ③ | **兜底池在顶班**：截图里「理解您的情况。请您说下：哪里受的伤…」逐字等于兜底池第 4 条 ⇒ 该条**不是 AI 生成**，是护栏拦下后的兜底 | `_DEFAULT_CONFIG.fallback_pool` 逐字比对 |

附：pin 在回复里出现 `**大概率评不上等级**` 的 Markdown 星号（私信纯文本，会原样显示给客户）。

### D-2 投递 ≠ 送达：「入池」被当成「已发送」

**唯一读库**（`members/m17db0f8209156f26/data/flowcap.db` 只读副本），2026-09-29：

| 读数 | 值 |
|---|---|
| 受理成功（`[投递验证]` 带真实 `server_message_id`） | **19** |
| 平台拒收回执（「对方回复或关注你之前，只能发送一条文字消息」） | **34**（全库 172） |
| 按**对端**归并 | 送达 **13** 会话 / 仅收到平台提示 **24** 会话 |

⇒ 与用户「40 条实际送达 13 条左右」**逐项吻合**。

**时序铁证**（同一天）：`12:14–12:22` 连续 9 条「local 写入 + `msg_type='7'` 回声 + 投递标记」三证齐全；
`12:23` 起每条**只回平台提示**，无回声无标记 ⇒ 账号级静默限流（前 9 条成功后平台开始逐条拒收）。

**为何 UI 仍报绿色「已发送」**：`core/dispatch.py` 把 `submit_by_uid` 返回
`accepted=True`（**已入池**）直接置 `RecordStatus.SENT`；M-5 钩子只往 DB 写标记、
**从不回写调度记录** ⇒ 送达口径在 UI 上**没有出口**，平台拒收回执**完全没进闭环**。
（与台账 H-20「`/show` 把『受理』冒充『达成』」**同形态第二次复发**。）

### D-3 弹幕区只显示约 20 条

`components/live/live-page.tsx` 的「实时评论统计列表」：`rows.slice(0, 12)`
**硬截断到前 12 行**，外层只有 `overflow-x-auto`（横向）——**无纵向滚动容器、无分页**
⇒ 第 13 行之后的弹幕**永远不可见**（诊断层不可观测即缺陷被掩盖，与 D-2 同族）。

## 2. 决策（D1~D4）

### D1 直播首触**默认不再查命中库**
新增 `ai_reply_config.live_reply_kb_enabled`，**默认 `False`**；
直播 `generate_dm_for_live` 的命中库查询置于该开关之后。私信侧**不受影响**
（另由 `strict_level` / `reply_sem_enabled` 控制）。
> 取舍：命中库的价值（零 token 直回）在直播首触场景**低于**它的风险（绕过全部护栏 + 存量碎片污染）。
> 用户拍板「保留开关可打开」，故不做删除式下线。

### D2 直播首触专用场景契约（**覆盖式**，不动私信）
新增 `_LIVE_CONTACT_RULES` 追加进 prompt（放 **last**、紧贴 user 消息、显式声明
「覆盖上文任何相反要求」），内容：禁报等级/结论/金额；不得说「有/无等级」；只给方向性口径；
一次只问 1~2 项；已说过的信息不重复问。

**为什么用「覆盖」而不是改 Agent prompt**：Agent prompt 是**两个场景共用**的，
改它会同时改变私信行为（越权）；且它是用户资产（用户可自定义），
场景契约属**系统约束**，必须在系统侧确保「无论用户怎么写 prompt 都成立」。

### D3 直播出口**场景护栏**（与「专业准确性护栏」分离）
新增 `_live_guard_violation`：① 任何「N 级」；② 有/无/评上/评不上…+等级；
③ 赔偿金额或清单承诺。经 `validate_reply(..., live_guard=True)` 只在直播出口启用
（默认 `False` ⇒ 私信**逐字不变**，零回归）。
> **与 `_RE_ASSERTIVE` 的分工**（不可互相替代）：后者管「结论**对不对**」（与专业知识相悖），
> 前者管「**该不该在这个场景出现**」（无依据断言本身）。首触没有下结论的依据，
> 所以判据是**场景**而非正确性。

### D4 「受理 / 送达 / 被平台拒绝」三档口径
- 新增**只读**判定出口 `services/delivery_verify.delivery_state_of(account, conv_id|uid)`
  → `delivered` / `rejected` / `""`，**不改任何写入路径与时序**；
- `api/tasks.py::_records_from_adm` 增下发 `delivery_state`（`sent/captured/fail` 语义**逐字不变**，不破坏别处消费点）；
- 前端 `live-shared.displayStatus()`：**拒收优先于受理**；`DM_META.sent` 文案改「已受理」；
- 统计条改「已受理 N · 已送达 M · 被平台拒绝 K（送达率 x%）」。

### D5 弹幕区滚轮式（用户指定「实时评论统计列表」）
全量渲染 + 纵向滚动容器（`overflow-auto` + `overscroll-contain`）+ 表头 `sticky`；
容器高度 `clamp(320px, calc(100vh-560px), 620px)`；另加**仅看异常**呈现过滤开关（不参与任何统计口径）。

| 层 | 命令 | 结果 |

| 实机（三段） | `python scripts/verify_live_contact_fix.py <库快照>` | **全部 PASS** |

| 前端类型 | `npx tsc --noEmit` | **exit 0** |
| 全量回归 | `python -m unittest discover` | 见 §验证记录 |

### 3.1 实机验证**当场抓出我自己写的两个缺陷**（诚实记录）
1. **`conv_id` 形态**：实库 `0:1:对端:自己` 与 `0:1:自己:对端` **两种方向并存**，
   初版只拼一种 ⇒ 170 条不一致。修法：复用 SSOT `conv_identity.peer_uid` 解析对端后，
   同时匹配两种规范形态（精确 `IN`，不用两端 `LIKE`）。
2. **`msg_type='7'` 是双方共用码**：对方发来的普通文本也是 `'7'`
   ⇒ 初版把对方留言误当「回声帧」⇒ **假送达**。修法：回声判据必须同时限定 `role='me'`。
   （本条已固化为 L1 用例与负控。）

## 5. 已知边界（诚实标注）

1. **平台限流不因本 ADR 消失**：本次修的是「**如实呈现 + 不再无依据答话术**」，
   不修「账号被平台限流」本身。后续若要把送达率提上去，应走**降低陌生首触频次 /
   提高触达质量**（另立议题），不属本 ADR。
2. `delivery_state` 依赖 `msg_type='7'` 回声帧作为送达指纹；若某账号长期不落回声帧，
   该条会显示「已受理」而非「已送达」（**宁缺勿错**，不臆断）。
3. 命中库**存量 28 条 auto 碎片未清理**（本 ADR 只做「直播侧不查」，私信侧仍可命中）。
   存量治理见 ADR-025 的通用性门槛与待确认区流程。
4. L3 真实网关调用的产出**随模型波动**（同一弹幕两次可能不同），门禁断言的是
   **不变量**（出口不得含等级/金额断言），不是具体文案。
