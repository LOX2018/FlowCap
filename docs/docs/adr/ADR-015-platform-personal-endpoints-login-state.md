# ADR-015：内容板块「本人端点」的登录态失效语义

- **状态**：已采纳（Accepted）
- **日期**：2026-09-26
- **版本**：v0.45.10
- **提交**：`c9f105a`
- **关联案例**：`工作记忆/cases/2026-09-26_内容板块三tab不可用_凭证过期伪装为空数据_case_v0.45.10.md`
- **前置 ADR**：ADR-014（内容板块 argus 403 签名断链 —— 同一板块的另一根因）

---

## 背景（Context）

内容板块「点赞 / 收藏 / 站内通知」三个 tab 同时不可用。实测根因：

**账号 cookie 已于 2026-09-24 20:09 过期**（`sid_guard` exp=1790251779），
服务端对**所有「本人相关」端点**返回：

```
HTTP 200
{"status_code": 8, "status_msg": "用户未登录"}
```

而 `feed` / `search` 等**公开类端点**仍返回 `status_code=0` 且数据正常 ——
因为它们**不校验登录态**。

原实现的两个缺陷：

1. 把 `sc=8` 一律解释为「短时高频限制，**稍后重试即可**」→ 在**硬过期**下是误导
2. `get_user_favorite` / `get_notice_list` **不抛异常**、直接返回 `sc=8` 的 dict
   → 业务层不判定 ⇒ **静默返回空列表** ⇒ UI 显示「暂无数据」

---

## 决策（Decision）

### D1. 「本人端点」必须显式判定 `status_code`

**规则**：凡返回「HTTP 200 + 业务错误码」的平台接口，业务层**必须显式读 `status_code`**，
**不得**依赖异常机制。新增 `_is_not_logged_in(raw)` 作为统一判定。

**理由**：这类接口的设计契约是"HTTP 层永远 200，错误在 body 里"。
把异常当错误通道 = 契约误读（上游 `Douyin_Spider` 同样如此）。

### D2. 登录态判据**复用** `auto_dm.accounts.verify_credential`，不另造

**规则**：`api/platform.py` 的 `_login_state_reason()` 内部调用既有
`verify_credential`，产出与「账号管理」页**同源**的原因。

**理由**：两处判据若各自演化，必然漂移（一条说"只读"、一条说"高频限制"），
用户会看到互相矛盾的结论。**判据 SSOT 只能有一处**。

### D3. 降级文案必须包含**可行动指引**

**规则**：`unavailable:true` 时，`reason` 必须同时给出 **① 真实原因** 和
**② 下一步动作**（如"请在账号管理执行【重新扫码】"）。

**理由**：`unavailable` 的价值在于把"用户不知道发生了什么"变成"用户知道该做什么"。
只给原因不给动作，用户仍卡住；给错误的原因（"稍后重试"）则**比不给更糟** ——
它让用户等待一个永远不会到来的自愈。

### D4. UI 必须区分「取不到」与「暂无」

**规则**：空列表 + `unavailable:true` → 显示"暂时取不到 + 原因"；
空列表 + 无 `unavailable` → 才显示"暂无 XXX"。

**理由**：这是本次缺陷的**直接用户可见表现**。两者外观相同、语义相反，
合并显示等于**隐藏故障**。

---

## 后果（Consequences）

### 正面

- 用户能立即分辨"没数据"与"登录过期"，并知道要重新扫码
- 三 tab 的原因同源，与账号管理页**不会打架**
- 建立了模式：后续新增本人端点（关注列表、收藏夹等）可直接复用
  `_is_not_logged_in` + `_login_state_reason`

### 负面 / 代价

- `/liked` `/favorite` `/notice/list` 在**凭证过期时多一次** `verify_credential` 调用
  （该调用可能触发探活/指纹浏览器唤醒，**有延迟**）
  - **缓解**：该路径**只在失败时**触发（成功路径零开销）；
    且失败时用户本就无法继续操作，延迟不增加额外损失
- 判断依赖 `verify_credential` 的实现细节（`dm.detail` 含 "609"/"只读"）
  - **风险**：若该函数文案变更，映射会失效 → **缓解**：已加 `try/except` 兜底回落通用文案

### 未解决（边界）

- **凭证过期本身不会被自动修复** —— 本 ADR 只解决"**让用户知道要重新扫码**"，
  不解决"自动重登"（后者涉及扫码，无法自动化，属设计边界）
- `profile/self` 的 HTML 回退路径（抓 `douyin.com/user/self` 正则抠 secUid）
  **仍不可靠**，本次未动（属另一议题）

---

## 备选方案（Alternatives Considered）

| 方案 | 否决理由 |
|---|---|
| A. 保持"稍后重试"文案，仅加日志 | 用户仍被误导；日志他看不到 |
| B. 前端自动重试 N 次 | 对**硬过期**无效，只是浪费请求 + 拖长等待 |
| C. 自动触发重新扫码 | 扫码需人介入，无法自动化；且**不得静默弹窗打扰** |
| D. 在 platform.py 内自建判据 | 与账号管理页判据漂移 → 用户看到矛盾结论（违反 D2） |
| **E. 复用 verify_credential + 可行动文案（采纳）** | —— |
