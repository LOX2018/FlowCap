## 0. 背景与判据

用户要求「审计今日的修改」→ 先出**人工审计**（可复跑读数），再按用户指令补跑 **OCR 外部审计** 并做三栏对账。

按「外部报告是输入不是结论」纪律：逐条自验后才进修复队列。

## 1. 关键发现（推翻人工审计的一处正向结论）

| 项 | 人工审计原判 | OCR + 自验结论 |
|---|---|---|
| 「受理 ≠ 送达」口径拆分（v0.45.92 交付） | ✅ 已落地 | 🔴 **假落地**：`tasks.py:140` `getattr(adm,"account_name","")` —— `AutoDM` **自身无**该属性（只 set 在 `monitor_auth`/`auth` 上）⇒ `_acct` 恒空 ⇒ `delivery_state_of()` **从不被调用** ⇒ 前端「送达率/拒收」恒为 0 |
| 留资护栏 `max_lead_ask` | ⚠️ 缺「拒绝停止条件」 | 🔴 **更严重**：`else` 回退分支**无条件** `append_lead_ask`+`_bump_lead_ask` ⇒ **每轮继续索要，上限从未生效**（与 ADR-027 D5 承诺直接矛盾） |

**方法论教训**：人工审计做的是「代码是否存在」的静态判据；OCR 做了「属性是否真存在」的**接线判据**。
假落地（假成功/死接线）只能靠**跨层对账**发现 ⇒ 后续审计必须含该维度。

## 2. 决策

1. **按「文件所有权」分 9 桶并行修复**（非按事项编号），每桶唯一文件集、唯一报告路径；已反查无文件落两桶。
2. **跨桶耦合解耦**：硬编码业务数字矛盾（24 vs 34）统一改为「不含数字的定性描述」，三方无需一致。
3. **版本升版 + git 提交由父会话最后统一做**；子 agent 一律禁止 git 写与改版本号。
4. **真机类验证不假报**：连麦真实申请 / BCC 漂移恢复 / 事件循环真机延迟 —— 子 agent 只做单测级，报告标注「待真机」。
