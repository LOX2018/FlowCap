# 案例：非受控折叠组件驱动的 UI 事件 —— 「编辑按钮点了没反应」

- **日期**：2026-09-28
- **报告人**：用户（LOX）实测报障
- **触发原话**：「知识库"对话回复库"的编辑按钮点击后无反应」
- **版本**：v0.45.80
- **门禁**：`backend/test_ui_collapse_controlled.py`（5 项，含负控）

---

## 1. 现象

知识库 → 子页「对话回复库」→ 列表某条点「编辑」→ **界面上毫无变化**（无报错、
无 toast、无网络请求），用户观感「按钮坏了」。

## 2. 排查链（Execution-Chain Traceability）

```
点「编辑」按钮
   ↓ onClick: setEditId(it.id) / setQ(...) / setA(...)
   ↓ 期望：编辑面板展开并回填
<Collapse title={editId ? "编辑话术" : "添加话术"}
          defaultOpen={editId !== null}>      ← ★ 断点
   ↓ kit.tsx:  const [open, setOpen] = React.useState(defaultOpen)
   ↓ React 语义：defaultOpen 只是 useState 的**初始值**，仅在首次挂载时读取
   ↓ 该折叠块在页面挂载时就已渲染（首帧 editId=null ⇒ open=false）
   ⇒ 之后 editId 变化 → defaultOpen 新值被**忽略** → open 保持 false
   ⇒ 面板不展开 ⇒ 观感「点了没反应」
```

**终端现象之所以「完全没有反应」**：三个 setState 都执行了，只是它们的效果
（面板展开）被非受控组件吞掉，页面上没有任何可见变化，也没有报错 → 最容易被
误判为「按钮事件没绑上」。

## 3. 取证（真实浏览器，非静态推断）

用 Chromium 加载真实组件（临时验证入口挂真实 `ReplyKb` + 桩数据，零数据副作用），
复现用户操作序列：

| 判据 | 实测 |
|---|---|
| 点击前「客户问法」输入框数 | **0**（面板收起，符合预期） |
| 点第 1 条「编辑」后输入框数 | **1** ✅ |
| 面板标题变为「编辑话术」 | **True** ✅ |
| 回填内容 | `你们这个啥价格`（= 该条 question）✅ |
| 「取消」按钮出现 | **True** ✅ |
| 连点第 2 条 → 回填切换 | `能便宜点吗`（第 2 条）✅ |
| 再点回第 1 条 | 正确切回 ✅ |

> 修复前的行为（由代码语义确定）：以上「点击后」的判据**全部失败** —— 输入框恒 0。

## 4. 根因（两层，缺一不可）

1. **组件契约缺口（根因）**：`Collapse` / `Card` **只提供非受控 `defaultOpen`**，
   无法表达「外部事件要求展开」；消费方用表达式驱动 `defaultOpen` 是与该契约
   不匹配的用法，而**错不在消费方** —— 折叠组件的展开态若能由外部事件驱动，
   就必须支持受控模式（标准 React 语义）。
2. **同型缺陷扩散**：`AuthorizationCard` 用 `defaultOpen={pendingList.length > 0}`，
   而待审列表是**异步**拉取的（挂载时为空）⇒ 数据到达后**永远不展开**，
   待审项被折叠在下面用户看不见（同类、同批修）。

## 5. 修复

- `components/page/kit.tsx::Collapse` 与 `components/settings/notify-widgets.tsx::Card`
  **补受控模式**（`open` + `onOpenChange`），保留原非受控行为（不传 `open` 即旧语义）。
- `kb/reply-kb.tsx`：编辑面板改**受控**（`open={panelOpen}`）；点「编辑」显式
  `setPanelOpen(true)`，并 `scrollIntoView` 让面板进入视野（面板在列表上方）；
  保存成功 / 取消时收起；标题加「正在编辑第 N 条」副标题；编辑按钮加稳定锚点
  `data-od-id="reply-kb-edit-<id>"`。
- `settings/AuthorizationCard.tsx`：改受控 + **待审出现时自动展开一次**
  （用户手动收起后不再强行展开，尊重其意图）。

## 6. 验证

- 门禁 `test_ui_collapse_controlled.py` **5 passed**（C1 受控分支存在 / C2 回归锚点 /
  C3 编辑按钮显式展开 / C4 异步展开 / C5 负控）。
- **真实浏览器 E2E PASS**（见 §3 表）。
- `tsc -b` 无 error。
- 门禁最初被**我自己写的解释性注释**误伤（注释里引用了旧写法）⇒ 已改为
  「剔除注释后断言实际代码」，并把该教训写入门禁注释。

## 7. 可迁移判据（跨项目）

1. **`defaultOpen` 不是「外部可驱动」的展开态**：React 的 `default*` props 只是
   初始值，**挂载后对 props 变化无响应**。凡「点 A 展开 B」「异步数据到达后展开」
   都必须用**受控**（`open` + `onOpenChange`）。
2. **缺陷可能是「契约缺口」而非「消费方写错」**：本案消费方表达意图的方式是合理的，
   是组件不支持该意图。修在**组件**（一处）> 修在每个消费方（多处）。
3. **「完全没反应」优先怀疑 `default*`/非受控/状态被吞**，而不是怀疑事件没绑：
   三处 setState 都执行了、页面上却毫无变化，正是这类缺陷的签名。
4. **排查同类扩散**：修一个 `defaultOpen` 用法后，应全库 grep 同型用法
   （本案又抓出 `AuthorizationCard` 的异步展开缺陷）。
5. **静态断言要么只看代码、要么承认自己会被注释骗**：断言前剔除注释行，
   否则「解释性注释里引用旧写法」会让门禁误红（本案实测踩到）。
6. **UI 验证要用稳定锚点**：`get_by_role(name="编辑")` 是**子串**匹配，面板标题
   「编辑话术」展开后也会命中且 DOM 更靠前 ⇒ `nth()` 漂移，会伪造出「第二条点不动」
   的假象（本案实测踩到，一度误判为产品 bug）。应加 `data-od-id` 之类稳定锚点。
