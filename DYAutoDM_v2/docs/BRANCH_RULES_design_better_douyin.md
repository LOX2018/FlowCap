## 三、本分支新增规则（照源项目）

### 3.1 接口方式基准 = `docs/reverse_interface_spec.md`

逆向所得（实测提取，非推断）：
- **双域名**：`www.douyin.com`（写/主）+ `www-hj.douyin.com`（读列表）
- **IM 域名**：`imapi.douyin.com` + WS `wss://frontier-im.douyin.com/ws/v2`
- **签名**：`a_bogus` / `x-bogus` / `msToken` / `x-secsdk-web-signature|expire` / CSRF 三件套
- **TicketGuard**：`ticket=&path=&timestamp=` → `ts_sign`/`req_content`/`req_sign` + REE 公钥
- **身份三元组**：`s_v_web_id`/`verifyFp`/`uifid`/`webid` + `screen_*`/`cpu_core_num`
- **UA 池**：5 套（Edge151 / Firefox117 / iOS Safari / Edge125 / Chrome）

### 3.2 频率控制模型 = 照源项目（**取代主分支闸门**）

```
auto_send_delay_ms            自动发送延迟（毫秒）
auto_scan_interval_seconds    扫描间隔（秒）
auto_max_actions_per_run      单轮最大动作数   ← ★ 核心限速参数
auto_require_context          需上下文才动作
auto_min_digg_count / _comment_count / _play_count    互动门槛
auto_match_keywords / _exclude_keywords               关键词准入/排除
（监控类）
user_interval_seconds         每目标检查间隔（前端约束 10~1440 分钟，默认 60）
max_new_downloads_per_check
```

**判据**：源项目**无全局闸门**（`rate_limit`/`backoff`/`throttle` 提取 0 命中），
风控靠「**按动作限速 + 关键词准入 + 互动门槛 + 单轮上限**」。

### 3.3 安全网关归因（照源项目的错误标识）

```
RELATION_SECURITY_GATEWAY: HTTP 403    ← 关系类操作（关注/收藏/点赞）独立网关
bd_passport_security_gateway            ← passport 网关
HTTP 403, TicketGuard                   ← 403 归因到 TicketGuard
```
**要求**：实现时**保留这些归因标识**，便于定位是哪层被拦。

## 五、风险声明（诚实记录）

| 风险 | 说明 |
|---|---|
| **账号安全** | 纯 HTTP + 凭证复用 + 主动查询是主分支**实机踩坑换来**的红线（2026-09-08 幽灵 uid、09-13 登录态强制下线）。本分支解除后，这些风险**真实存在**。 |
| **不可逆** | 若账号被风控/封禁，恢复成本高。 |
| **非源项目等价** | 源项目的对抗手段（TicketGuard EC 曲线细节、a_bogus 算法内核）**仍未知**——逆向只得到**参数名与流程骨架**，算法内核闭源。**照抄参数名 ≠ 照抄算法**。 |
| **无实测对照** | 无法运行源项目二进制实测其真实请求（macOS arm64，且需真实账号），故"源项目不被风控"**未经实测验证**。 |
