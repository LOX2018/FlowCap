## 1. 背景

用户要求：在「直播间」板块，按现有「配置管理」按钮的样式**复刻一个「直播间管理」按钮**，
点开的管理页用于：**填直播间链接 → 自动解析出房间** + **填备注** + **绑定直播策略** +
**是否支持脱敏**。

## 3. 决策（用户 2026-09-22 已确认）

### 3.1 数据模型：**房间与策略分离**

| 层 | 载体 | 内容 |
|---|---|---|
| **策略**（怎么发） | kv `live_room_configs`（**不动**） | 发送参数（现状不变，零迁移） |
| **房间**（在哪发） | **新增kv `live_rooms`** | 身份 + **策略引用** + 脱敏开关 |

一份策略**可被多个房间复用** ⇒ 房间记录只存 `strategy_id` 引用。

### 3.2 `live_rooms` 记录契约（房间 id 形如 `lr_<epoch_ms>`）

```json
{
  "id": "lr_1758...",
  "room_id": "992931212705",
  "live_url": "https://www.douyin.com/follow/live/992931212705?anchor_id=...",
  "name": "自营-工伤咨询",          // 用户填的备注
  "strategy_id": "lc_1758...",      // 引用 live_room_configs；空 = 未绑定
  "allow_desensitized": false,      // 是否支持脱敏监听（默认 false）
  "updated_at": 1690000000
}
```

### 3.3 脱敏布尔语义（与 ADR-002 §3.6 的关系，**必须写清避免撞概念**）

- 全局「脱敏处理策略」（ADR-002 §3.6，默认「跳过」）＝ **默认行为**。
- 本页布尔 `allow_desensitized` ＝ **该房间的覆盖开关**：
  - `false`（默认）⇒ 按全局策略走（默认即「跳过，不监听」）；
  - `true` ⇒ 即使检测到脱敏也**继续监听**，但只做**仅统计**（在线数/热度/开播检测），
    **不采真实昵称/uid、不发送私信**（无解密权时本就拿不到身份）。
- ⇒ **一个概念、两级粒度**，不新增第三套「脱敏策略」概念。

🔴 **诚实标注（须告知用户）**：按 ADR-002 §3.6 的实测结论，**解密权取决于房间归属**
（自营有 / 他人默认脱敏，与凭证无关）。故 `allow_desensitized` 的实际用途是
「**允许盯一个我没解密权的房间做统计**」，**不是**「能拿到它的昵称」。

### 3.4 引用完整性：删除策略必须处理悬空引用

现状 `delete_strategy` 注释写「无任何跨模块解绑副作用」——**引入引用后不再成立**。
⇒ **删除策略时自动解绑**所有引用它的房间（把 `strategy_id` 置空），并在响应里返回
解绑数量（`unbound: N`）。**禁止静默留下悬空引用**
（同族先例：删除 Agent 必须自动解绑引用账号）。

### 3.5 迁移

存量 `live_room_configs` 内的**房间形**旧记录（键非 `lc_*`、且带 `room_id`/`live_url`）
⇒ 迁移为 `live_rooms` 的一条房间记录（保留 room_id/live_url/name），
**迁移是一次性显式动作**（脚本或首次读取时惰性迁移），迁移后该策略槽位删除或保留空壳
由实施时定，但**必须可复现且留日志**。

## 4. 页面（复刻 `RoomConfigPage` 样式）

- **按钮**：置于「直播间」板块，与「配置管理」**并排**（同样式，标签「直播间管理」）。
- **页面**：列表（已登记房间）+ 表单：
  1. **直播间链接**输入 → **自动解析**（复用 `/api/live/resolve`）→ 展示解析出的房间号；
  2. **备注**（`name`）；
  3. **策略绑定**（下拉，列出 `live_room_configs` 的策略；可空）；
  4. **是否支持脱敏**（Switch）；
  5. 保存 / 删除；列表项显示房间号 + 备注 + 绑定的策略名 + 脱敏开关状态。

## 5. 验收判据（可机械判定，按 D-07 须自证「失败态会变红」）

- [ ] 新页新增房间 → `live_rooms` 出现记录，字段齐全；**`live_room_configs` 不被污染**（无身份字段写入）。
- [ ] 策略删除 → 引用它的房间 `strategy_id` 置空，响应 `unbound ≥ 1`（**悬空引用 = 0**）。
- [ ] 同一策略被 2 个房间引用 → 删除策略时**两个**房间都解绑。
- [ ] `allow_desensitized` 持久化并在重启后保持。
- [ ] 旧「992931212705」房间形记录迁移后**信息不丢**（room_id/live_url/name 可见）。
- [ ] 前端 `npx tsc -b` 通过；页面在真机渲染（截图/计算样式）。
