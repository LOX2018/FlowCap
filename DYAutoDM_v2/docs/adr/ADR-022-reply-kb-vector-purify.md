# ADR-022：对话回复库「向量提纯」——学习环节从「照搬」改为「沉淀通用」

- 状态：已采纳（2026-09-28，v0.45.70）
- 关联：`services/reply_purify.py`（新）、`services/reply_kb.py`、`api/ai.py`
- 契约文档：`工作记忆/13_业务域_AI与通知.md`

## 背景

用户判定：「聊天内容自动学习……很多东西都是照搬，而且挑选的聊天记录并不具备
通用性，很多都是这个客户的个例。**对话回复库一定要经过向量提纯之后，沉淀的通用部分**。」

**改前机理缺陷**：`reply_kb.learn_from_history` 只做「抽 them→me 对 → LLM 一次性提纯
→ 逐条入库」，**没有任何通用性判据**：同一问法各学一条、客户个例被照搬成"通用话术"、
被问过一次的观点即入库。

**实测取证**：
- 库内 81 条 auto：含具体个案信息的问法 20/81；向量 θ=0.82 下 33/81 属 14 个重复簇；回复 ≤6 字 30/81。
- 对现网 60 对真实问答跑真机提纯：**57 个簇、几乎全是单例 → 达标（≥2 成员）仅 1 簇 → 0 条通用候选**。
- 阈值扫描 θ=0.60~0.85：达标簇恒为 1~3 个，且内容是「好的/好」。⇒ **现网数据里几乎不存在可沉淀的通用问答**。

## 决策

新增 `services/reply_purify.py` 作为**学习环节唯一净化入口**，流水线固定为：

1. 向量化问法；
2. 聚类（余弦 ≥ `sim_threshold`）——同一问题的多种说法归为一簇；
3. **通用性门槛**：只保留成员数 ≥ `min_cluster_size` 的簇；
4. 剔个案成员（数字/地名/伤情/超长）；
5. 簇内 LLM **抽象**成通用问法 + 去个案专业回复；
6. **专业实质门槛**（回复须含工伤域信息）；
7. 与库内既有条目向量去重。

**关键契约**：
- **不降级照搬**：embedding 不可用 → `ok=False` 且零产出（绝不退回写入原文）。
- **LLM 失败即跳过**该簇（不写原样截断）。
- **待确认区**：候选落 `ai_reply_candidates`，经 `/api/ai/replies/candidates/{confirm,reject}`
  人工确认后才升格进正式库（**绝不直接覆盖** `ai_reply_chat_replies`）。
- 参数走配置中心 `dm.learn_min_cluster / learn_sim_threshold / learn_max_case_chars`。

## 后果

- 正向：入库的只可能是「被多个客户以不同说法问过 + 有专业实质」的通用知识；
  照搬个案在结构上被排除。
- 负向/边界：**门槛严格 ⇒ 产出很少**。实测现网 0 产出，这不是缺陷而是信号——
  现有学习数据本身以个案/寒暄为主；要产出通用知识，需**更多量的重复提问**或
  **人工补充专业库（pro_kb）**。
- 移除物：`reply_kb.LEARN_PROMPT`（旧一次性提纯 prompt）删除，提纯 SSOT 归 `reply_purify`。

## 验证

见 `工作记忆/cases/2026-09-28_对话回复库向量提纯_v0.45.70.md`。

## 修订 2026-09-28（v0.45.71）：通用性判据改为「按来源计」

**发现（真机回归）**：初版第 3 步的「通用性门槛」用**簇内原始问法条数** ≥ `min_cluster_size`。
同一客户把同一类问题问 N 遍（实测「测试」×3 **全部来自 1 个会话**）即可凑过门槛，
把寒暄/无信息内容沉淀成「通用问答」。

**修订**：

- 通用性 = 簇内**通用（非个案、非寒暄）**成员须来自 **≥ `min_sources` 个不同来源
  （会话/客户）**。新增配置 `dm.learn_min_sources`（int，默认 2）。
- 新增第 4 步「**剔寒暄**」（`is_greeting`）：「你好 / 好的 / 收到 / 你们已互相关注对方 /
  测试…」即便跨会话重复也**不沉淀**。
- 流水线顺序更新为：向量化 → 聚类 → 粗门槛 → **剔寒暄** → 剔个案 →
  **按来源计通用性** → 抽象 → 专业实质 → 去重。
- `learn_from_history` 抽取时同步产出 `conv_keys`（来源会话 id）并传入 `purify`。

**验证**：修复前实测有 3 个「刷屏凑数」簇达标；修复后 **0 个**越门，
且「真·跨会话通用」对照组仍产出候选（**未矫枉过正**）。
详见 `工作记忆/cases/2026-09-28_提纯门通用性判据修复_v0.45.71.md`。
