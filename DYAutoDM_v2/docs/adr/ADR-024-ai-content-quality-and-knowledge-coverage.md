# ADR-024：AI 内容层质量 —— 知识覆盖（GB/T 16180-2014）+ 残句/断言护栏

- 状态：已采纳（2026-09-28，**v0.45.76 初版 → v0.45.77 修正**）
- 关联：`services/ai_reply.py`、`knowledge/pro_kb_seed/gb16180_2014.json`、`scripts/load_pro_kb_seed.py`、`frontend/src/components/settings/AiEngineSection.tsx`
- 上游依据：`skill llm-feature-debugging` 零号判据（先怀疑喂给模型的东西，不先改 prompt）
- 承接：ADR-021 D4（AI 获客治「客服腔」）—— 本 ADR 是其**专业正确性**延伸
- **v0.45.77 修正**：① GB/T 16180-2014 正式入库（D1 由 2 条扩为 5 条，共 3 类）
  ② 修复 v0.45.76 **截断后未复核** 导致的残句泄漏（AI-066）
  ③ 修复 v0.45.76 **断言正则过宽** 导致的疑问句误伤（AI-065 误报）

## 背景

用户实测：问「陈旧性骨折还能认工伤吗，厂里不认」，AI 回 **「能认」**。
用户判定：**与专业知识完全相悖** —— 陈旧性骨折难以证明是本次事故造成，
实务中**基本不予认定**；等级也按治疗后功能障碍评，不得凭伤情断言。

## 实测取证（Step 1~3，真机载荷 + 库快照）

- `pro_kb` 共 **6 条**：全部是赔偿项目/等级月数/户口/合同，
  **无一条**讲「陈旧性骨折能否认定」⇒ 模型无事实可锚（不是 prompt 问题）。
- `validate_reply` 只有**违禁词 + 最大长度**，**无最小长度** ⇒ 2 字残句直发。
- `_generate_reply` 优先级链：`reply_kb.find_match`（命中即回，零 token）→ AI（rag 注入 pro_kb）→ 兜底。
  命中库 81 条全为 `auto` 学习条目（40 条仍可生效），是内容质量另一风险面（见「未覆盖」）。
- 降级链实测：`agnes-2.5-flash` 两次 60s 超时 → 切 `deepseek-v4.1-flash` → 只回「能认」。

## 决策

### D1 补知识（**根因修复**）

向 pro_kb 增 grounded 专业条目（经**运行中后端 API** 写入 —— 活库被后端持有，
遵守并发写铁律，不直写库）；并固化为**可复现种子** `knowledge/pro_kb_seed/gb16180_2014.json`
+ 装载脚本 `scripts/load_pro_kb_seed.py`（幂等：重跑只合并不重复）：

1. 【工伤认定疑难点 / 陈旧性骨折】——**基本不予认定**；须补事故证明+首诊记录+时间线；
   即便认定一般也**评不上等级**（看功能障碍）；**不得对客户承诺结果**。
2. 【劳动能力鉴定 / 评残依据】——等级按**功能障碍**评，**不按损伤名称对号入座**。
3. **GB/T 16180-2014 三条**（本次新增，逐条引用标准原文；主题
   「劳动能力鉴定标准 GB/T 16180-2014」）：
   - **标准总则与评定原则**：唯一技术规范；须先工伤认定、医疗期满后按功能障碍评；
     **4.3 对原有伤残及合并症的处理**（旧伤核心条款：本次加重原有伤残→按加重后结局；
     本次轻于原有伤残→按本次结局）；与《人体损伤致残程度分级》是两套标准不可混用。
   - **骨科常见定级条款**：十级「骨折愈合后无/轻度功能障碍」；九级「压缩<1/2、1~2 节内固定、
     四肢长管状骨内固定、髌骨/跟骨/距骨/骨盆骨折内固定术后」；八级「压缩 1/2 以上、≥3 节内固定」；
     七级「骨盆内固定+环不稳、下肢短缩 2~4cm」；六级「成角>15°+短缩 4cm 以上」；五级「脊柱后凸 30°+根性痛」。
   - **脊柱与骨折旧伤专题**：压缩骨折按度数分九/八级；陈旧性骨折**先解决能否认定本次工伤**，
     评残阶段按 4.3 处理；**不得断言「肯定能评几级」**。
   来源：人社系统公布标准文本（淄博市人社局 .gov.cn 等），**逐字引用**，非记忆转述。

### D2 残句护栏（两处，缺一不可）

`validate_reply` 增 `min_reply_len`（配置项，默认 **5**，与 prompt「5-40 字」口径一致）。
低于阈值判残句 → 走兜底话术。**关键（v0.45.77 修正）**：`max_reply_len` 截断（取第一句）
发生在长度检查**之后**，原实现**未复核** ⇒ 长回复首句极短时（如「很难。……」）会被
**切回残句直发**（实测 65 字 → 「很难」2 字）。故**截断后必须复核** `>= min_reply_len`
（AI-066），否则「长度检查」与「实际外发文本」解耦，post-condition 形同虚设。

### D3 专业准确性护栏

`validate_reply` 增**绝对化断言**拦截（`_RE_ASSERTIVE`）：命中即走兜底。
- 「陈旧性骨折/旧伤 + **直接肯定**认定」（肯定词前无「不/否」）
- 等级断言（「能评上九级」「确定就是十级」）

**边界（防误伤，v0.45.77 修正）**：旧版正则把**疑问句**「旧伤**能不能认**」当断言
（`能认` 是 `能不能认` 的子串）→ **误伤正确回答**（实测把一条专业回复拦成兜底）。
现要求：肯定词前无否定前缀、尾部不是「吗/呢/？」—— 即只拦**陈述式断言**，
疑问句与「最终以认定结论为准」式分析**全部放行**（正控用例固化，含实测误伤原文）。

## 后果

- 正向：陈旧性骨折这类问题回到**与专业知识一致**的口径；残句不再外发（含截断路径）；断言被拦。
- 权衡：D3 是**形态护栏**，不区分疑问/陈述就误伤（已修），且拦不住「措辞含糊」型错误（见未覆盖）。
- 知识可复现：GB 内容不再只活在活库里 —— 种子 + 装载脚本可随仓库重建。
- 配置：`min_reply_len` 进 AI 页（与 `max_reply_len` 并列），可调。

## 未覆盖（诚实标注）

1. **`sem_enabled=False`** ⇒ pro_kb 注入走「时间衰减取前 5」而**非相关性检索**；
   实测出现「十级能赔多少」相关条目**未必入选**。⇒ 建议开启语义检索（`ai_sem` 链 +
   `sem_model`），**需用户定夺**。
2. **命中库 81 条 auto 碎片**（41 条失效、40 条仍生效）仍是「命中即回」最高优先级风险面；
   治理路径见 ADR-022（提纯门），存量清理**需用户拍板**。
3. 断言护栏是**形态匹配**，非知识推理；覆盖有限，属「防绊」非「根治」。
4. 活库中的 GB 条目**不在** git 内（DB 未跟踪）—— 种子文件是**唯一可复现来源**，
   新增/修订知识须同步更新种子，否则重装后丢失。
