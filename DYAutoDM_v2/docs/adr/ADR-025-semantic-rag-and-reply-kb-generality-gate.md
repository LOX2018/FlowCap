# ADR-025：内容层第二期 —— 知识库语义检索开启 + 命中库通用性门槛 + 存量审计

- 状态：已采纳（2026-09-28，v0.45.78）
- 关联：`services/ai_reply.py`、`services/reply_kb.py`、`services/reply_purify.py`、`api/ai.py`、`frontend/.../AiEngineSection.tsx`
- 承接：ADR-024（v0.45.77 的「未覆盖」三项）→ 本 ADR 逐项闭环
- 前序：ADR-022（提纯门 v0.45.70/71）、ADR-024（GB/T 16180 入库 + 护栏）

## 背景（ADR-024 遗留的三项）

1. `sem_enabled=False` ⇒ pro_kb 注入走「时间衰减取前 5」，**非相关性**。
2. 命中库 81 条 auto 碎片（其中 40 条仍可生效）—— 存量未清，且**命中即回绕过出口护栏**。
3. 断言护栏是**形态匹配**，非知识依据。

## 实测取证（真机，镜像根零写活库）

### ① 语义检索开关的实际影响（先测再改）

| 配置 | `kb_mode` | 注入条目 | prompt 字数 |
|---|---|---|---|
| `sem_enabled=False`（现状） | `fallback_decay` | 赔偿标准 / **流程与维权 / 常见疑问** / 赔偿项目 / 赔偿标准 | 3261 |
| `sem_enabled=True` | `semantic` | 赔偿标准 / 赔偿标准 / 赔偿项目 / **评残依据** | **1303** |

⇒ 开语义后**全相关**且 prompt 减半。embedding 链路健康：`ai_sem` 链 →
`llama-nemotron-embed-vl-1b-v2`，**2048 维**（直连 31415 无 key 返回 401 属正常；走 model_hub 带 key 成功）。

### ② 命中库「绕过出口护栏」—— 结构性漏洞

`_generate_reply`（L1628）与 `generate_dm_for_live`（L1970）对 `reply_kb.find_match` 的命中
**直接 `return hit`**，**不经 `validate_reply`**。实测库内可用条目含：
- 「能确定上九级吗？ → **你的伤情就是 9 级水平的**」（等级断言原件直发客户）。

### ③ 命中库语义级沿用宽松阈值会**张冠李戴**

命中库语义级原读 `sem_threshold`（默认 **0.40**，那是为「知识库选条」调的）。
实采（29 条可用条目）：

| 客户提问 | 0.40 下最高分命中 | 判定 |
|---|---|---|
| 陈旧性骨折还能认工伤吗 | 「工伤认定书还能销毁吗？」@ **0.502** | **错！** |
| 没有劳动合同单位不给报工伤 | 「支付宝能查到工伤人员吗」@0.471 | 错 |
| 腰椎压缩骨折能定几级 | 无（0.233） | 漏 |

⇒ 知识库「选错=噪声」与命中库「选错=**直答客户**」是**两个风险等级**，不能用同一开关+阈值。

## 决策

### D1 开启 pro_kb 语义检索（`sem_enabled=True`）

知识库 RAG 语义只决定「注入哪几条」，错选只是噪声（模型仍会判断）⇒ 开放。
实测收益：选条全相关 + prompt 3261→1303 字。

### D2 命中库语义级**独立开关 + 严格阈值**（默认关）

- 新增配置 `reply_sem_enabled`（默认 **False**）、`reply_sem_threshold`（默认 **0.78**）。
- `_sem_ready` 改为 `sem_enabled && reply_sem_enabled && sem_base_url`。
- 理由：命中即回**绕过护栏**，错选即张冠李戴；0.40 实测已证会误命中，故门槛从严且默认关。
- 显式配置原则：不靠"自动判断库干不干净"，由开关与阈值显式决定。

### D3 命中库通用性门槛（匹配侧：`_entry_usable`）

在既有「长度/占位」门槛上补两条（**只约束 source=auto**，人工条目不受限）：
- **个案化**问法 → 失效（复用 `reply_purify.is_case_specific`，**单点判据**）；
- 寒暄问法 → 失效（`is_greeting`）；
- 回复含**等级断言**且无豁免语（「以…结论为准/具体看/不一定/可能」）→ 失效。

效果（真机库）：可生效 **40 → 29** 条（挡下 9 个案 + 2 断言）。

### D4 存量审计（`reply_purify.audit_legacy_auto` + `POST /replies/audit_auto`）

- 把正式库里「个案/寒暄/断言/占位」的 auto 条目**移入待确认区**（`ai_reply_candidates`），
  **可逆**（确认即升格回来，拒绝即丢弃），对齐 ADR-022「绝不直接覆盖正式库」。
- 只处理 auto；**人工条目一律不动**。
- 幂等：二次运行 moved=0。

### D5 断言护栏的定位（回应 ADR-024 第 3 点）

- **保留形态匹配**作为最后一道绊（低成本、零延迟、可解释），但**不再宣称"根治"**。
- 真正的知识依据由 **D3（命中库门槛）+ pro_kb 知识（ADR-024）** 提供：
  命中库断言在**入口**失效；AI 生成的断言在**出口**被拦；两者的知识锚都是 pro_kb。
- 结论：**形态护栏 + 知识锚**分层，而非把护栏升级为 LLM 判别（后者引入延迟与不稳定）。

## 后果

- 正向：注入更相关、更短；命中库不再直发个案/断言；存量脏条目可逆清理；开关风险分级。
- 权衡：D3/D4 收紧后「命中即回」覆盖下降（40→29）——这**不是缺陷**：命中即回的价值在
  「确定性正确」，宁可多走一次 AI（走 pro_kb + 护栏），也不发错话术。
- 路径：部署后调 `POST /api/ai/replies/audit_auto` 落库清理（逐条可在候选区复核）。

## 验证

- 门禁：`test_reply_kb_generality` **9/9**（含门槛负控 + 豁免语正控 + 开关隔离 + 审计幂等/可逆）；
  合计 **42 项全绿**（+quality_guards 8 / purify / e2e / h31）。
- 真机量化：pro_kb 选条 off→on 对比见上表；命中库可用 40→29；审计扫描 81→移出 52。
- 前端 `npm run build` ✓；版本六处齐平。

## 未覆盖

1. 命中库语义级**默认关**：库内 29 条仍以精确/包含 + Jaccard 命中，语义召回未启用（需人工确认库干净后再开）。
2. `audit_legacy_auto` **需部署后手动触发**（当前运行实例仍是旧版，不改写用户活库）。
3. pro_kb 语义缓存键读 cfg 的 `sem_model`，而链实际模型为 `llama-nemotron-embed-...`——
   若换模型需 `pro_kb.sem_cache_invalidate()`（既有机制，本次未改）。
