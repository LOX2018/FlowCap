# 设计契约 · C-04 私信投递（services/dm_dispatch · dy_apis/client_im）

> 来源：本轮读源码（2026-09-21）+ `01_铁律与红线.md` + `07_反爬对抗.md`。
> 本契约承载**「发送成功」的定义**——历史上「UI 弹窗即报成功」事故的防线。

## 1. 设计意图

把一条私信**真实投递到目标会话**，并在频控压力下保持账号可用。

## 2. 设计契约（DbC）

| 类型 | 内容 |
|---|---|
| **前置条件** P | ① `peer_uid` 有效、非空、**非自身**；② 账号在发送白名单内；③ 账号未处于强制冷静期；④ `bd-ticket-guard` 头链可构造（IM 写以它为鉴权主体） |
| **后置条件** Q | ① 发送结果**必须经 DB 落库硬验证**（`role=me` + 本次 `skey`/msg_id 记录）才算成功；② 失败须分类（频控 / 凭证 / 网络），不得静默吞掉 |
| **不变式** I | Ⅰ1 **严禁仅凭抓包到上传步骤或 UI 弹窗宣称发送成功**（用户明确红线）；Ⅰ2 命中「频繁」回执 → 强制冷静期 + 权重降档；Ⅰ3 peer_uid 是自己的一律拒绝入池；Ⅰ4 回执分类与 `douyin_api._classify_send_fail` 对齐 |

## 3. 规范契约

| 字段 | 语义 | 禁止 |
|---|---|---|
| `peer_uid` | 对端 uid | — |
| `conv_id` | 会话 id（由对端解析） | 不得由后端推导伪造 |
| `skey` | 本次发送的验证键 | — |
| 回执分类 | 频控 / 凭证 / 网络 / 已投递 | **二态** ok/fail（须保留分类） |

## 4. NFR

| 指标 | 预算 | 依据 |
|---|---|---|
| 陌生人首发 | 降权 + 强制冷静周期 | 反爬对抗 |
| 冷静期 | `SEND-024` 失败后按策略（见 `dm_dispatch` 常量） | 频控 |
| 发送间隔 | `can_send(min_interval)` 闸门 | 防封 |

## 5. 验证方式（Live-Instance Verification）

```bash
# 硬验证（唯一可接受的「成功」证据）
#   发送后查 DB：role='me' 且 skey/msg_id 为本次记录
# 探针
py314 -m unittest test_capability_probe    # send_delivery 探针
```

> ⚠️ **当前缺口**：`send_delivery` 探针在**无验证标记**时只能报 `degraded`——
> 投递验证钩子尚未接全（见 `02_效果定义与探针.md` §六 下一步②）。

## 6. 已知缺口

- 回执一致率未接入探针（回执侧证据缺失）。
- 「发送成功」目前依赖落库侧证据；回执侧独立证据待补。
