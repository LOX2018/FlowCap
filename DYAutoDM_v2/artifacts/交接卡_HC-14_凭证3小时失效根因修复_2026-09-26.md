## 1. 已完成（逐条带证据）

### ① 根因定位（实测，非推断）—— 提交 `f54f554` 前的诊断

**用户提供的对照实验（关键锚点）**：
> 「我本机的一个 edge 浏览器 Cookie 稳定性还是很高的，半个月都是没有问题」
> 「凭证基本上也就只能管三个小时」

同一账号、同一网络、同一机器：**Edge 半个月稳定 ↔ Camoufox 3 小时失效**
⇒ 差异必在**环境层**，而非 cookie 本身。

**实测证据链**（BCC `POST /env_audit`，错误码 BCC-068）：

```
navigator.platform 与档案不一致: 期望 windows / 实际 Win32
CPU 核心数不一致:      档案=12      浏览器=8
screen 不一致:         档案=1280x720 浏览器=2560x1440
UA 不一致:  档案=...AppleWebKit/537.36 Chrome/148... 
            浏览器=...(rv:152.0) Gecko/20100101 Firefox/152.0
```

**矛盾诞生机制**（完整链条，逐环实测）：
```
_chrome_exe_path() 依赖 camoufox Python 包
  → 源码环境无该包 → 返回 ""
  → kernel_version() 退兜底 "148.0.0.0"
  → 档案声明 Chrome 148（浏览器实际 Firefox 152）
```

### ② D1-D4 四项修复（提交 `f54f554`，v0.45.11）

| # | 决策 | 实现 | 验证 |
|---|---|---|---|
| **D1** | 浏览器身份由**内核推导** | `_kernel_is_gecko()` + 档案双分支 | UA = `...(rv:152.0)...Firefox/152.0` ✅ |
| **D1·甲** | 内核定位**不依赖 Python 包** | 文件系统扫描 `%LOCALAPPDATA%\camoufox\...\camoufox.exe` | 版本 148 → **152.0.4-beta.30** ✅ |
| **D2** | Gecko **不发 Client Hints** | `sec_ch_ua=""` + `header.py` 条件发送 | 出站头无 `sec-ch-ua*` ✅ |
| **D4** | 消除**全部硬编码残留** | **7 处**统一到 `utils.fingerprint.user_agent()` | 活跃硬编码归零 ✅ |

**实测出站头对照**：
```
修复前  user-agent: ...Chrome/148.0.0.0      sec-ch-ua: "Google Chrome";v="148"   ← 对立
修复后  user-agent: ...(rv:152.0)...Firefox/152.0   sec-ch-ua: （未发送）        ← 一致 ✅
浏览器真值: ...(rv:152.0) Gecko/20100101 Firefox/152.0                        ← 逐字一致
```

### ③ D3-A 档案跟随内核真值（提交 `189ce6d`，v0.45.12）

**问题**：D3 有两个**相反方向**，必须先选。

**决定性证据**（camoufox 官方文档 `python/usage.md`）：
> Do NOT randomly assign values to these properties. WAFs hash your WebGL
> fingerprint and compare it against a dataset. **Randomly assigning values
> will lead to detection as an unknown device.**

**实测事实**：
- 项目预设 = 5 屏幕 × 4 GPU × 11 核数 = **220 种组合**
- Camoufox 用 **BrowserForge**（上游数据集，组合数高数百倍）
- Camoufox 自带 `clamp_screen_to_display()`（源码 `fingerprints.py:414`）

⇒ 项目自造预设**正是官方警告的 "randomly assign"** ⇒ **选 D3-A**。

**实现**：新增 `services/kernel_truth.py` + BCC 探针落盘 + 档案消费。

**实测验证**（BCC 真实探针 → 落盘 → 档案读取）：
```
浏览器真值: screen 5120x1440, cores 8, webgl Mozilla/GTX980
     ↓ record_kernel_truth()
档案: _truth_source=kernel, screen_width=5120, cpu_height=1440, cpu_core_num=8
对照修复前: 档案 1280x720/12核 vs 真值 2560x1440/8核 —— 完全不一致
```
