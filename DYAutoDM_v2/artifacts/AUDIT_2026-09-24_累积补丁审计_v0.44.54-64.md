### C1 · `replay/sanitize_db.py` 列白名单漂移（**fatal**）

```python
# sanitize_db.py:172-176（登记 7 列）
"dm_uid_sink": {"account","peer_uid","nickname","source","first_seen_ts","sent_ts","send_count"}
# database.py:218-231（现网 12 列，新增 5 列）
#   keyword_score / is_high_value / high_value_reason / window_end_ts / aggregate_text
```

```python
# sanitize_db.py:245-261（默认拒绝）
def _validate_schema(cur, tables):
    """默认拒绝：未登记的表/列一律 raise（绝不静默丢弃/透传）。"""
    ...
    unknown = [c for c in cols if c not in _POLICY[t]]
    if unknown:
        raise UndocumentedColumn(...)
```

**判据**：`build()` 在 L272 调用 `_validate_schema` ⇒ 对**任何含新增列的真实库**必经 L258-261 raise。
**后果**：回放层 fixture **无法再生成**；`test_replay_gates` 依赖此能力。
**性质**：**契约与代码的列级同步无门禁**导致的漂移（见 §4 缺失维度 2）。

### H1 · `dm_dispatch.mark_seen` 首条双计（**已实测**）

```python
# L801-806：INSERT 时 aggregate_text 已写入 text
"INSERT OR IGNORE INTO dm_uid_sink(...,aggregate_text) VALUES(...,?)"
    (..., (text or "")[:max_chars] if text else "")
is_new = (getattr(cur, "rowcount", 0) or 0) > 0
if text:                       # ← 未按 is_new 分流
    conn.execute("UPDATE ... SET aggregate_text=substr(COALESCE(aggregate_text,'')||' '||?,1,?) ...")
```

**实测（可复跑）**：

```
mark_seen("a1","u1","张三","live","工伤能赔多少")   # 仅一次
get_aggregate("a1","u1") → '工伤能赔多少 工伤能赔多少'   # 原文出现 2 次
```

**后果**：双计污染 `get_aggregate()` 输出（AI 生成上下文），并浪费 `AGGREGATE_MAX_CHARS` 预算。
**修法**：`UPDATE` 以 `not is_new` 为条件，或 INSERT 时 `aggregate_text` 留空由 UPDATE 一次性填充。

> 「解决：本模块在导入时立刻把 `DY_APP_ROOT` 指向独立临时目录，并保证 database 尚未被导入」

**实测不成立**。至少三个模块**各自在模块级赋值** `DY_APP_ROOT`：

| 模块 | 行为 | 根 |
|---|---|---|
| `test_config_isolation` | `os.environ["DY_APP_ROOT"] = _ROOT`（**显式赋值**） | `%TEMP%/dyautodm_cfgtest_root`（固定） |
| `test_uid_sink_ext` | `os.environ["DY_APP_ROOT"] = _ROOT`（显式赋值） | `mkdtemp`（每次新） |
| `test_p2_live_guards` | `os.environ.setdefault("DY_APP_ROOT", _ROOT)` | `%TEMP%/fixA`（固定） |

`unittest discover` 单进程导入 ⇒ **最后导入者胜**。
实测（全模块导入后单跑 p2）：`database._db_path()` =
`…\Temp\uid_sink_ext_test_tz9yfnsi\data\dyautodm.db`（**竟是另一个模块的根**）。

### 5·2 后果（实测）

`test_p2_live_guards` 的通过**依赖前次运行在共享库中留下的方案记录**
（`save_room` 会校验 `strategy_id` 存在性并**正确拒绝**悬空引用）。

**实验证据**：我把 `test_engine_contract_p1` 的会话泄漏修掉（消除其 `.session.json` 残留）
⇒ 套件 **830 OK → 7 项失败**（`KeyError: 'room'` / `IndexError`）。

### 5·3 处置（按**迭代止损律**）

对同一缺陷的尝试已远超 2 次 ⇒ **停止局部修补**，**回滚**该未提交改动，
复测恢复 **830 OK** 绿态。**未把净回归留在树里。**

**正确取径（建议，需用户拍板）**：**套件级统一隔离** ——
① 所有 `test_*.py` **不得自设** `DY_APP_ROOT`；
② 由 runner / `conftest` 统一注入，且**每模块独立子根**（`<tmp>/<module>/`）；
③ 加机械门禁防回退（缺失维度 4）。
**风险**：动 6+ 个测试模块 ⇒ 属**设计级改动，须先出 ADR**。
