# 前端信息架构重设计 —— 从用户使用逻辑出发

> **状态：设计提案（未执行）**　|　**日期**：2026-09-14　|　**分支**：`design/better-douyin`
> **用户定调**："我是指了一个方向，自己从用户视角分析入口的使用逻辑来设计，现有结构给我的感觉就是纯业务化不人性化"

---

## 一、问题定性（先回答：为什么"纯业务化不人性化"）

### 1.1 现状是一个"功能清单"，不是"用户任务图"

当前侧栏 12 项，是**按代码模块**排的，不是按**用户想干什么**排的：

```
核心:  总览 · 私信 · 直播
内容:  采集 · 内容 · AI 获客 · 知识库
系统:  账号 · 任务 · 通知 · 日志 · 设置
```

这些词**全是系统名词**（"采集""内容""任务""通知"），用户要自己翻译成"我要做什么"。
更糟的是分组逻辑混用：`直播`在"核心"、`内容`在"内容"组——**名字和组名撞车**。

### 1.2 铁证：应用自己在教用户"去别的页面"

实测抓到的**跨页指引**（代码原文）：

| 位置 | 文案 |
|---|---|
| `ai.tsx:250` | "Agent 的新建、删除与账号绑定请到**「设置 → AI 与 Agent」**" |
| `ai.tsx:366` | "模型 / 提供商连接已统一到**「设置 → AI 与 Agent → 模型链路中心」**" |
| `notify.tsx:226` | "模型配置已统一到**「设置 → 通知与指令」**页管理" |
| `live.tsx:241` | "请到**「账号」**页面点【重新扫码】重新抓取签名" |
| `live.tsx:274` | "可查看下方原始原因，或到**「日志」**页查看后端详细日志" |
| `live.tsx:1055` | "请到**「账号管理」**添加账号并完成扫码授权" |
| `crawl.tsx:115` | "请先在**账号管理页**登录一个账号" |
| `UnifiedConfigSection:470` | "标签的新建与删除请到**「配置标签」**页" |

**这些提示的存在本身就是设计失败的证据**——一个自解释的界面不需要教用户"去别处"。
而且"设置 → AI 与 Agent → 模型链路中心"是**三级路径**，用户得记住。

### 1.3 三个具体的不人性化

1. **不知道从哪开始**：新用户装完应用，看到 12 个平级入口，且**无任何引导**（实测：无 onboarding 概念）。
   而真实的第一步是"加账号 + 扫码"，这一步藏在 12 项里的"账号"。
2. **配置与使用分离**：用户在看私信时想调"发送频率"，得先记住"设置 → 私信发送"。
   **配置项离开了它的使用场景**。
3. **同一概念多处出现**：话术库在设置页和 AI 页都能改；知识库在设置页和知识库页都有。

## 二、设计原则（从用户视角提炼）

| # | 原则 | 反对的现状 |
|---|---|---|
| P1 | **按"我要做什么"组织，不按"系统有什么模块"** | 12 个系统名词平铺 |
| P2 | **配置跟着使用场景走**（就近可调），共享配置才集中 | 配置全塞进设置页 |
| P3 | **同一设定全局只有一个可写入口** | 话术/知识库两处可写 |
| P4 | **边界清晰**：共享设定在"配置中心"（唯一可写），业务页只"选择/引用" | — |
| P5 | **首屏回答"我现在该做什么"** | 首页只堆 4 个展示区块 |
| P6 | **删掉所有跨页指引**（把指引变成能力） | 8 处"请到 XX 页" |

用户已拍板的两个决策（本次采纳）：
- **D1 = 侧栏底部独立入口**（与"收起"并列，视觉区分于业务项）
- **D3 = AI 页只读展示 + 跳转；账号页加"选 Agent / 选标签"下拉**（真正的选择口）

## 三、新信息架构设计

### 3.1 两层结构：业务（左侧栏）+ 配置中心（底部入口）

```
┌─────────────────────────────────────────┐
│  🟢 DYAutoDM                             │
│                                          │
│  【任务】                                 │
│    ◉ 总览                                 │   ← 首屏：我该做什么
│    ○ 私信                                 │
│    ○ 直播                                 │
│    ○ 采集                                 │
│                                          │
│  【资产】                                 │
│    ○ 账号                                 │   ← 账号/内容/知识库是"我的资产"
│    ○ 内容                                 │
│    ○ 知识库                               │
│                                          │
│  【记录】                                 │
│    ○ 任务                                 │
│    ○ 通知                                 │
│    ○ 日志                                 │
│                                          │
│  ─────────────────────────────────────   │
│  ⚙️ 配置中心                    [新入口]  │   ← 唯一可写配置入口
│  ◀ 收起                                   │
└─────────────────────────────────────────┘
```

**分组重命名（按用户心智，不按模块）**：

| 原分组 | 新分组 | 含义 | 成员 |
|---|---|---|---|
| 核心 | **任务** | 我在跑的活 | 总览 · 私信 · 直播 · 采集 |
| 内容 | **资产** | 我积累的东西 | 账号 · 内容 · 知识库 |
| 系统 | **记录** | 发生过什么 | 任务 · 通知 · 日志 |

> **"AI 获客"去哪了？** —— 它本质是"用 AI 做获客"的**跨页能力**，不是一个独立页面。
> 现方案：**并入"私信"与"直播"的 Agent 选择器**（AI 能力应嵌在使用场景里，而不是单开一页）。
> *若用户认为 AI 页有独立价值（如话术编辑、线索管理），则保留为"资产"组下的第八项。*

### 3.2 配置中心（新页面：唯一可写入口）

侧栏底部独立按钮 → 打开配置中心（**占满主内容区**，与业务页同级）：

```
配置中心
├── 通用            (前端/系统行为)
├── 发送与风控       ← 原「私信发送」
├── 直播监听
├── 捕获与存储
├── 模型链路中心     ← 模型/提供商/避障（唯一真源）
├── Agent 与话术     ← Agent 模版 + 账号绑定 + 回复话术（话术的唯一可写处）
├── 配置标签
└── 通知与指令
```

**关键改动**：
- 原"设置"从 12 项里**移到底部独立入口**（D1 已定）
- **回复话术**从 AI 页收回到这里（P3：唯一可写）
- **账号绑定 Agent** 的"绑定矩阵"移到这里（这里是配置），账号页只留"选择"（D3）

### 3.3 各业务页的"调用口"（选择，不可写）

| 页面 | 现状问题 | 改造后 |
|---|---|---|
| **AI 获客** | 可编辑话术（与设置页冲突） | **只读展示**当前生效的 Agent/档位/模型；`[去配置]` 按钮 → 配置中心 |
| **账号** | 无 Agent/标签选择 | 每账号一行：`[Agent ▾]` `[标签 ▾]` 下拉**选择**（真正符合用户的"选择配置的调用口"）|
| **私信** | 无配置感知 | 顶部一行**只读摘要**："发送策略：默认 · Agent：商家A" + `[调]` 小按钮直达 |
| **直播** | RoomConfigManager | **保留**（房间级覆盖是业务需求）；全局参数只在配置中心 |
| **知识库** | 与设置页概念重叠 | 保留为资产页；配置中心不再重复"知识库"入口 |

### 3.4 首屏改造：回答"我现在该做什么"

现总览页只有 4 个展示区块（当前查看账号 / 实时动态 / 运行中任务）。
**新增"上手引导"（仅当条件未满足时出现）**：

```
┌ 快速开始 ─────────────────────────────┐
│  ① 添加账号并扫码授权      [去添加]     │  ← 未完成时高亮
│  ② 配置 AI Agent（可选）   [去配置]     │
│  ③ 开始采集或监听直播      [去采集]     │
└───────────────────────────────────────┘
```
条件满足→卡片消失。这直接消灭"新用户不知道从哪开始"。

## 四、这笔"跨页指引"债务的清偿表

| 现文案 | 位置 | 改造后 |
|---|---|---|
| "请到「设置 → AI 与 Agent」" | ai.tsx | 页面内直接有 `[去配置]` 按钮（一键直达，不需记忆路径）|
| "模型已统一到「设置 →…模型链路中心」" | ai.tsx | 只读展示生效模型 + `[换模型]` 按钮 |
| "模型配置已统一到「设置 → 通知与指令」" | notify.tsx | 同上 |
| "请到「账号」页重新扫码" | live.tsx | 页面内提供 `[重新扫码]` 按钮（或跳转带上下文）|
| "请到「配置标签」页" | UnifiedConfigSection | 移到配置中心内，不再跨页 |
| "请先在账号管理页登录" | crawl.tsx | 空态里直接给 `[去添加账号]` 按钮 |

**目标：把 8 处"请到别处"变成"就地能做"或"一键直达"。**

## 七、边界与风险

- **不动昵称链路**（风控红线）
- **房间级配置覆盖**（RoomConfigManager）是设计意图，保留
- 架构改版会动 sidebar + settings + accounts + ai + overview，**分步提交、每步可回滚**
- 一切以**实机实测**为准，不接受观感判决（本轮 3 张图已有 1 张被实测推翻）
