# AI 获客页打散归类方案

> **状态：✅ 已执行（commit `9e7f345`，v0.43.18）**　|　**日期**：2026-09-14　|　**分支**：`design/better-douyin`
>
> **用户决策（Q1–Q4）**：Q1 彻底消失（无只读页）· Q2 留资线索→私信页 · Q3 合成「AI 回复引擎」区 · Q4 并入

> **用户指令**："AI获客页打散拆分，按照类型归类到特定页面"

## 一、AI 获客页现状（560 行，6 个区块）

| # | 区块 | 数据面 | **作用域**（实测） | 行数 |
|---|---|---|---|---|
| 1 | AI 获客自动回复（运行控制） | `/api/ai` status/start/stop | 全局引擎 | ~30 |
| 2 | Agent 设定 | `/api/ai/config`（prompt/商家名/档位/延迟/`forbidden_words`/`fallback_pool`/`max_reply_len`）| **按 Agent** | ~75 |
| 3 | 知识库入口 | 纯跳转卡片 | — | ~36 |
| 4 | 留资线索 | `/api/ai/leads` | **按账号**（表含 `account` 列 + `UNIQUE(account,conv_id,…)`）| ~52 |
| 5 | 护栏配置（违禁词/兜底池/图片兜底/最大长度）| 同 `/api/ai/config` | **按 Agent** | ~42 |
| 6 | 黑名单 | `/api/ai/blacklist` | **全局**（kv 存储，无 agent/account 维度）| ~34 |

**共同点：它们全是"AI 回复引擎"的配置与产出**，被硬塞进一个叫"AI 获客"的页面。
但按作用域看，它们其实分属**四种不同归属**——这正是"打散归类"的依据。

---

## 二、归类依据（不是拍脑袋，按作用域判定）

我实测了每块数据的**存储作用域**，这是归类的客观依据：

```
按 Agent 维度   → 属于「AI 回复引擎」的配置   → 配置中心
按账号维度     → 属于「账号的产出/资产」      → 账号页 或 私信页
全局维度       → 属于「全局共享设定」        → 配置中心
纯导航         → 重复入口，直接删            → —
```

**一个关键实测结论**：`leads` 表有 `account` 列，而 `blacklist` 是全局 kv。
同样是"AI 的产出/约束"，**作用域不同，去向就该不同**。

## 三、打散归类方案

### 3.1 逐个去向

| # | 区块 | 去向 | 理由 |
|---|---|---|---|
| 1 | **运行控制**（启停+统计） | **总览页** | 它是产品级"运行状态"：总览已经展示"运行中任务/实时动态"，AI 就绪状态属于同一层。放总览=用户一眼看到"AI 在不在跑" |
| 2 | **Agent 设定** | **配置中心 → 「AI 回复引擎」** | 按 Agent 维度=配置；是"回什么"的定义 |
| 3 | **知识库入口卡** | **删除** | `kb.tsx` 已完整含"专业知识库/对话回复库"两个子 tab（实测 `SubTab = "pro" \| "reply"`），此卡是**纯重复导航** |
| 4 | **留资线索** | **私信页**（新子 tab）或 **账号页**（按账号展开） | 线索来自私信对话，`account` 列使其天然可按账号筛选。**私信页更符合"它就产生在我聊天的地方"** |
| 5 | **护栏配置** | **配置中心 → 「AI 回复引擎」**（与 Agent 设定同区）| 同属 `/api/ai/config`、同按 Agent，是"回复内容"的一部分 |
| 6 | **黑名单** | **配置中心 → 「AI 回复引擎」** | 全局共享设定；定义"谁不回复" |

### 3.2 配置中心的分区（更新后）

```
配置中心（侧栏底部独立入口 · 唯一可写）
├── 通用
├── 发送与风控        ← 原「私信发送」
├── 直播监听
├── 捕获与存储
├── AI 回复引擎  ★新  ← Agent 设定 + 护栏配置 + 黑名单 + 模型链路
│      ├─ 模型链路中心（模型/提供商/避障）
│      ├─ Agent 设定（商家名/prompt/档位/延迟）
│      ├─ 护栏（违禁词/兜底池/图片兜底/最大长度）
│      └─ 黑名单
├── 配置标签
└── 通知与指令
```

> **为什么合并为一个"AI 回复引擎"区？**
> 实测这四块都通过 `/api/ai/config` + `/api/ai/blacklist` 读写、都按 Agent 或全局生效——
> 它们是**同一个引擎的四组参数**，拆成四个顶部 tab 反而让用户来回跳。

### 3.3 侧栏结果

```
任务:  总览 · 私信 · 直播 · 采集
资产:  账号 · 内容 · 知识库
记录:  任务 · 通知 · 日志
─────────────────
⚙️ 配置中心
◀ 收起
```
**"AI 获客"项消失**（12 项 → 11 项 +配置中心）。

## 七、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **Agent 草稿隔离** | `ai.tsx` 有精细的草稿/脏标记逻辑（切 Agent 丢弃草稿）| **整体搬迁**该逻辑，不重写 |
| **保存条吸底** | dirty 时的 sticky 保存条 | 一并搬到配置中心 |
| **风控红线** | 本页只读写 `/api/ai`，**不触发捕获/昵称查询** | 搬迁后**保持这一点**，红线不破 |
| **TabId 移除** | `"ai"` 被 `TITLE_OF`/sidebar/App 引用 | 全局 grep 后逐处清理 |
| **用户习惯** | 用户可能习惯去"AI 获客"找东西 | 靠**总览的运行控制区块**与**私信线索 tab**给出可见去处 |
