fix(v0.43.3): 修复更新会话四大回归（昵称头像全空/图片不解码/状态不持续/切换churn）

用户实测反馈（v0.43.2 后）：
  「更新会话机制像完全丢失了：只能看到首包解析的内容，没有头像数据，
    图片没解码只显示『前往抖音查看』，更新状态切页就丢」

【根因1：昵称/头像全空 ← 我 v0.42.7 的「纯无头」回滚造成】
实测日志对比（决定性）：
  09-01 22:25 「真有头+窗口移屏外」→ 昵称捕获 277 个 ✅
  09-03 23:13 「真有头+窗口移屏外」→ 昵称捕获 280 个 ✅
  09-06 22:02 「真有头+窗口移屏外」→ 昵称捕获  81 个 ✅
  09-13 20:22 「无头模式=native（纯 headless）」→ 累计昵称 0 个 🔴
    （滚动轮次1 新点击=12 累计昵称=0 → 3 轮无新增终止 → 预热完成：0 个）
结论：**抖音前端在纯 headless 下不发 im/user/info**，BCC 的被动 hook
截不到任何昵称 → 全部降级为裸 UID，头像全空（库内 72/72 peer_name=peer_id、
有头像 0 条）。
修复：容器恢复常驻「真有头 + 窗口最小化」（minimize 而非移屏外；用户不会误关
最小化的窗口）。回退开关 DY_BCC_HEADLESS_MODE=native。

【根因2：切换可见性重建 context → 状态丢失 + 频繁重启】
set_visible 原来「关旧 context → 重开」，3~6s churn，且切换期间业务全排队失败。
现改为**只改窗口状态**（CDP Browser.setWindowBounds normal/minimized），
不重建 context —— 业务零中断、环境零跳变。
回退开关 DY_BCC_SWITCH_MODE=rebuild。

【根因3：图片不解码（只显示「前往抖音查看」）】
首包解析路径 messages.append **从不提取图片解密要素**，导致图片消息落库
extra={}（实测 3 条 [图片] 消息 extra 全空）→ origin_image_resolver 拿不到
skey/origin_url → 无法 AES-256-GCM 解密 → 前端降级。
（cmd 301 路径早有该提取，首包路径漏了。）
修复：首包按 field 8 取 content_json 并调 _extract_image_secret()，补齐
skey/origin_url 两个字段。

【根因4：更新会话状态不持续（切页就丢）】
refreshing 是 messages.tsx 组件内 useState —— 切页组件卸载即归零。
修复：提升到 App 级（refreshState {account, startedAt}），经 PageProps 下发；
计时改为基于 startedAt 计算（切页回来继续正确计时，不再归零重计）。

版本 0.43.2 → 0.43.3。
