﻿# V2 前端联调与账号管理（2026-08-20 整理）

> 来自已验证的联调经验与前端修复，符合当前 V2 架构。

## 一、前后端契约一致性要点
- 后端 `/api/accounts` 返回 `{ok, accounts:[...]}`；`client.ts.getAccounts()` 已剥离外壳直接返回数组。任何前端消费点必须统一用数组语义（messages.tsx 曾因解 `{ok,accounts}` 导致"无已授权账号"）。
- 前端 `selectAsMonitor` 传角色用 `"watch"`/`"send"`（后端 `AccountRole` 枚举值），不是 `"monitor"`/`"sender"`（否则 422）。
- `client.ts` 必须包含后端所有真实路由方法（getLiveStream/sendDanmaku/doLike/requestDm/resolveLive/search/diggVideo/favoriteVideo/exportStats/selfCheck/openFingerprintBrowser/autoRecapture 等），只改组件调用不改 api 包装会 `is not a function` 崩溃。

## 二、账号管理页（accounts.tsx）
- 账号卡片边框按有效/失效变色：`isValid = wp level==="ok"` 绿色、否则红色；isMonitor 保留青色光晕。
- 双引擎分两行清晰标注：wp 引擎（凭证守护捕获四件套）、私信引擎（dm 列表拉取测试）；`wpEngine.level==='stopped'` 时 UI label 覆写"未运行"。
- 引擎校验按钮（`runCheck`）走 `/{name}/check`（dm_loopback=True 真拉列表），成功分支**不**自动 refetch（避免轮询覆盖手动结果），仅失败分支 refetch。
- 删除账号（batchDelete）：乐观更新——本地 `qc.setQueryData` 先过滤掉，再发请求，finally 静默 refetch，感官零延迟（原误用 `setAccounts` 未定义会 TS 编译失败）。
- 打开指纹浏览器（`openFingerprintBrowser`）：先 `_quit_browser_daemon(name)` 释放 profile 锁再弹窗，避免 Chromium profile 抢锁；返回 `ok=False` 时带真实 error（如内核缺失），前端 push 提示。

## 三、启动自检弹窗（App.tsx + SelfCheckModal）
- 后端 ready 后 `useEffect` 跑一次 `selfCheck`（对所有账号真跑 `verify_account(dm_loopback=True)`），仅 `bad.length>0` 才弹 `SelfCheckModal`，正常静默不弹。
- 自检弹窗列出不可用账号 wp/私信引擎状态 + 「立即处理验证」(调 autoRecapture 打开 chat?isPopup=1)。

## 四、直播监听页（live.tsx）
- 未连接后端（`!ready`）时**不**渲染任何可点监听入口（移除假"开始监听"按钮），只显示"未连接后端·无法监听"提示。
- 直播流信息（live.py get_stream）：从 `adm.live`（LiveChatHook）读 feed/heat/online/likes/roomTitle/liveUrl/listening。
  - 运行态判断：`running = not bool(live._should_stop) and bool(live.ws)`（LiveChatHook 继承 DouyinLive 基类**没有 running 属性**，用基类 `_should_stop` False=运行中 + ws 连接存活，否则 alive 恒 False → 前端永远"等待运行"）。
  - 房间标题读 `adm.room_title`（AutoDM._run 里 `self.room_title=room_title`），不是 `live.room_status.get("room_info")`（`room_status` 是 check_room_live 返回的 status 字符串，非 dict）。
- 房间热度解析（live_hook._on_room_stats）：在线/点赞数两种顺序（"X人在线"数字+单位 / "在线 X人"单位+数字）都要兼容，互不污染；数字/单位万/k 换算保留。
- 停止语义：直播监听页"停止监听"→ `api.stopSoft()`（软停，已捕获未发延迟私信继续发完）；任务中心"停止"→ `api.stop()`（硬停，清空队列）。

## 五、联调测试套件

## 六、运行日志页（logs.tsx + api/logs.py）
- 后端 `GET /api/logs?limit=&name=` 读 `backend/logs/run_*.log`；未指定 name 时合并 `logs/` 下全部 `*.log`（run_*/browser_daemon_*/recv_daemon_*）按时间排序取尾部。
- 守护进程（browser_daemon/recv_daemon）顶部 `logger.add(sys.stderr, enqueue=True, level=INFO)`（enqueue 规避 Windows GBK 中文编码崩溃），与文件 sink 并存，使前端运行日志页可见守护活动。
- `GET /api/logs/sessions` 列历史会话（每个 run_*.log 一次启动）；`DELETE /api/logs/sessions` 只删历史文件（current 受保护），清空显示是前端本地行为不删实质日志。

## 七、切页冗余拉取（已修，2026-08-25 复盘）

- **现象**：切到私信页时，后端 `api/messages.py` 在 1 秒内对 `recv_daemon /conversations` 打出 3 次 45 会话的完整日志，观感像"反复拉取"。
- **根因（非首次全量拉取）**：日志里 `peer_name` 已是解析好的昵称（非 fallback 到 uid），证明 `_api_pulled` 早已 True，**对抖音 0 次 API 调用**，纯属冗余读请求被后端逐会话 debug 日志放大。三股叠加：
  1. `React.StrictMode`（`main.tsx:20`）双挂载副作用，首次挂载发 2 次；
  2. `convsQ` 是**页面级** `useQuery` 且无 App 级缓存，切页冷启动拉 1 次（与 accounts 的常驻轮询机制不一致）；
  3. `activeAcct` 从 `""` → 首个账号的 state 变化又触发 1 次 refetch。
- **修复**：
  - **前端（治本）**：把 conversations 轮询**提升到 App 级常驻**（`App.tsx` 新增 `useQuery(["msg-convs", msgAcct], refetchInterval:5000, gcTime:5min, staleTime:10s)`），当前私信账号 `msgAcct` 提升为 App state 经 `pageProps` 下传；`messages.tsx` 的 `convsQ` 改用同 key **只读缓存、不再自带 refetchInterval**，账号切换按钮调 `props.setMsgAcct`。切页时该 key 已在内存热着，页面挂载直接读缓存，不再冷拉；守护未运行的自动拉起逻辑也移至 App 常驻查询内。
  - **后端（治标）**：`api/messages.py` 收敛逐会话 debug 日志——只保留"返回 N 个会话（未读合计 M）"一行 INFO，完整 JSON 降级为 `logger.debug`（默认 INFO 级别不输出），消除日志爆屏。
- **铁律**：凡是"切页要看到、且持续热着"的数据（账号/直播流/任务/私信会话），轮询必须放在 **App 常驻层**而非页面层；页面只 `useQuery` 同 key 读缓存。否则 StrictMode 双挂载 + 冷启动必然冗余拉取。
- **验证**：`npx tsc --noEmit` 零错误。

## 九、前后端字段契约错配两例（2026-09-11，v0.41.1）

用户报「前端下拉框显示异常全是空白」+「设置页『AI 与 Agent』渲染崩溃」。**两者都不是玻璃拟态移植引入的**（`git diff HEAD` 显示 `UnifiedConfigSection.tsx` 未改、`ModelHubSection.tsx` 的改动来自更早的 AI/model_hub 功能开发），是**前后端 JSON 字段形状契约不一致**，长期潜伏、直到真机点开对应用户才暴露。

### 9.1 下拉框全空白：`options` 字符串数组 vs 对象数组

- **现象**：所有下拉（设置页「运行模式」等）选项行存在但**文本与 value 全空**，React 报警告 `Encountered two children with the same key`（key 全 `undefined` → 被折叠成 1 条）。实测 HTML：`<select><option></option></select>`。
- **根因**：后端 `backend/services/app_config.py` 的 SECTIONS 下发 `"options": ["native", "disguise"]`（**字符串数组**）；前端 `api/client.ts` 的 `ConfigField` 类型与 `UnifiedConfigSection.tsx` 渲染按 `{ value, label }[]`（**对象数组**）写：`<option key={o.value} value={o.value}>{o.label}</option>` → 对字符串取 `.value`/`.label` 都是 `undefined`。
- **修复**：前端做**双向兼容**（后端不改，避免动 schema 契约）：
```tsx
{(s.options ?? []).map((o, i) => {
  const val   = typeof o === "string" ? o : o.value;
  const label = typeof o === "string" ? o : (o.label ?? o.value);
  return <option key={val ?? i} value={val}>{label}</option>;
})}
```
  并同步放宽类型 `options?: (string | { value: string; label: string })[] | null`，`ConfigField.type` 补上漏声明的 `"select"`。
- **铁律**：**看到「选项框空白」先查形状不查样式**——`<option>` 的 `key`/`value`/文本三方同时为空 = 取属性的对象不是预期形状，不是 CSS 隐藏。诊断命令：CDP 里 `document.querySelectorAll('select')` 打印每项 `innerText`。

### 9.2 「AI 与 Agent」白屏崩溃：`routeDraft` 类型是数组、实际灌进对象

- **现象**：进设置页 AI 与 Agent 分栏，React 整棵树卸载（`#root` 被清空 → 白屏），控制台 `TypeError: L.includes is not a function`（在 `Array.prototype.map` 回调内）。
- **根因**：`ModelHubSection.tsx` 用 `setRouteDraft(JSON.parse(JSON.stringify(routes)))` **整树克隆**；后端 `routes` 的形状是 `{ llm: { models: [...] }, vision: {...}, sem: {...} }`，而 `routeDraft` 的 TS 类型是 `Record<HubRouteKind, string[]>`（**只放 id 数组**）→ `routeDraft[kind]` 变成**对象**，后续 `ids.includes(...)` 立刻 `TypeError`。
- **修复**：克隆时按下标取数组字段，并加防御性兜底：
```tsx
const next = {} as Record<HubRouteKind, string[]>;
for (const k of Object.keys(HUB_ROUTE_KINDS)) {
  const v = (routes as any)?.[k];
  next[k] = Array.isArray(v) ? v : Array.isArray(v?.models) ? v.models : [];
}
setRouteDraft(next);
```
- **铁律**：`JSON.parse(JSON.stringify(x))` 是**类型逃逸**手段——克隆不会校验形状，TS 一切正常、运行时才炸。凡是「克隆后端返回值塞进强类型 state」的地方，都必须显式逐字段取 + `Array.isArray` 兜底，不能整树克隆。
- **定位手法（值得复用）**：生产包（minified）只能看到 `L.includes` 这种缩写名，**必须**用 dev server（`npx vite --port 5201`）加载未压缩源码才能拿到 `ModelHubSection.tsx:855` 这样的**精确文件+行号**。做法：把 WebView2 的 CDP `Page.navigate` 指到 `http://127.0.0.1:5201/` 并注入 `localStorage['dy.member.token']`，即可在真实 Tauri 窗口里跑 dev 源码。
- **验证证据**：dev 模式下设置页 `#root` 子节点 1、296 个模型卡渲染、console 错误 0；全站 select 扫描 `emptyText` 计数全 0。`tsc -b` + `vite build` exit 0。

# B · 前端设计体系

## 十二、前端元素选择模式（Element Inspector，v0.43.93）

**背景**：Tauri 生产构建**没有 DevTools**（右键检查不可用），前端排查时无法把「界面上看到的
控件」映射回「源码里的哪个组件 / 哪个 `data-od-id`」。本项目已有 `data-od-id` 稳定锚点体系
（73 处），本工具即它的可视化取址入口。

**入口：全局顶层悬浮（左下角「◎ 元素选择」胶囊按钮）**。
> 2026-09-19 用户定调（勿回退）：原实现把按钮挂在 TopBar `topRight`，用户判为
> 「**这个入口不合理，把该入口设定为全局顶层悬浮**」。旧做法两个硬伤：
> ① 未登录时 `AppShell` 不渲染 ⇒ **登录框/闪屏阶段看不到入口**（而那正是最需要定位的时候）；
> ② 挤在状态徽章/退出/窗口控制之间，不像调试工具该待的位置。
> 现为 `position:fixed; left:14px; bottom:14px`，`z-index` 高于结果面板与所有业务层；
> **在 `App` 的登录门分支与主界面分支各渲染一次**（两处条件互斥，同时只存在一个实例），
> 因此闪屏 / 登录门 / 主界面三阶段入口恒可见。左下角是刻意的 —— 避开右下角的结果面板。
> 进入选择模式时按钮转为激活态（accent 描边 + 呼吸动画 + 文案变「退出选择」）。

**可拖动（2026-09-19 追加需求：「这个按钮设定为非固定位置可以长按拖动」）**：

- **长按阈值 `DRAG_HOLD_MS = 160ms`** 才进入拖动 —— 短按仍是「开关选择模式」，
  两种手势互不干扰。**关键判据：不能用 `onClick` 切模式**（拖一下就误切换），
  开关逻辑必须写在 `pointerup` 里按「是否移动过/是否进入拖动」分流。
- 实现：pointerdown 记基准 → 长按后 `setPointerCapture` 接管指针（移出按钮也不断）
  → pointermove 更新坐标（夹在可视区内）→ pointerup 落位并**记住位置**；拖动结束不触发短按。
- **位置记忆**：`localStorage["dy.inspector.pos"] = {x,y}`（**只存坐标**）——
  本工具唯一允许碰 localStorage 之处；守卫测试已显式豁免并**限制为单一键**。
- **防丢**：视口 resize 时把按钮夹回可视区；**双击复位**到默认左下角并清除记忆。
- `touch-action:none`（防浏览器把指针手势抢去做滚动）；拖动中禁过渡/位移（保证跟手）。

> 验证：`scripts/verify_inspector_drag.py`（**11 项**，真实鼠标 `mouse.down/move/up` 驱动）
> ——短按切模式 / 长按拖动跟随 / 松手不回弹 / 拖动不误触发 onClick / 写 localStorage /
> 刷新后位置保留 / 双击复位并清记忆 / 复位后短按仍可用 / 长按不移动不误切 / 无 pageerror；
> dev 与**生产构建**均 11/11 PASS。

**交互**：悬停高亮 → 点击选中 → 面板给出 CSS / XPath / Playwright / 组件链 / 结构 / 状态；
`↑↓` 父↔子、`←` 上移一层、`c` 复制、`Esc` 退出。面板「复制全部」产出可直接粘贴的取址报告。

**设计契约（未来同类需求照此办理）**：

1. **只选择、不触发** —— 必须三件事同时成立，缺一即静默破约：
   ① 拦截清单覆盖 `click/pointerdown/pointerup/mousedown/mouseup/contextmenu/submit` 等
   （**菜单类组件在 `pointerdown` 就展开**，只拦 click 无效）；
   ② 在 **window 捕获阶段**注册（`addEventListener(ev, fn, true)`），否则 React 委托根先收到；
   ③ `preventDefault + stopPropagation`。
2. **零业务耦合** —— 只读 DOM / React fiber，不读不写任何 API、store、localStorage；
   挂载点收敛为 TopBar 按钮 + App 根部面板两处，业务组件零改动。
3. **取址优先级**：`#id`（全局唯一）→ `tag.稳定类名`（root 内唯一）→ `tag:nth-of-type(n)`；
   **哈希类名永不入选择器**（构建期会变）。XPath 优先锚定最近 `data-od-id`。
4. **降级诚实**：fiber 属实现细节，生产构建压缩组件名 → 显示「不可用」，**绝不显示 `ep`/`t`
   这类压缩名**（误导性信息比不显示更糟）。React 组件按 PascalCase 约定过滤。

**实测捕获的 3 个真缺陷（都应进防线）**：

| 现象 | 根因 | 修法 |
|---|---|---|
| 能选中（高亮变）但**面板永不出现** | `swallow` 与 `onClick` 是 `click` 上**兄弟监听器**，`stopImmediatePropagation` 连自己的 `onClick` 一起吞 | 去掉 `stopImmediatePropagation` |
| 选择器/类名里混入 `ei-hover` | 工具自身悬停类被当业务类 | `classListOf` 过滤 `ei-` 前缀 |
| 点「复制全部」**毫无反应**（连提示都无） | `${(__APP_VERSION__ as string) \|\| "?"}`：**模板里的 TS 类型转换让 Vite `define` 常量替换失效** → 运行时未定义 → `ReferenceError` **被 async promise 静默吞掉** | 包 `frontendVersion()`：`try/catch + String(__APP_VERSION__)`（同 `api/client.ts` 惯例） |

**通用教训**：`define` 注入的常量一旦被包进类型转换/复杂表达式，替换即失效；且 **async
函数里的 `ReferenceError` 无 pageerror、无 console，静默消失** —— 排查必须直读**构建产物**，
不能只跑 dev server（dev 下 `__APP_VERSION__` 反而存在，问题只在产物暴露）。

**验证**：`scripts/verify_element_inspector.py`（真实浏览器 + 一次性临时 profile，
**20/20 PASS**，dev 与**生产构建**各跑一遍）；静态守卫
`backend/test_element_inspector_guards.py`（**13 项 OK**）。核心用例 =
「选择模式下点危险按钮计数不变」+「退出后点击计数 +1」。

**案例**：`工作记忆/cases/2026-09-19_前端元素选择模式_Element-Inspector_v0.43.93.md`

### 10.x 补充（2026-09-30，v0.45.126）—— 拖动判据必须是**位移**，不能是按住时长

**用户报障**：「元素选择按钮无法使用，点击之后变成『位置已记录』」。

**根因**：按钮的「短按=切换选择模式 / 拖动=移动」用**160ms 长按定时器**（`DRAG_HOLD_MS`）
区分——`pointerdown` 起定时器，到点即进入拖动态。普通点击只要按得稍慢（>160ms）或手抖 >4px，
抬起时就落进拖动分支 → 只写位置 + 弹提示，**永不切换选择模式**。

**修法（判据纠正）**：拖动意图由**实际位移**（`DRAG_MOVE_PX = 4`）判定，与「按住多久」无关；
`pointerdown` 立即 `setPointerCapture`，`pointermove` 首次超阈值才进拖动态。
静态守卫 `test_element_inspector_guards.py` 同步从 `assertIn("DRAG_HOLD_MS")` 反转为
`assertIn("DRAG_MOVE_PX") + assertNotIn("DRAG_HOLD_MS")`（**把该缺陷钉成负控**）。

**通用判据**：凡「单击 / 拖动 / 长按」复用一个控件，**时长不可作区分依据**（慢点击天然
冲突）——用**位移阈值**；且「位置已记住/已记录」这类**动作覆盖提示**本身即缺陷信号：
用户明明在点按钮，系统却执行了另一个动作。

**案例**：`工作记忆/cases/2026-09-30_元素选择失效与配置中心布局崩坏_v0.45.126.md`

## 十一、旧 CSS 下线后的**死类名**：字段布局崩坏（2026-09-30，v0.45.126）

**用户报障**：「配置中心所有子页面副标题像新手指南、暴露大量开发信息，文本链路超长，
导致输入框长度异常夸张、页面分布极其不合理」。

**根因（架构级）**：v0.43.16「旧 CSS 体系全量下线」删除了 `global.css`（含 `.set-field`
定义 `flex:1 0 220px; min-width:0`），但 `unified-config-widgets.tsx:SchemaField` 仍在用
**死类名 `set-field`**。父容器为 `display:flex; flex-wrap:wrap` ⇒ flex 项失去
`flex-basis / min-width:0` 后按 **max-content** 定宽；**中文无空格** ⇒ 一行 hint 即一个
不可断「单词」⇒ max-content = 整条 hint 长度 ⇒ 字段被撑到极宽、内部 `width:100%` 的
input 同步溢出、整页分布崩坏。

**修法**：关键布局**内联化**（不再依赖已删 CSS）：字段 `flex:1 1 240px; minWidth:0;
maxWidth:"100%"`；hint 加 `overflowWrap:"anywhere"` 限宽换行。

**铁律**：**CSS 体系迁移必须同步扫描「旧类名的消费点」** —— 删 CSS 而留 `className`，
在 flex 容器下会静默退化为 `max-content`（尤其中文长句），比样式缺失更严重（**撑破布局**）。
判据：迁移后用 `getComputedStyle(field).flexBasis` 回读，不是 `auto`/空即可疑。

**顺带收敛**（用户「保留简洁、删除冗余、勿暴露开发信息」偏好）：
`settings-page.tsx` 页头说明 78 字 → 一句；`UnifiedConfigSection` 的「保存到/当前」教学段落
压成一句；`app_config_schema.py` 8 条 hint 去掉 `BCC`/`hardcoded timeout=`/`socket`/`.env`/
`/api/probe/run`/`ADR-007 D2`/`带账号 cookie` 等内部实现细节（R13 同族反模式）。

**案例**：`工作记忆/cases/2026-09-30_元素选择失效与配置中心布局崩坏_v0.45.126.md`

### 10.y 配置中心 hint 全量瘦身（2026-09-30，v0.45.131）

**用户反馈**：「55 个字的说明也很长啊，给普通用户留这么长的说明干什么，如果非要提示，
只需告诉他们这个选项是干嘛的就行了」。

**铁律（本项目 UI 文案）**：**hint 只承担一句话说明「这个选项是干嘛的」（≤18 字）**；
与标签重复、或讲「为什么 / 怎么做 / 边界 / 不推荐」的内容一律删除（那些属开发信息，

**做法**：124 个字段的 hint 全量重写——**77 条压到 ≤18 字、47 条与标签重复者直接删除**

**契约安全**：只动 hint/label/option 文案；`type/default/min/max/env/apply` 逐项 AST 核对未变
（提交 `2237e72`，v0.45.131）。

**配套机械判据（可加进门禁）**：schema 的 `hint` 长度 ≤ 18 字、`label`/option 标签 ≤ 12 字。
