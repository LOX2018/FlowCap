## 〇、为什么这是第一优先

`00_爬虫项目说明.md` 列出七项必备机制（M1~M7）。**实测本项目的 M1/M3/M7 全部为零**：

| 机制 | 实测 | 后果 |
|---|---|---|
| M1 能力探针 | **0 个** | 只能等用户发现失效；改完不知效果是否还在 |
| M3 不确定性三态 | **0 处** | 抓到 37/44 不知算好还是坏 |
| M7 效果基线 | **无** | 无法判断改动是变好还是变坏 |

**这带来一个真实的历史代价**：2026-09-14 那轮「全解除」架构改动后，**无人敢回退**——
因为没有探针，任何回退都无法验证「业务效果是否还在」。同理，任何重构（P3）都无法验收。

> **结论：不先建 M1，P3 架构重构无法进行**（因为无法验证重构没破坏效果）。

## 一、效果定义的通用形式（三态 + 覆盖率）

### 1.1 禁止二态

```
❌ 现在：成功 / 失败
✅ 应为：确认成功 / 部分成功（带覆盖率与置信度）/ 确认失败
```

判定「部分成功」必须携带两个数字：**覆盖率**（拿到多少 / 应该有多少）与**置信度**（这些数据有多可信）。

### 1.2 置信度分级（对齐 `00_爬虫项目说明.md` §3.3）

| 级 | 来源 | 可否作结论 |
|---|---|---|
| A | 真实运行实例现场取证 | ✅ 可 |
| B | 官方协议/结构化响应解析 | 需 A 验证 |
| C | 页面结构/DOM/文案推断 | ❌ 仅线索 |
| D | 旧文档/旧日志/旧定性 | ❌ **必须重验** |

**探针输出的置信度 = 其数据来源的最低级**。例如「昵称来自 DOM 推断」→ 探针只能报 C 级，不得报健康。

## 二、五条业务链的效果指标（**待实测填值**）

> 下表为**定义**（应该测什么）。`当前值` 列必须由探针实测填入；
> 未实测前标注 `未知`，**禁止用推断值填充**。

### 2.1 会话更新与捕获（`更新会话`）

| 指标 | 定义 | 判据 | 健康阈值 | 当前值（2026-09-21 实测） |
|---|---|---|---|---|
| **会话覆盖率** | 落库会话数 / 抖音侧实际会话数 | 与 DOM 滚动枚举数比对 | ≥ 95% | 未知（**分母需外部观测源**，探针不臆造） |
| **昵称覆盖率** | 有真实昵称的会话 / 落库会话数 | 昵称 ≠ 数字 uid | ≥ 95% | 张老师 **0.9931** / 尚进 0.9775 —— ⚠️ **尚进最近一次捕获关联率 0.0（effective min=0.0 → failed）** |
| **消息完整度** | 落库消息数 / 应抓消息数 | 抽查目标会话 | ≥ 90% | 未知（分母需另一观测源） |
| **幂等性** | 重复触发后总条数不变 | 连点两次比对 DB | 必须 100% | ✅ 无重复行（msg_id 覆盖 张 1.0 / 尚进 0.9837） |
| **不降级性（I2）** | 新结果 ≥ 旧结果 | 比对前后 | 必须 100% | ⚠️ 已接入基线告警；尚进曾 −0.9775 |

**已知失效模式（必须被探针捕获）**：
- 昵称全为数字 uid（= 关联失败）
- `peer_name` 存的是数字 `peer_id`（DB 实测：`peer_name` = 假昵称）
- 会话数骤降（覆盖/降级）

> 🔴 **探针口径铁律（2026-09-21 实测确立）**：关联类指标必须取
> **`有效关联率 = min(库内历史比例, 最近一次捕获自身关联率)`** ——
> 库内比例是**历史快照**，可停在好状态而链路已失效（尚进即活例：库内 0.9775 但最近一次 0.0）。

### 2.2 私信发送

| 指标 | 定义 | 判据 | 健康阈值 | 当前值（2026-09-21 实测） |
|---|---|---|---|---|
| **真实投递率** | 对端实际收到 / 提交发送数 | **必须有真实写校验** | ≥ 95% | ⚠️ 仅有落库证据：张老师 173 条 role=me 但**投递验证标记 0** → **degraded**；尚进 98 条含验证标记 1 → healthy |

## 三、探针的实现要求（M1）

### 3.1 每条业务链一个探针，输出三态

```python
# 伪代码：探针契约
{
  "capability": "conversation_capture",
  "state": "healthy | degraded | failed",     # 三态，非二态
  "coverage": 0.0..1.0,                        # 覆盖率
  "confidence": "A|B|C|D",                     # 置信度（数据来源最低级）
  "measured_at": "ISO8601",
  "evidence": ["...硬证据..."],                # 判据留痕，禁止无证据报健康
  "baseline_delta": -0.02                      # 与上次基线差值（M7）
}
```

### 3.2 硬性要求

1. **必须真的执行**（发起一次真实链路），不是读缓存/读旧日志。
2. **必须留证据**：报告 `healthy` 时，`evidence` 不能为空。
3. **必须能被动触发**：不仅用户点击时可跑，还应能定期跑（发现"悄悄坏了"）。
4. **必须与基线比对**（M7）：报 `baseline_delta`，劣化即告警。
5. **不得用二态**。部分成功必须报 `degraded` 并带覆盖率。

### 3.3 接入点

| 位置 | 作用 |
|---|---|
| 后端启动后自检 | 开机即知各链路状态 |
| 关键动作后自检 | 「更新会话」完成后立即报覆盖率 |
| 定时巡检 | 发现"悄悄坏了"（当前**完全没有**） |
| UI 展示 | 用户一眼看到五链路的健康度 |

## 四、最低可用的第一步（建议）

不要一次全建。**先建一条：会话更新的覆盖率探针**。

理由：
1. 它是本项目**最核心的能力**（会话+昵称+消息是全系统的数据源）。
2. 它**最近刚发生过静默失效**（昵称 0 个、14/44），最需要防复发。
3. 它的判据已经明确（会话覆盖率 / 昵称覆盖率 / 幂等性 / 不降级性）。
4. 它为后续所有重构（P3）提供验收手段。

**验收判据**：人为制造一次失效（如临时断网/改错选择器），探针必须**先于用户**报出 `degraded/failed`。

## 六、已落地的探针（v0.44.29）

**入口**：`GET|POST /api/probe/run`（`?account=`/`capability=` 可选）、
`GET /api/probe/capabilities`、`GET /api/probe/status`（巡检状态）、
`POST /api/probe/patrol`（手动跑一轮）。
实现：`backend/services/probe.py`；测试：`backend/test_capability_probe.py`（**35 项**，含 v0.44.29 新增的 `with_browser` 分流 4 项）。

| 能力 | 对应 §2 域 | 判据（全部来自本地事实） | 三态规则 |
|---|---|---|---|
| `conversation_capture` | 2.1 会话捕获 | 库内会话/昵称率 **＋ 最近一次捕获自身关联率** | 有效关联率=**min(库内, 最近一次)**；超陈旧阈值→failed；<失败线→failed；中间→degraded |
| `send_delivery` | 2.2 私信发送 | role='me' 落库 + **显式投递验证标记** + 重复行 | 无记录→unknown；有重复→failed；**无投递验证→degraded（不得 healthy）** |
| `credential_identity` | 2.4 凭证有效性 | 落盘 `.env` uid ↔ conv_id 共同项（**AUTH-050**） | 不一致→failed；数据不足→unknown |
| `live_danmaku` | 2.3 直播监听 | 日志 `[弹幕]` 行的 **uid==111111 且 sec_uid 空** | 窗口内无弹幕→**unknown（未监听≠失效）**；真实率<失败线→failed |
| `ai_lead_capture` | 2.5 AI 获客 | `ai_leads` 条数 + 联系方式有效率 + 窗口内 AI 活动 | 无留资→unknown；有效率<0.5→failed；**有效率够但无 AI 活动→unknown** |
| `message_integrity` | 2.1 幂等性 | msg_id 覆盖率 + (conv_id,msg_id) 重复行 | 无消息→failed；有重复→failed；覆盖<0.8→degraded |

**零风控硬边界（源码级测试守护）**：探针**只读** SQLite + 本项目运行日志，
**绝不发起网络请求、绝不触碰/启动浏览器（BCC）**。真实链路验证仍由
`POST /api/messages/{account}/refresh`（用户显式动作）负责。

### 6.1 三条由此轮实测确立的判据铁律

① **「最近一次」优先于「库内历史」**（防**探针假健康**）：
实测尚进最近一次捕获 `uid关联=0 未命中44/44` 而库内 `0.9775` → 只看库会报 healthy。
⇒ 关联类指标取 `min(库内历史, 最近一次)`。

② **落库 ≠ 投递**：`role='me'` 行只证明本地落库；**skey 存在性也不是投递证据**。
⇒ 无「显式投递验证标记」时，发送域最多报 `degraded`。

③ **未活动 ≠ 失效**：探针观测窗内没有该域活动（未监听直播、无 AI 活动）时必须报
`unknown` 并写明「未活动」，**不得** 报 healthy 也不得报 failed。

### 6.2 阈值（唯一来源：配置中心 `capture.probe_*`）

| 键 | 默认 | 含义 |
|---|---|---|
| `probe_min_convs` | 10 | 低于此数判 degraded |
| `probe_nickname_healthy` / `probe_nickname_degraded` | 0.95 / 0.50 | 有效关联率的健康线 / 失败线 |
| `probe_capture_stale_sec` | 3600 | 最新捕获超此秒数 → failed |
| `probe_live_window_hours` | 24 | 弹幕观察窗（窗内无记录→unknown） |
| `probe_live_healthy` / `probe_live_degraded` | 0.95 / 0.50 | 弹幕真实率健康线 / 失败线 |
| `probe_ai_window_hours` | 72 | AI 活动观察窗 |

### 6.3 覆盖率口径（诚实标注）

`conversation_capture.coverage` 与 `send_delivery.coverage` **恒为 null**：
真实分母（抖音侧会话数 / 对端实际收到数）需**独立观测源**，本探针**不臆造分母**，
只按绝对量 + 可证伪的比率判档，并在 `coverage_note` 写明。`live_danmaku` /
`ai_lead_capture` 的 coverage 是**真实比率**（分母来自本地日志/DB）。

## 七、定时巡检与 UI（v0.44.28，P1 收尾）

### 7.1 定时巡检（M1 的「发现『悄悄坏了』」那一环）

**为什么必须有**：`02` 原文 §3.3 早已列出「定时巡检」接入点，但实测**完全没有** ——
历史上所有能力失效（昵称归零、投递失败、弹幕脱敏）**都是用户先发现的**。
探针只有「用户点击时才跑」= 探针的价值大打折扣。

| 项 | 实现 |
|---|---|
| 调度原语 | `threading.Timer` 循环（**与 `kb_maintain` 同一原语**，不新增第二套调度机制） |
| 启动点 | `main.py` lifespan（后端启动后自动）；`probe_patrol_enabled=false` 可关 |
| 周期 | 默认 **15 分钟**（`probe_patrol_interval_min`）；首轮延迟 120s（`probe_patrol_first_delay_sec`） |
| 状态持久化 | kv `capability_probe:patrol:state`（runs / last_run_at / last_result / errors[-20:]） |
| 异常处理 | 内部异常**兜住并记录**，绝不中断循环（测试已覆盖） |
| 手动触发 | `POST /api/probe/patrol`（与定时器那一轮等价） |
| 只读保障 | 巡检调用的就是探针本身 → **零网络零浏览器**，可安全高频 |

### 7.2 UI（总览页「能力健康」区块）

**位置选择依据**：与「AI 运行状态」同层 —— 都是**产品级运行状态**，不是某页的局部功能，
故并入总览页（用户打开首页一眼看到五域健康度）。

展示：总体态徽章（healthy/degraded/failed/unknown **四态各有独立视觉**）+
四态计数 + 需关注项（`能力@账号`，能力名译中文）+ 巡检节奏 + 上次耗时 + 「立即巡检」按钮。
**unknown（未定论）绝不显示成健康** —— 这是三态语义在 UI 层的落地。

**验证（三道，缺一不算完）**：
1. `tsc -b` 通过；2. **产物 grep**：5 个用户可见文案全命中（构建绿 ≠ 页面进包）；
