### v0.43.47 — 租约竞态 + schema 重复键（commit `7d3f2ff`）

**① 租约跨线程竞态（实测 30/30 复现）**
`_lease`/`_scan_exclusive` 是模块级 dict，读写分布在 FastAPI 主 loop 与
`run_keepalive` 子线程，**全程无锁**；`_lease_acquire` 是「读→判空→写」三步非原子
→ 并发同时通过判空 → **双写覆盖** → 后写者 lease_id 生效，先写者无法 release
→ 租约要等 TTL（最高 600s）才被回收，**期间全部业务被 403/busy 挡回**。

**② `app_config_schema.py` 字典重复键 10 个**（agent 报 8，实查 10）
Python 字面量重复键 **last-wins 且无告警** → 前一份（`scan_interval` 5~86400）被静默丢弃。

**③ 其他**：`/show` 吞 body；`refresh_cookie_to_env` 写盘失败**谎报成功**；
`/linkmic_run` **绕过租约仲裁**；`_nav_page` 引用不回收。

## 七、方法论沉淀

1. **外部报告必须逐条实测甄别**（误报率 ~47%），但**不要整体否定**（它能抓你的回归）。
2. **收敛优于逐点**：64 处 `verify=False` 不逐个改，而是引入统一策略模块 + 显式开关。
3. **同类必须找全**：判「某机制正确」前 `search_files` 找齐所有同类实现做对照。
4. **修复必须给「修复前也复现」的对照**；只证明「修完通过」是无效验证。
5. **静默失效最危险**：本轮最高价值缺陷（NameError / 配额泄漏 / 缓存僵尸）
   都被 `except: pass` 或调用方降级成日志，表面毫无症状。
6. **不臆造实现**：`generateSecretPhoneNum/Code` 全仓不存在 → fail-closed 而非猜测补全。
