## 三、🔴 必须上报的两个风险

### 风险 1 · 重构「自身」制造的新跨模块耦合面（阻断级；**已知 3 处，2 修 1 未修**，根未除）

**事实**：P3-5 大组件拆分**插入了此前不存在的跨模块边界**，两条边界各带一个未验证的隐性前提：

1. **模块身份分叉**：入口 `browser_daemon.py` 以 `__main__` 运行，却被 `bcc_routes.py` 按包名 `daemon.browser_daemon` 反向 import ⇒ `sys.modules` 两个键并存 ⇒ `_state` 两份 ⇒ 空 `_state` ⇒ `BCC-051` 熔断、容器永不启动、日志 sink 被删致 **日志 0 字节**。
2. **startup 双跑**：生命周期 handler 从 `@app.on_event` 搬到 `@router.on_event` + `include_router` ⇒ 上游 FastAPI 语义下 **`_startup()` 执行 2 次** ⇒ 双容器抢 profile ⇒ BCC-058/BCC-006「反复激活」。

**为何以前不出事**：拆分前 handler 与 `_state` 全在同文件、无「他模块反向 import 入口」这条边。**拆分创造了这条边。**

**现处置**：`sys.modules.setdefault` 归一 + 「路由可 include、生命周期不行」——**属绷带**。

**🔴 第 3 处（本会话独立复核新增，原报告未列）**：`daemon/bcc_login.py:230` 的 `scan_login` **P0 独占租约恒被拒**——外层 `_exec` 已持 `bcc-internal`(prio=2, ttl=30)，内层再 `_lease_acquire("scan_login","exclusive",0)` 必然返回 `{'ok': False, 'busy': 'bcc-internal'}` ⇒ `_sl_lid=None` ⇒ 扫码登录的独占租约**从未建立**。**实测复现**（非静态推断）。
同族第四处敞口：`daemon/recv_daemon.py` 同形态入口**无归一、无守卫**（`sys.modules.setdefault` 计数 0；用最小合成对证明未归一必然模块级状态分叉）。
⇒ **拆分引入的跨模块边界共 4 处，2 修 2 未修**；这正是「逐处修」不如「结构性消除」的直接证据（见下方架构判断）。

> **架构判断（本条的价值所在）**：这是 §I「禁止巨大组件 / SoC」的反面教材——
> **拆分若只搬代码、不定义新边界的前置条件，会把 bug 从"体积问题"升级为"身份问题"。**
> 结构性解法：**入口与库分离**（专用 `__main__.py`/launcher 入口，禁止任何模块按包名 import 入口），
> 并写入 `00_爬虫项目说明.md` §3.1 分层不变式。建议列为下一 P 窗口的架构决策（出 ADR）。
