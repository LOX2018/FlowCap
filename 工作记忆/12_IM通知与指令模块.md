> 2026-09-08 新增。用户需求：把 AstrBot（https://github.com/AstrBotDevs/AstrBot）

## 12.1 关键决策：提取组件，不是整项目嵌入

用户明确：**「我并不需要整项目嵌入而是提取需要的项目组件就行」**。

AstrBot 是 40k stars 的 Python Agent 平台，其平台适配器
（`astrbot/core/platform/sources/*`）重度耦合自身框架：
`Platform` 基类、`AstrBotMessage`、`MessageChain`、事件队列、Star 插件体系。
整文件搬入会拖入上千行无关代码 + 全套依赖。

**本项目只需要「出站推送」** —— 汇报和告警是单向的，不需要入站事件建模。
因此只按各渠道的**真实 HTTP 协议**重写精简客户端。

### ⚠️ iLink 被动回推硬约束（协议级，非缺陷）

`sendmessage` **必须携带 `context_token`**，而该 token 只在**收到过该用户消息后**
才存在。对方必须先给机器人发一条消息，机器人才能回推。
AstrBot 源码原话：`"context token missing for %s, skip send. You should send one
message to refresh context_token."`
→ 代码里 `WeixinOCChannel` 无 token 时明确报错，不静默失败。

## 12.7 事件桥接层（2026-09-09 补齐：从「模块」到「真的会告警」）

> 上一版只建好了通知模块，**但 `notifier.emit()` 没有任何业务代码调用**
> —— 即「凭证失效提醒 / 私信汇报 / 任务监控」三件事还没真正接上。
> 本次补齐 `backend/notify/events.py` 桥接层 + 4 个真实埋点。

### 为什么要单独一层 events.py
业务代码（`core/sender.py`、`core/auto_dm.py`）**不直接 import notifier**：
- 通知异常绝不能反噬主流程（emit 全吞异常）
- 未启用时几乎零开销直接 return
- 业务只描述「发生了什么」，不关心推到哪个渠道

### 4 个真实埋点（位置均实测 grep 确认）

| 事件 | 埋点位置 | 级别 | 节流 |
|---|---|---|---|
| 凭证失效 `cred_expired` | `core/sender.py:_maybe_auto_recapture` | critical | 600s/账号 |
| 任务启动 `task_started` | `core/auto_dm.py:_run` 状态置 RUNNING 后 | info | 60s |
| 任务结束 `task_finished` | `core/auto_dm.py:_finish_history_task` | info | 60s |
| 运行异常 `task_failed` | `core/auto_dm.py:_run` except 块 | critical | 120s |

**关键设计**：
- 凭证失效**先告警再重捕获**（即使重捕获失败，人已收到通知）
- `task_finished` **复用 `_finish_history_task` 里已有的真实 count/sent 计数**，
  绝不另算一套（避免「日志说发完但实际漏发」的误导）
- 节流按 `dedup_key` 区分账号：A 账号告警不会屏蔽 B 账号

### 验证：15/15 通过（真实事件流，非 mock）
未启用时零副作用 / 任务启动含直播间信息 / 结束汇报含真实计数
（成功7 失败2 成功率78%）/ **8 次凭证告警只推 1 条** / 不同账号不受影响 /
critical 无视 min_level / 风控 KICK 告警 / auto_fixing 文案正确。

### 🔴 打包后暴露的真实 bug：adm 反查失败（已修）
- **现象**：裸源码跑测试一切正常，打成 exe 后 `/api/notify/command`
  的「查询状态 / 停止任务」恒返回 `{"reply":"引擎实例不可用"}`。
- **根因**：`_get_adm()` 用运行时 `from main import app` 反查 `app.state.adm`。
  **PyInstaller onefile 下模块身份/导入顺序不可靠**，反查拿不到实例
  （`app.state.adm` 在 lifespan 内确实赋过值，不是没赋值）。
- **修法（不靠猜，改成确定性注入）**：`api/notify.py` 新增
  `_BOUND_ADM` + `bind_adm(adm)`；`main.py` 在 `app.state.adm = AutoDM()`
  **之后**立即 `notify_api.bind_adm(app.state.adm)`。运行时反查仅作回退。
- **实测对照**：
  - 修复前：`{"reply":"引擎实例不可用"}`
  - 修复后：`{"state":"EngineState.IDLE","status_msg":"未启动","sent":0,"failed":0}`
  - 「停止任务」真实执行：`{"ok":true,"state":"idle"}`

> 教训：**凡是「运行时从 main 反查全局对象」的写法，在 PyInstaller 下都不可信**。
> 新模块需要引擎/全局状态时，一律在 main 里显式 bind 注入。

## 12.6 风控红线（延续既有铁律）
