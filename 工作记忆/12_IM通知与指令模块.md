> 2026-09-08 新增。用户需求：把 AstrBot（https://github.com/AstrBotDevs/AstrBot）
> 「嵌入」本项目，用于 **任务新建 / 任务监控 / 私信情况汇报 / 凭证失效提醒**。

## 12.1 关键决策：提取组件，不是整项目嵌入

用户明确：**「我并不需要整项目嵌入而是提取需要的项目组件就行」**。

AstrBot 是 40k stars 的 Python Agent 平台，其平台适配器
（`astrbot/core/platform/sources/*`）重度耦合自身框架：
`Platform` 基类、`AstrBotMessage`、`MessageChain`、事件队列、Star 插件体系。
整文件搬入会拖入上千行无关代码 + 全套依赖。

**本项目只需要「出站推送」** —— 汇报和告警是单向的，不需要入站事件建模。
因此只按各渠道的**真实 HTTP 协议**重写精简客户端。

（用户确认：个人微信 = 腾讯官方 iLink Bot API / ClawBot 方案）

### ⚠️ iLink 被动回推硬约束（协议级，非缺陷）

`sendmessage` **必须携带 `context_token`**，而该 token 只在**收到过该用户消息后**
才存在。对方必须先给机器人发一条消息，机器人才能回推。
AstrBot 源码原话：`"context token missing for %s, skip send. You should send one
message to refresh context_token."`
→ 代码里 `WeixinOCChannel` 无 token 时明确报错，不静默失败。

## 12.3 代码结构

```
backend/notify/
  channels.py    五渠道出站客户端（统一 send_text 接口 + 重试 + 配置校验）
```

### 补充实测：企业微信发送协议（2026-09-08 二次核验）

AstrBot 的 wecom 适配器走 `wechatpy` 库（`from wechatpy.enterprise import

- 端点：`POST https://qyapi.weixin.qq.com/cgi-bin/message/send?access_token=`
- body：`{"touser","msgtype":"text","agentid":int,"text":{"content"}}`

## 12.4 实测坑位（务必记住）

1. **`start_engine` 真签名是 `(request, config: TaskConfig)`**，不是无参。
   `TaskConfig` 文案字段是 `dm_pool: list[str]`（不是 dm_text），账号字段是 `acct`。
   —— 凭记忆写会直接 TypeError，这次是实测 grep 后修正的。
2. **`asyncio.run()` 结束会取消 worker**：测试里分两个 `asyncio.run` 验证节流，
   第二个事件因 worker 已被销毁而不派发（误报 bug）。Worker 现改为
   queue 只初始化一次 + 取消时事件回队。测试须在同一事件循环内断言。
3. **fastapi 0.141 的 `include_router` 会包装成 `_IncludedRouter`**，
   `[r.path for r in app.routes]` 会 `AttributeError`。
   验证挂载是否成功要用 **TestClient 真发请求**，不要靠遍历 routes。
4. 后端依赖不在 hermes venv 里，验证用
   `C:\Users\LOX\AppData\Local\Programs\Python\Python314\python.exe`（loguru/fastapi 齐）。

## 12.5 打包部署实测（2026-09-08，第二次打包后通过）

改动是**纯 backend Python**（`notify/` 新包 + `api/notify.py` + `main.py` 挂载），

### PyInstaller 隐性依赖（必须显式声明）
`main.py` 里 notify 是 **try/except 容错 import**（挂载失败要降级而非崩溃），
这类 import 易被静态分析判为可选依赖漏打。已在 `scripts/build_sidecar.py`
的 `if entry == "main.py"` 块追加（与 wp_recv / multipart 同款处理）：
```
notify / notify.channels / notify.cmd_parser / notify.notifier / api.notify / aiohttp
```

### 🔴 打包后暴露的真实 bug：adm 反查失败（已修）
- **现象**：裸源码跑测试一切正常，打成 exe 后 `/api/notify/command`
  的「查询状态 / 停止任务」恒返回 `{"reply":"引擎实例不可用"}`。
- **根因**：`_get_adm()` 用运行时 `from main import app` 反查 `app.state.adm`。
  **PyInstaller onefile 下模块身份/导入顺序不可靠**，反查拿不到实例
  （`app.state.adm` 在 lifespan 内确实赋过值，不是没赋值）。
- **修法（不靠猜，改成确定性注入）**：`api/notify.py` 新增
  `_BOUND_ADM` + `bind_adm(adm)`；`main.py` 在 `app.state.adm = AutoDM()`
  **之后**立即 `notify_api.bind_adm(app.state.adm)`。运行时反查仅作回退。
- **实测对照**：
  - 修复前：`{"reply":"引擎实例不可用"}`
  - 修复后：`{"state":"EngineState.IDLE","status_msg":"未启动","sent":0,"failed":0}`
  - 「停止任务」真实执行：`{"ok":true,"state":"idle"}`

> 教训：**凡是「运行时从 main 反查全局对象」的写法，在 PyInstaller 下都不可信**。
> 新模块需要引擎/全局状态时，一律在 main 里显式 bind 注入。
