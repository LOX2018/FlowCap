## 一、设计意图回归（Step 1）

| 项 | 内容 |
|---|---|
| 模块 | `backend/utils/ab_pure.py`（a_bogus 签名器）+ `backend/builder/params.py` + `backend/dy_apis/client_live.py` |
| 设计契约 | a_bogus 是对 **query+body** 的完整性签名，其中内嵌 `(aid, page_id)` 标识**请求所属子域**；调用方签名时的 host 必须与请求实际发出的子域一致 |
| 期望行为 | 对 `live.douyin.com` 的请求，签出**直播域**的 a_bogus（aid=6383, page_id=**7571**） |
| 假设 | 「签名只要算法对就行，子域无关」——**本例证伪** |

## 二、偏差（Step 2）

- 偏差类型：data（签名内容错 → 服务端静默拒绝）
- 偏差点：`ab_pure.py:288-291`，`L[67..70]`（page_id）与 `L[71..74]`（aid）**均写死 `6383`**
- 偏差描述：page_id 应为 7571（直播域）/ 11881（主站），实际填成了 aid 的值 6383

⇒ 本仓是**移植时漏接了这段能力**，不是「抖音刚改版」。

## 四、根因（RCA）

```
直播请求 → Params.with_a_bogus()
             ↓ 本仓无 host 参数，恒按 www.douyin.com
         generate_a_bogus() → _pure_sign().sign('https://www.douyin.com/?...')
             ↓ sign_query() 内 L[67..70]=le(6383,4)  ← 写死，应为 page_id
         a_bogus 携带主站 (6383,11881) 身份
             ↓
         live.douyin.com 收到「自称主站」的签名 → 静默拒绝/降级
             ↓
         表现：直播流数据全部拉不到，且**无任何报错**
```

**为什么"静默"最危险**：这类缺陷不抛异常、不打日志，靠运行时观察永远发现不了。

## 九、可复用判据（沉淀）

1. **「数据拉不到且无报错」优先查签名身份，而非连通性**——连通性故障通常有异常，签名错才静默。
2. **判断「上游是否新增了某能力」要用 `git log -S <符号>`**，而不是看 `pushed_at` 变新。本例上游近期 4 次提交**都与本故障无关**，真正的能力是更早引入、本仓漏移植的。
3. **diff 到函数体而非文件名**：`with_a_bogus` 两侧同名，只有读到签名 `host` 参数才看得出差异。
4. **WS「连上但零帧」不能直接判为失效**——真实客户端每 5s 发 `payloadType='hb'` 心跳；裸连接不发心跳时零帧是**预期行为**，加心跳后立刻收到 4 帧。（本例踩过一次误判。）
5. **修完必须用 stash 对比基线**，否则无法区分「新增回归」与「存量失败」——本例 4 项失败在改动前后完全一致。
