## 2. 债 A：契约要求运行的模块，只有 0 个用例

**根因**：`test_config_isolation.py` 原为 **32 行纯 helper（0 个 `def test_`）**，
但契约 `docs/design-contracts/C-03-credential-verification.md` §5 把它列为 C-03 的验证命令：

```
py314 -m unittest test_config_isolation
```

而 G14（`scripts/check_contracts.py:314-357`）从契约文档**正则抽取** `-m unittest <mod>`
作为「契约要求的单测模块」，逐个运行，并按 `FAIL:/ERROR:` 行**逐用例登记**；
**无用例时登记文件级** ⇒ 只能补真判据，**不能靠豁免绕开**（脚本注释明写「禁文件级豁免」）。

**修法**：补 `TestConfigIsolation`（3 个用例），但**不是空壳占位** —— 三条断言在隔离失效时必然变红：

| 用例 | 断言 |
|---|---|
| `test_app_root_is_isolated_temp_not_repo` | `DY_APP_ROOT` 非空、位于系统临时目录下、**不在源码树内** |
| `test_database_resolves_under_isolated_root` | **真实解析**的 `database._db_path()` 落在隔离区且不在源码树 |
| `test_fresh_returns_usable_app_config` | `fresh()` 返回可用 `app_config`（含 `reset_section`） |

**负控（证明断言真会变红）**：注释掉导入期 `os.environ["DY_APP_ROOT"] = _ROOT` →
`FAILED (failures=2)`，证据原文：
`DB 路径未落在隔离根: C:\...\DYAutoDM_v2\data\dyautodm.db`（正是要防的源码树污染）。

### 2·甲 我在修的途中自己引入并纠正的两个错（记录以免复发）

1. **加了 `if __name__ == "__main__": unittest.main()`** → 该文件同时被
   `test_b4_global_switches` 等按包名 import ⇒ 触发

## 3. 债 B：沙箱 DB 跨运行持久 → 窗口用例依赖历史运行

**症状复现（单跑必失败）**：残留数据留痕

```
acct=acct__delays_send  uid=w1  wend=1790217941  [已过期 19273s前]
```

**机理**（两段叠加）：

1. **测试侧**：`test_uid_sink_ext.py` 把 `DY_APP_ROOT` 指向**固定**临时目录
   （`<tmp>/uid_sink_ext_test`）⇒ **沙箱 DB 跨运行持久**（实测该库 mtime 跨小时仍被复用）。
2. **生产语义**：`UidSink.mark_seen()`（`services/dm_dispatch.py:765-826`）是
   `INSERT OR IGNORE`（冲突**不覆盖**）+ **仅高价值(`hv=1`)才走刷新窗口的 CASE**
   ⇒ 二次调用时旧 `window_end_ts` 被**保留**。

⇒ 第 2 次运行时，`should_send` 读到**已过期**的 `window_end_ts` → 放行 →
`assertFalse(ok)` 失败。**单跑必失败、全量偶发**（取决于上次跑留下的时间戳）。

**组合运行另有加剧因素**：`member_ctx._resolve_member_id()` 有**三个**来源

```
mid = current_member_id() or os.environ.get("DY_MEMBER") or ""
if not mid:
    mid = _session_file_member_id() or ""     # ← 第三来源：盘上会话
```

而 `clear_current()`（`member_ctx.py:180-186`）只清**进程内 `_current` + `DY_MEMBER`**，
**不清盘上会话文件**（`<app_root>/members/.session.json`）⇒ 会员上下文跨测试泄漏，
把 `get_db()` 重定向到**固定**的会员空间路径
（`.../dyautodm_cfgtest_root/members/<id>/data/dyautodm.db`，同样跨运行持久）。

**修法（最小、稳健、与「库是哪个文件」解耦）**：`setUp` 里显式清零**本账号自己的**残留行：

```python
database.reset_connection()
conn = database.get_db()
conn.execute("DELETE FROM dm_uid_sink WHERE account=?", (self.acct,))
conn.commit()
```

> 为什么不用「清 `DY_MEMBER`」或只 `reset_connection()`：
> 前者治标（第三来源是**盘上文件**，与 env 无关）；后者不够（下一次 `get_db()` 仍会按
> 同一会话解析到同一个**陈旧**库文件）。显式清零与 DB 解析结果无关，故**顺序无关**。

**负控（证明修复必要且充分）**：还原成固定根 + 预置**已过期**窗口 →
`FAILED`，与原始故障**完全相同**的
`AssertionError: True is not false : 窗口未到期必须拒绝（实际 reason=''）`。

## 5. 🔴 未闭环：测试隔离泄漏（根因已定位，**未擅自动手**）

**判据**：`test_uid_sink_ext` 的模块级 docstring 原本**自认**：

> 「隔离的正确判据是『不落到仓库相对路径』，由 `test_config_isolation` 守护」

**实测不成立**：一旦某个测试留下**盘上会话**，后续模块的
`database.get_db()` 会被重定向到那套会员上下文对应的路径 —— **固定且跨运行持久**。
即「测试套件的实际 DB 落点每次不同」，这本身就是测试基础设施缺陷。

**根因（三处协同，任一单独都有其正当性）**：

| # | 位置 | 行为 |
|---|---|---|
| 1 | `member_ctx._resolve_member_id()` | 第三来源 = 盘上会话文件（为**独立进程**能解析会员空间而设计，有正当理由） |
| 2 | `member_ctx.clear_current()` | 只清 `_current` + `DY_MEMBER`，**不清盘上会话** |
| 3 | `test_member_smoke` 各用例 | 用**固定**沙箱路径（`dy_member_smoke_` 或固定 cfgtest 根） |

**为何未修（诚实标注）**：
- 改 `_resolve_member_id` 或 `clear_current` 会触及**生产会员安全边界**（跨会员隔离/`.env.enc`
  可读性），属架构级改动，按纪律需先出 ADR 并由用户拍板；
- 本轮是「清测试债」，把生产路径一起改会扩大爆炸半径、且违反「迭代止损律」
  （同一缺陷已尝试 4 次，第 5 次必须换取径而非继续局部打补丁）。

**建议取径（供用户拍板，二选一）**：
1. **测试侧**：给 `test_member_smoke` 的沙箱也改 `mkdtemp`（与债B 同法），
   消除跨运行持久 —— 风险最低，只动测试。
2. **生产侧**：让「测试/无会话进程」的 `_session_file_member_id()` 可被显式禁用
   （如 `DY_DISABLE_SESSION_FALLBACK=1`，测试专用开关）—— 更彻底，需 ADR。
