## 1. 设计意图（Step 1）

ADR-002 §3.4(B) 用户决策：多账号同房间监听时，「沉淀池必须跨账号——同一用户在同房间被任一账号发过后，其余账号不得再发；发送额度在账号间做交替/轮次分配」。

§5.4 策略中心已落地配置面（`sink_global_scope`、`rotation_strategy`、`sink_cooldown_days` 等 7 字段），但 **运行时未消费**。§5.5(B) 即为消费点实现。

### 现存差距

现有 `dm_uid_sink` 主键 `(account, peer_uid)` ⇒ 账号是去重维度，**跨账号天生不去重**。多账号并发下同一用户会被每账号各发一次。

### 设计契约

| 判据 | 预期 |
|---|---|
| `sink_global_scope=true` 时 | `submit_by_uid` 优先跨账号沉淀池（`dm_cross_sink`），同一 `peer_uid` 冷却期内拒绝一切账号 |
| `sink_global_scope=false` 时 | 回退 `dm_uid_sink`（per-account 旧路径），行为不变 |
| 轮转分配 | 多账号竞争同一 uid 时 `RotationAllocator` 选一账号发，其余静默丢弃 |
| 冷却参数 | 取自 §5.4 `sink_cooldown_days`（默认 90 天）/ `sink_permanent` |

## 4. 根因（Step 4）

原设计 `UidSink` 以 `(account, peer_uid)` 为主键时，其「去重」语义天然绑定到单账号。多账号并发场景下，同一 `peer_uid` 出现在 N×账号 = N 条独立记录，**零拦截**。

解决路径：新表 `dm_cross_sink`（`peer_uid` 全局 PK）作为优先裁决层，与旧 `dm_uid_sink` 并存——`sink_global_scope=true` 时前者拦截后不再查后者；`false` 时绕过前者，维持旧行为。

## 5. 实现变更（Step 5）

### DB (`database.py:228-239`)

```sql
CREATE TABLE IF NOT EXISTS dm_cross_sink (
    peer_uid TEXT NOT NULL PRIMARY KEY,
    account_sent TEXT NOT NULL,       -- 最后发送的账号
    nickname TEXT DEFAULT '',
    source TEXT DEFAULT '',           -- live(弹幕) | crawl(采集) | manual
    sent_ts REAL,                     -- 最后发送时间
    cool_until REAL,                  -- 冷却到期时间（预计算）
    send_count INTEGER DEFAULT 0      -- 累计发送次数
);
```

### 跨账号沉淀池 (`services/dm_dispatch.py:548-621`)

`CrossAccountSink`：

| 方法 | 职责 |
|---|---|
| `__init__` | `_lock`（线程级）+ `_cache: Dict[str, float]`（一级内存缓存）+ `_loaded` |
| `_ensure_loaded()` | 懒加载：从 `dm_cross_sink` SELECT 全量刷入内存 |

if _cross_sink_global_scope():

    # 轮转分配器选发送者

## 8. 已知边界（诚实标注）

- **端到端未验**：跨账号沉淀池的运行时行为（真实弹幕流 → dispatch → sink → 轮转 → 发送）当前**仅单元覆盖**，未在真机双账号并发送证。
- **轮转分配器全存内存**：`_last_sender` / `_window_sender` / `_room_owner` 进程重启后清空 ⇒ per_target/per_time_window 策略下重置为首个账号，per_room 策略下重新注册。
- **异常路径不写冷却**：`_send_one` 中 `cross_sink.mark_sent()` 只在 `ok=True` 分支执行（`1296-1299`）。异常/超时 → 不写 cross_sink → 下次可重发同一 uid（设计行为：发送未确认成功不应冷却）。
- **前端多任务卡片（§5.6）仍待实施**：当前引擎状态与账号管理通过现有编排层 API 可查，但无独立的多任务 UI 面板。

## 9. 通用判据（可迁移）

1. **跨账号去重必须在 DB 层面设计为全局主键**，不能依赖 per-account 的 `UNIQUE(account, uid)` —— 只要主键含 `account`，跨账号的「同一 uid 被任一账号发过即不应再发」就做不了。
2. **新特性与旧路径并存时，用配置开关切换**而非直接替代。`sink_global_scope=true/false` 让新/旧行为可对比、可回退，不影响已有单账号用户。
3. **轮转分配的内存持久化问题**：进程重启即失在「持续运行 + 不重启」的部署模式下可接受，但若出现运维重启，轮转历史丢失可能导致冷却期内同 uid 从另一账号获发（已由 `cross_sink.should_send` 拦截兜底 —— 轮转选人 × 去重拦截两者解耦，单一失效不导致重复发送）。
