# 案例归档：更换指纹浏览器内核为 Camoufox（可切换），v0.44.0

**日期**：2026-09-20
**版本**：v0.44.0（design/better-douyin，运行实例 `C:\temp\dyautodm_design`）
**严重度**：fatal（抖音登录交互被拦 → 凭证无法更新）
**状态**：内核已接入并可切换；**Camoufox 独立验证通过（两轮未弹窗）**，
        但在项目内的端到端（昵称/WS 链路）**尚未验证**

---

## 一、设计意图

`vbrowser.launch_async/launch_sync` 是**全部 34 处**浏览器启动调用点的唯一出口
（扇入架构）。接入新内核必须：
1. **调用方零改动**（门面模式，本项目既有做法）；
2. **可配置回退**（Chromium 保留），避免把路走死；
3. 沿用既有铁律：单 profile、headless 是调用方意图、代理由配置显式决定。

## 二、为何更换（触发原因）

现行方案 = ungoogled-chromium + `add_init_script` 注入劫持
`window.fetch` / `XMLHttpRequest` / `WebSocket`。

抖音在**交互时刻**（扫码授权、输手机号）弹：
「您正在尝试访问的网站存在安全风险…已阻止此次访问」。

**关键对照（决定性）**：

| 内核 | 首屏 | 点「验证码登录」 | 输手机号 |
|---|---|---|---|
| Chromium + 注入 | 正常 | **🔴弹窗**（复现 1 次） | — |
| **Camoufox（C++ 层注入）** | 正常 | **⚪未弹窗** | **⚪未弹窗** |

Camoufox 连续**两轮**（冷启动 + 复用 profile）均通过。
其官方设计：*Fingerprint injection & rotation (without JS injection)* ——
数据拦截在 **C++ 实现层**，无法通过 JavaScript 检查发现。

## 三、过程中的错误判断（必须记录，避免重犯）

1. **误判「出口 IP 分叉」为唯一根因**：确实修复了真实 bug
   （`_env_path_of_account` 会员路径解析失败 → 配置从未生效），
   但修完后仍弹窗 → 说明还有第二个变量。
2. **一度错误断言「换浏览器无效」**：基于一次不可靠观察
   （Chromium 场景页面间歇空白），差点终止正确方向。
   **教训：单次观察（尤其样本=1）不得作为定论依据。**
3. **实验方法缺陷（根）**：此前所有对照都用 `tempfile.mkdtemp()`
   = **全新环境**，而全新环境本身就是风控放大器 →
   「页面空白 / 弹窗」可能只是新环境副产物，与内核、注入均无因果。
   改用**持久 profile** 后才得到稳定可判读的结果。

## 五、验证

- 守卫测试 **37/37 PASS**。
- Camoufox 独立验证（持久 profile，含冷启动）：首屏正常加载、点验证码登录
  **未弹窗**、输手机号**未弹窗**，两轮一致。
- 出口 IP 经 Camoufox 实测 = `23.191.200.205`（与代理一致）。

## 六、遗留与风险（必须知悉）

1. **Firefox 与 Chromium 的 profile 不兼容**：Camoufox 使用
   `<账号profile>/_camoufox` 子目录 = **全新环境**，需**重新扫码**。
2. **私信 WS 抓取不可用 JS 注入**：Camoufox 下已禁止注入，WP 通道的
   WebSocket 劫持失效 → 需改用 Playwright 原生事件（非页面注入，无痕迹）。
3. **昵称抓取（IndexedDB `<uid>_user`）在 Firefox 下未验证**，库名/结构可能不同。
4. 出口 `23.191.200.205` 经查为 **美国机房 IP**（`proxy=true, hosting=true`），
   **仍是风控隐患**；即使换了内核，若弹窗再现应优先换**国内家宽/住宅**出口。
5. 端到端（扫码成功 → 昵称/私信链路正常）**尚未验证**。

## 七、回退方式

配置 `DY_BROWSER_KERNEL` 设为 `chromium`（或删除该变量）即回到原内核，
无需改代码 —— 保留回退是本次接入的硬约束。
