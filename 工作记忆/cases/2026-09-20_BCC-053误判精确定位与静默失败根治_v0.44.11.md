## 1. 设计意图（Design Intent）

| 项 | 内容 |
|---|---|
| 模块职责 | 让常驻 BCC 容器**就地**在有头/无头之间切换（不另起实例、不抢 profile） |
| 设计契约 | 切换为「有头可见」后，该容器内核进程在 OS 层必须存在 `IsWindowVisible=True` 且类名为浏览器顶层窗口（Chromium=`Chrome_WidgetWin` / Camoufox=`MozillaWindowClass`）的窗口 |

## 2. 观察到的偏差

| 项 | 内容 |
|---|---|
| 偏差类型 | 上报/时序（误报）+ 可观测性（静默失败） |

## 3. 执行链追溯（自异常点向上）

```
POST /show(visible=true)
  → set_visible()                         # 无头 → 必须重建
  → _do_switch_background(headless=False)
  → _launch(headless=False)
      ├─ _wait_profile_released()         # 【缺陷③】对 Firefox 空操作
      └─ launch_async() → launch_camoufox_async() → AsyncCamoufox
  → _window_really_visible()              # 【缺陷①】PID 兜底静默失败
  → 报 BCC-053（错误）
```

## 4. 根因分析（RCA）

### ① 真因：PID 兜底「按固定进程名过滤」+ 静默吞异常
兜底用 `Get-CimInstance Win32_Process` 且条件写死 `$_.Name -eq "camoufox.exe"`。
进程名一旦不是它（AsyncCamoufox 注入的是 ms-playwright 的 firefox，且现场观测
到进程名为 `camoufox.exe` 的情形**无法稳定复现**）→ **查询恒空** → `pids` 为空
→ `return False`。异常又被 `except Exception: pass` 吞掉 → **零日志**。

> 关键判据：`_window_really_visible` 的**主路径**其实还有一条——
> `self._browser.process.pid`；但 Camoufox 返回 `BrowserContext`，`self._browser`
> 恒为 `None`，主路径直接失效，所有压力都落在那个写死进程名的兜底上。

### ② 检查时机：单次检查 + 未实测的时间假设
`_launch()` 返回后**只检查一次**。而实测「launch 返回 → 窗口真正可见」仍有
**约 12s** 时间差 → 单次检查必然误判。（原注释「冷启动 1~3 分钟」经实测**是错的**。）

### ③ 整链路缺陷：`_wait_profile_released` 对 Camoufox 是空操作
只轮询 Chromium 锁名 `SingletonLock`/`lockfile`；Camoufox 是 Firefox，锁名
`parent.lock` → 不在列表 → `if not locks: return` **立即返回**。
（且实测：Firefox 退出后 `parent.lock` **不会删除** → 即便把名字加进列表，
也只会每次白等满 timeout，是性能回归而非修复。）

## 7. 固化铁律（已并入 `工作记忆/07_BCC浏览器容器业务链.md`）

1. 外部工具/系统查询的「查不到」必须**响亮**；`except: pass` 会把机制失效伪装成否定结论。
2. 指纹内核的进程名**不可假定**，一律按 cmdline 里的 profile 稳定片段匹配。
3. **「探测不到」≠「不存在」**：取数失败必须落到第三种结果（诚实降级）。
4. 同一件事的进程判据**跨内核不通用**（Chromium 认锁文件 / Firefox 认进程退出）。
5. 等待窗口的时长上界必须**实测**；等待期必须有「切换中/冷却期」保护，否则
   探活失败 → 重启风暴 → 无头↔有头横跳 → 抖音判环境异常。
