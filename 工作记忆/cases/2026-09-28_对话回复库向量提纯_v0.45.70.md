## 一、回归设计意图（Step 1）

命中库(reply_kb)设计契约 = **命中即回、零 token** 的高优先级复用库（学习自真实成功会话）。
其 NFR：沉淀的必须是**可复用的通用知识**，而非个案记录。

## 二、实测偏差（Step 2）

对现网 81 条 auto 条目取证（`_probe_learn_quality.py`）：
- 含具体个案信息（数字/地名/伤情）问法 **20/81**；
- θ=0.82 下 **33/81 条属 14 个「同一问法」重复簇**（如「这半个月了还能改吗」4 变体）；
- 回复 ≤6 字占位 **30/81**。

**真机提纯验证**（真实 embedding + 真实 LLM，现网数据）：60 对 → 57 簇 → 达标 1 → **0 条通用候选**。
**阈值扫描**：θ=0.60~0.85 达标簇恒 1~3 且内容为「好的/好」。

## 三、链路溯源（Step 3）

`kb_maintain.run_learn_job` / `api/ai.post /replies/learn` → `reply_kb.learn_from_history`
→ 抽对（`_extract_pairs`）→ **LLM 一次性提纯** → `add_item` 逐条入正式库。
**断点在第 4 步**：无聚类、无通用性门槛、无个案剔除、无专业实质门槛。

## 四、RCA（Step 4）

「一次性提纯」把**选样问题**当成**改写问题**：指望 LLM 在改写时顺带"通用化"，
但选样未做通用性筛选 ⇒ 个案/碎片照样进库。治本是**在选样阶段**加向量聚类 +
通用性门槛，把 LLM 只用于「簇级抽象」。

## 五、修复（新增 `services/reply_purify.py`）

流水线：向量化 → 聚类 → 通用性门槛(≥N) → 剔个案 → 簇级 LLM 抽象 → 专业实质门槛 → 向量去重。
契约：不降级照搬；LLM 失败即跳过；候选落 `ai_reply_candidates` 待人工确认后升格；
参数走配置中心。移除了 `reply_kb.LEARN_PROMPT`（SSOT 归 reply_purify）。
