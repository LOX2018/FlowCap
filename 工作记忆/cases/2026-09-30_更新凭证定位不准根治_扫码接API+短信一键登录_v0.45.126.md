- **日期**：2026-09-30
- **报告人**：用户（LOX）实测报障
- **触发原话**：
  > 「目前凭证更新依旧使用未修复的二维码和短信通道，先尝试修复，如果不能就变回最初的弹出浏览器用户手动更新」
  > 「我点击的是凭证校验区域的**立即处理**按钮，以及上方的**更新凭证**按钮他都是用这个逻辑来处理的，
  >   但是现在感觉**定位是有问题的**，所以没有办法精准找到**二维码和短信登录的入口**」
- **版本**：v0.45.125 → **v0.45.126**

## 1. 报案现象

| # | 用户可见现象 |
|---|---|
| 1 | 点「更新凭证」/「立即处理验证」，两条「定位不准」：**二维码抓不到、短信登录进不去** |
| 2 | 短信「提示发送失败」或一直卡住（实际卡在更早一步） |

## 2. 排查链（Execution-Chain Traceability）

```
用户点「立即处理验证」→ POST /auto-recapture ; 点「更新凭证」→ POST /update-login(无 mode)=手动
用户（本次实际）→ POST /update-login {mode:"sms"}（显式备用路径）
   ↓
api/accounts.py  update_login()  →  sms_login()  →  _do_sms_scan()  →  login_remote.do_sms_login()
   ↓
do_sms_login  goto(LOGIN_URL) → 【直接】fill_phone('input[name="normal-input"]')
   ↓                                                            ▲
   │                                            断点①：从不调用 handle_one_click_login
   │                                            ⇒ 界面上根本没有该输入框
   └─ 实测日志：16:19:51 短信登录失败于 fill_phone: 手机号填入失败（input[name="normal-input"]）

扫码线（另一条）：
_rpa_scan_login → prepare_qr_login → grab_login_qrcode → _QR_ANCHORS[0] = "#animate_qrcode_container img"
   ↓                                                      断点②：真机 DOM 里二维码已改 SVG（image×13）
   └─ 命中 0 ⇒ 只能进慢速枚举兜底 ⇒ 大概率解不出

更上游：
```

## 4. 根因收敛

1. **界面分支未枚举** —— `do_sms_login` 假定「任何 profile 状态下都有手机号表单」；
   已记住账号的 profile 弹的是「一键登录」面板 ⇒ 100% 卡在 `fill_phone`。
2. **契约漂移（第二次复发同型病）** —— 处理函数 `handle_one_click_login` 写好了但**没接线**
   （与 H-30「`login_remote.py` 是全仓零调用孤儿模块」同型）。
3. **硬编码锚点被外部改版打废** —— 二维码 `<img>`→SVG、tab 具名→哈希类名。
4. **更优能力未接线** —— ADR-017 拍板的 API 扫码路径从未落地。

## 5. 修复（见 ADR-034 §4）

- 扫码：**优先上游 API（纯 HTTP，子进程隔离 + 文件交接）**，RPA 容器栅格化降为兜底；
- 短信：`do_sms_login` **第一步**接 `handle_one_click_login`（判据改为决定性的「登录其他账号」），
  tab 改点稳定 id；
- 凭证写盘：唯一入口 + 写前备份 + **四件套硬门禁** + 三重校验（磁盘/服务端/身份），
  不过就**还原并回落**；
- 环境：API 代理**只由账号配置显式决定**，不探测本机。

## 8. 可迁移判据

1. **「能力已实现」≠「已接线」**：文档/模块声称的能力，必须机械检出**调用点**。
2. **同名顶层包 ⇒ 只能子进程隔离**（同进程 `sys.path` 操作无解）。
3. **改版免疫的定位顺序**：确定性接口 → 稳定 id → 容器栅格化/机械解码 → 文本兜底。
4. **界面分支必须显式枚举**，否则必在某分支 100% 失败。
5. **落盘类子进程必须顶层兜底写盘**，否则失败只剩「进程消失」。
6. **凭证写盘硬门禁**：四件套不全**绝不落盘**（缺件会反派生旧签名 = 假成功）。
