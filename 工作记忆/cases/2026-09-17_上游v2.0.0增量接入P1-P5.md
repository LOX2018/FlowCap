## 三、根因与决策记录（Step 4）

### 3.1 PNG 长图：为什么不是 BCC 截图

用户明确否决浏览器方案。三条路径对比后选 **Pillow 原生绘制**：

| 方案 | 新增依赖 | 需浏览器 | 结论 |
|---|---|---|---|
| BCC 容器 `page.screenshot()` | 0 | ✅ | ❌ 用户否决 |
| Playwright 独立无头 | 有（且要装浏览器） | ✅ | ❌ 重、仍依赖浏览器 |
| **Pillow 原生绘制** | **0**（Pillow 已在 requirements） | ❌ | ✅ 选用 |

代价：排版须自实现（折行/分页/气泡定位）。故**用逐像素客观验证**替代肉眼：
- 我方气泡平均 x = 72% 宽（靠右）、对方 39%（靠左）→ 分栏正确；
- 日期标签带 7799 像素 → 日期分隔存在；
- 最右墨迹 990/1040 → 留白 49px，未贴边裁切；
- 墨迹采样 22033 点 → 字形确实渲染（非空白/方框）。

### 3.2 合并转发风控评估（接入前先探）

上游注释明确「never copies browser cookies to a different domain」「Never send
login cookies to the CDN」→ 与铁律 §一·2（复用带凭证的浏览器本身）**一致**：
- 取资源链接：在**已登录页面上下文**发同域 POST（复用登录态）；
- 下载资源：**不看 cookie**，只用 CDN 签名 URL，且**域名白名单**。

### 3.3 ★ 13600 契约订正（本项目最值得记住的一条）

**发现**：我方 `conversation_capture.py` 注释称「上游 getProfileCard 用 aweType=13600」，
据此把 `13600` 归类为**名片**。

**上游源码逐字核对**（`frontend/src/lib/douyinMessage.js`）：
```js
export function getForwardInfo(msg) {
  const cj = getContentJson(msg) || tryParseJson(msg.content)
  if (String(cj?.aweType) !== '13600') return null      // ← 13600 = 合并转发
  ...
}
export function getProfileCard(msg) {
  const cj = getContentJson(msg) || tryParseJson(msg.content)
  if (!cj || !cj.name || !(cj.secUID || cj.sec_uid ||
      (cj.uid && cj.source === 'others_homepage'))) return null   // ← 与 13600 无关
  ...
}
```
→ 原注释**不成立**；13600 是**合并转发**，名片另有判据。

**处置**：按 Iron Law 5（契约即架构，改动须走评审）——
1. 实现改为「13600 → 聊天记录」，名片改用上游同款判据；
2. 回归暴露 `test_upstream_p1.test_profile_card` 固化了错误契约 → **订正该断言**
   （并新增「名片走上游判据」断言），而非迁就旧测试；
3. 同步写回代码注释，注明订正依据与出处。

## 五、可复用教训（跨任务）

1. **对照上游必须先取全量版本再下结论**：只读最新 tag 会把历史债误判为增量。
2. **「跑通不报错」不是验证**：CENC 要逐样本比对、PNG 要逐像素判定、
   脱敏要断言真实密钥串不出现。
3. **测试夹具本身要能被证伪**：夹具与真实文件不同构时，会同时掩盖实现错误。
4. **旧测试可能固化错误契约**：契约订正时回归失败要区分「我改坏了」与
   「旧断言写错了」，后者应改测试并写明依据。
5. **导出/迁移类功能默认必须脱敏**，且 sqlite 物理复制要显式开关 ——
   否则用户会以为导出的是干净数据。
6. **`backup()` 的源连接要用独立只读连接**：应用连接可能持有写事务 → 等锁挂死。
