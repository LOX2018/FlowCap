# 实测 · API 扫码「65 秒短 TTL」—— 身份同源化三组对照（v0.45.147 续）

- **日期**：2026-10-01 04:10–04:25
- **分支**：`design/better-douyin`
- **账号**：四川工伤张老师（design 根 `C:\temp\dyautodm_design`）
- **结论一句话**：**65 秒与「身份指纹」无关，是 `login.douyin.com` 对「非浏览器会话」的固定 TTL。**

---

## 一、为什么要做这组实验

用户提出：「既然合成指纹转 C++ 指纹有冲突暴露风险，那为什么不用 C++ 指纹去拉取 API，
然后再重新注入浏览器」。该思路方向正确（避免跨身份自曝），**但需实测它是否就是 65 秒的成因**。

## 二、实验设计（三组对照，全自动化）

| 组 | 配置 | 目的 |
|---|---|---|
| A 基线 | 默认 `DY_HTTP_IMPERSONATE` 未设 ⇒ chrome150 TLS + Chrome UA | 已知 65s |
| B | `DY_HTTP_IMPERSONATE=firefox147`（TLS 换 Firefox） | TLS 同源化是否有效 |
| **C（用户方案）** | firefox147 TLS **+ 真实 C++ 指纹**（fpk1 88 / ttwid 127 / s_v_web_id 52 / msToken 176） | 双同源是否有效 |

真实指纹来源：无头 Camoufox（C++ 层指纹注入）打开 `https://www.douyin.com/` 后读 `ctx.cookies()`；
浏览器 UA 实测为 `Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:152.0) Gecko/20100101 Firefox/152.0`。

## 三、结果（三组**全部精确 65 秒**）

| 组 | 出码 | 码寿命 |
|---|---|---|
| A 基线（Chrome） | 3.0s | **65s** |
| B TLS→firefox147 | 3.0s | **65s** |
| **C firefox147 + 真实 C++ 指纹** | 3.0s | **65s** |

⇒ **零差异**，用户方案未改善。

## 四、至此被排除的候选成因（累计 4 项）

| # | 候选成因 | 证据 | 状态 |
|---|---|---|---|
| 1 | 缺 fpk1 | fpk1 属 `WWW_ONLY_COOKIES`（上游 login_api.py:56-58），**到不了 login.douyin.com 的 get_qrcode** | ❌ 协议层否证 |
| 2 | 灌注真实 fpk1 可改善 | 对照 65.013s vs 65.013s | ❌ 实测否证 |
| 3 | TLS 指纹不匹配（Chrome vs Firefox） | `DY_HTTP_IMPERSONATE=firefox147` ⇒ 仍 65s | ❌ 实测否证 |
| 4 | 跨身份自曝（合成+真实混用） | C 组双同源 ⇒ 仍 65s | ❌ 实测否证 |
| — | 限频/拦截 | 全程 `poll_err=None` | ❌ 否证 |

## 五、结论

**65 秒是 `login.douyin.com` 对「非浏览器会话」下发的固定 TTL**
—— 由**调用方式**（裸调接口、无页面上下文）决定，而非调用**身份**决定。

这与用户更早的推断一致：「抖音应该不会专门做一个空场景 API 用于登录」
⇒ 该接口本应在浏览器页面内被调用；被裸调后，服务端照发码但压短生命周期。

## 六、处置（迭代止损）

同一故障点已试 5 轮（默认优先 → 灌注 → 归因证伪 → TLS 同源 → 双同源）均无效，**停止该方向**，
**不建「指纹捕获/灌注」模块**（上游情报评级 `need-new-module`，工作量大且已被证伪为无用）。

保留结论：
- API 通道**仅可用于「快速出码」**，不足以完成登录；
- 默认维持**接口桥**（无头 Camoufox，码由页面自发生成 ⇒ 正常生命周期）；
- API 保持 `DY_LOGIN_QR_BACKEND=api` 显式可选，供后续实验。

## 七、真正剩下的堵点

**接口桥的「扫码 → confirmed → 凭证落盘」全流程仍未真机验证** —— 需用户用抖音 App 扫一次码。
这是当前唯一未闭环项，也是决定是否可交付的关键。

## 八、教训

- **正确的原则不等于正确的归因**：「避免跨身份自曝」是对的，但它不是 65 秒的成因。
  原则正确 ≠ 该处就是病灶，必须做对照。
- **五轮否证也是成果**：它把 API 通道的价值边界钉死了（只能快出码），
  避免未来反复投入。
- 判据要能**证伪**：本轮三组全是 65s ⇒ 强证伪；若只对一组做实验就会误判。
