## 3. 故障链（Source → Propagation → Terminal）

### Source：上游 `camoufox` 0.5.6 的自毁分支

`camoufox/pkgman.py:811`（`camoufox_path()` 内）：

```python
if os.path.exists(INSTALL_DIR) and os.listdir(INSTALL_DIR) and not COMPAT_FLAG.exists():
    rprint("Cleaning old data...", fg="yellow")
    shutil.rmtree(INSTALL_DIR)
```

而 `.0.5_FLAG`（`COMPAT_FLAG`）**只在 fetch 成功落盘后**才 `touch()`
（`multiversion.py:453`）。⇒ **「内核未装 / 装失败」时该清理分支会把整个安装目录删掉。**

实机读数（Python314 + 打包态同版 0.5.6）：

```
INSTALL_DIR = C:\Users\LOX\AppData\Local\camoufox\camoufox\Cache
listdir     = ['browsers']            # 非空
COMPAT_FLAG.exists() = False          # flag 缺失
⇒ rmtree 触发条件 = True
```

### Propagation

```
should_use_vb(cfg)
  └─ from camoufox.pkgman import installed_verstr     (vbrowser.py:1177)
       └─ CamoufoxNotInstalled("official/stable is not installed...")
            └─ RuntimeError("[BCC-070] ...")
                 └─ _launch() 抛出（无专项熔断分支）
                      └─ _ensure_alive(): 只判「env_path 为空」为致命态（BCC-051）
                           ⇒ 走普通自愈 → await self._launch(headless=self._headless)
                                └─ WP 通道 3s 轮询 → 无限重建
```

### Terminal

- BCC 容器起不来：`[BCC-028] 浏览器容器启动失败`
- 对外：`POST /show{visible:true}` 无 context 可用 ⇒ **「无法有头启动」**
- 日志实测：**BCC-006 × 136 / BCC-070 × 138 / BCC-043 熔断 × 0**
- 风暴分布：15:02→21 次、15:03→19、15:06→26（**3.05s 一轮**）

## 4. 第二根因：`nul` 残留文件让 fetch 连第 0 步都跑不动

用户此前在 **git-bash** 里用 `dir ... > nul` 记录探测输出 —— 在 POSIX 语义下 `nul`
不是设备名，于是生成真实文件：

```
C:\Users\LOX\AppData\Local\camoufox\camoufox\Cache\browsers\official\nul   (137 B)
C:\temp\dyautodm_design\nul                                                (同源)
```

后果：`fetch` CLI 的清理分支（`__main__.py:257`，同一 rmtree）在 `os.unlink` 处崩：

```
OSError: [WinError 87] 参数错误。: '...\official\nul'
⇒ fetch 退出码=1，第 0 步即中止（HC-12 交接卡把阻塞归因于 403，漏掉了这个更硬的阻塞）
```

**为什么 Win32 侧删不掉它**（实测矩阵）：

| 手段 | 结果 | 原因 |
|---|---|---|
| Python `os.unlink` | ✗ WinError 87 | 路径被 Win32 解析成 **NUL 设备** |
| Python `os.rename` | ✗ WinError 87 | 同上；`os.stat` 返回字符设备 `0o20000`（非普通文件） |
| PowerShell `[IO.File]::Delete('\\?\…')` | ✗ Test-Path=False | `\\?\` 仍不把 `nul` 当普通名解析 |
| **MSYS `rm -f`** | ✓ **成功** | 走 POSIX 语义，**不被 NUL 设备名劫持** |

⇒ **创建者与清除者是同一工具集的盲区**：git-bash 造出来的 `nul`，只有 git-bash 能删。

## 5. 修复

### 5.1 运行时恢复（本轮实做）

```bash
# 1) 用 MSYS rm 清掉 nul（Win32 API 全部无效）
rm -f "C:/Users/LOX/AppData/Local/camoufox/camoufox/Cache/browsers/official/nul"
# 2) 带 token + 走代理 fetch（匿名 GitHub API 限额已耗尽：limit=60 remaining=0）
export GITHUB_TOKEN=<profile .env>          # 值绝不落日志，只报长度
export HTTPS_PROXY=http://127.0.0.1:10808
python -m camoufox fetch                    # → v152.0.4-beta.30，493MB @ 13.4MB/s
# 3) 校验 flag 与版本
ls .../Cache/.0.5_FLAG                      # 必须存在
python -c "from camoufox.pkgman import installed_verstr; print(installed_verstr())"
```

**关键**：`fetch` 自带 `GITHUB_TOKEN` 支持（`pkgman.py:79/712`），
但**GUI sidecar 不继承 shell 环境** ⇒ 必须显式注入；否则撞匿名限额（403）。

### 🔴 本次踩到的执行位置陷阱（**通用教训**）

首轮有头验证**失败**：`exitCode=3221225477`（ACCESS_VIOLATION）+ GPU 进程 3 次失败。

**真因不是项目缺陷，而是我的执行位置**：Hermes 的 shell 在 **Session 0（services，非交互）**，
而用户桌面是 **Session 1（console）**。**非交互会话物理上无法渲染窗口。**

判据（实测读数）：

```
powershell PID=12592 SessionId=0
query session:  services(0,断开) / console LOX(1,运行中)
```

**正解**：用计划任务把探针投到交互会话 ——
`schtasks /Create /RU LOX /IT` → `schtasks /Run`，结果落盘再回读。
投过去后**一次通过**（`MozillaWindowClass` 可见窗口 5.6s）。

⇒ **凡「有头/窗口/可见性」类验证，先确认执行会话号；Session 0 的失败不算证据。**

## 7. 沉淀的规则（防复发）

1. **不可自愈的外部依赖缺失必须与「凭证不可用」同级熔断**，不得走普通自愈重试
   （迭代止损律：同一故障点连续两轮无效即须停手，禁止无限重建）。
2. **内核类依赖要有巡检前置项**：gitignored、不进 CI、无 sha256 门禁的外部资产，
   只能靠运行时才发现 —— 必须在能力探针里先报。
3. **不要在 git-bash 里用 `> nul` 记日志**；用真实文件名。已产生的 `nul` 只有 MSYS `rm` 能删。
4. **fetch 类工具需显式带 `GITHUB_TOKEN` 并走代理**（GUI sidecar 不继承 shell 环境）。
5. **冻结契约（`CAPABILITY_ORDER`）不得为新增观察项扩员**：非业务域检查按既有先例
   折进巡检（同 D4 `contract_check` 模式）。
6. **有头类验证必须先确认执行会话号**（见 §6 陷阱）。
