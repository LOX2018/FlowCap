# H-30 接线：RPA 登录模块从「孤儿」接入 /scan（v0.45.37）

- 日期：2026-09-26
- 版本：`v0.45.36` → `v0.45.37`
- 关联：ADR-017（§8 实施收口）、H-30
- 性质：架构级缺口修复 —— **能力已实施但未接线到产品**

---

## 1. 设计意图（Design Intent）

**模块**：`/api/accounts/{name}/scan`（扫码登录入口）。

**设计契约（SoC + 能力协商）**：
- 浏览器 RPA 操作全部委托 `auto_dm/login_remote.py`（能力层，v0.45.14~18 实施）
- 凭证落盘全部委托 `auth_helper.save_cookie_to_env`（**禁止自造写盘**，ADR-017 §8.3）
- API 层只做：编排（async→sync 桥接）+ 状态回写 + **失败回落**

**预期行为**：`/scan` 优先走 RPA（真浏览器 + 二维码可推送 + 官方接口硬判据探活）；
RPA 不可用/失败 ⇒ 回落老 `enrich_auth(force=True)`，**产品能力不退化**。

---

## 2. 实测偏差（Observed Deviation）

**偏差类型**：架构缺口（wiring gap，非 crash）

**偏差点**：`api/accounts.py::_do_scan` 与 `auto_dm/login_remote.py` 之间**无调用边**。

**实机读数**：
```
grep -rn "login_remote" --include=*.py .
⇒ 排除 login_remote.py 自身与 login_api_vendor.py 的 4 处注释后，命中 0
```

**偏离预期**：
- `login_remote.py`（936 行、12 个能力函数、v0.45.14~18 五个提交）
  是**全仓零调用的孤儿模块** ⇒ H-30 的核心能力**从未到达产品**。
- `/scan` 仍走老的 `enrich_auth(force=True)` 弹窗扫码（需人在电脑前）。
- `login_remote.py:40` 注释写着「凭证经 `login_capture` 判非污染态（**由调用方校验**）」
  —— 而**调用方根本不存在**，该契约无人履行。

---

## 3. 根因（RCA）

- **实施期只交付了能力层，未交付接线层**：v0.45.14~18 五个提交全部落在
  `auto_dm/login_remote.py`（能力），API 入口 `api/accounts.py` 一次未改。
- ADR-017 §8 归档的是**能力与实测判据**，未包含「接线」这一验收项
  （F1~F10 里没有一条是「能力已被产品调用」）。
  ⇒ **验收判据本身的缺口**，导致孤儿状态被 5 个提交的绿灯掩盖。

---

## 4. 处置（Fix）

**在 `api/accounts.py` 新增接线层**（能力层 `login_remote.py` **一行未改**）：

1. **新增 `_rpa_scan_login(name, env_path, st) -> bool`**
   - `asyncio.run(prepare_qr_login(...))` 出码 → `st["qrPng"]` 回传前端
   - `asyncio.run(poll_qr_scanned(handle, 240s))` 等扫码（硬判据：cookie 出现 sessionid/sid_tt）
   - 凭证经 `save_cookie_to_env(cookie_str, env_path)` 落盘（**复用既有入口**）
   - `finally` 必调 `close_handle` —— 否则 profile 长期占用（ADR-017 §8.5，实测卡 180s）
   - **失败不抛异常**，返回 False 由调用方决定回落

2. **`_do_scan` 改为能力协商**
   - 先试 RPA；失败/异常 ⇒ 回落 `enrich_auth`（**老逻辑一行未改**）
   - `st["path"]` 记录实际路径（`rpa` / `legacy`），便于归因

3. **`/scan-status` 增加 `qrPng` / `decoded` / `path` 字段**
   - RPA 有二维码图可展示；老路径为空串（前端按此判有无）
