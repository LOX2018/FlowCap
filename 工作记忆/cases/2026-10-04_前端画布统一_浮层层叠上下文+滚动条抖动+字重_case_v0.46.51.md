# 前端画布统一与浮层层叠上下文根治（三条 UI 报障）_case_v0.46.51

> 日期：2026-10-04　版本：v0.46.51（debug）　提交：待补
> 触发：用户三条报障 ——
> ① 「前端页面画布没有统一吗，查阅模式、视频播放采集页面会导致画面溢出」
> ② 「配置中心每一个页面的显示区宽度不一致，切换 Tab 会导致画面跳脱」
> ③ 「配置中心的 IM 页面和其他 tab 页面字体大小、型号都不一致」

---

## 一、诉求①：查阅模式 / 播放页「画面溢出」——根因是**层叠上下文吞掉 fixed 浮层**

### 表象
用户截图（红框标注）显示：查阅模式下「评论查阅模式」标题、首个筛选片、表格「时间」列**左侧被切**，
看起来像「内容溢出/画布没统一」。

### 真根因（代码真值，非推测）
```
app-shell.tsx:52   <div className="relative z-10 flex min-w-0 flex-1 flex-col">   ← 创建层叠上下文
sidebar.tsx:98     <aside className="relative z-20 ...">                          ← 另一个层叠上下文
live-page.tsx:1423 <ReviewMode />  渲染在 <PageContainer> 内，未走 Portal
```
`ReviewMode` 的 `z-[var(--z-view)]`=120 **被困在 z-10 的层叠上下文内部**，
永远无法超越兄弟节点 sidebar 的 `z-20`。虽然 `fixed inset-0` 让它铺满视口，
但**左侧 144px 被侧栏盖住** ⇒ 标题首字/首列被遮 = 用户看到的「溢出」。

### 修法
`LiveReviewMode.tsx` 改用 `createPortal(..., document.body)`，把浮层移出 z-10 上下文。
项目里 `modal.tsx` / `CrawlFloatingPanel.tsx` **本来就是** Portal，唯独这个全屏浮层漏了。

### 关键判据（可机械化）
- `overlay.parentElement === document.body`（Portal 生效）
- **`document.elementFromPoint(侧栏中心) !== aside`**（浮层在侧栏之上）← 决定性判据

### 一类缺陷扫描（同一根因，不是一处）
全站 `fixed inset-0` 全屏浮层共 13 处，其中 **10 处**渲染在 `z-10` 内容区内且未走 Portal：

| 文件 | z 层 | 修复 |
|---|---|---|
| `live/LiveReviewMode.tsx` | z-view=120 | ✅ Portal |
| `accounts/AccountReview.tsx` | z-view=120 | ✅ Portal |
| `platform/platform-page.tsx`（player overlay） | z-view=120 | ✅ Portal |
| `accounts/AccountDrawer.tsx` | z-drawer=130 | ✅ Portal |
| `accounts/ProxyDrawer.tsx` | z-drawer=130 | ✅ Portal |
| `crawl/crawl-page.tsx`（评论抽屉） | z-drawer=130 | ✅ Portal |
| `live/RoomConfigPage.tsx` | z-modal | ✅ Portal |
| `live/RoomManagePage.tsx` | z-modal | ✅ Portal |
| `messages/message-viewer.tsx` | z-modal | ✅ Portal |
| `ui/modal.tsx` / `crawl/CrawlFloatingPanel.tsx` | z-modal | 原本已是 Portal |

`App.tsx:479`（verBlock 阻断页，AppShell 未挂载）与 `ui/dialog.tsx`（Radix 自带 Portal）**无需改**。

### 教训（判据不统一导致返工）
初判时误用「这个文件里还有没有别的浮层」作为要不要修的依据，
导致 crawl-page 上**三次反复**（修→跳过→再修）。
**正确判据只有一个**：浮层的**祖先链里有没有层叠上下文制造者**（`z-index` + `position` / `transform` / `filter` / `backdrop-filter` / `isolation`）。
与「同文件有无其它浮层」无关。

## 二、诉求②：配置中心切 Tab「画面跳脱」——根因是**滚动条槽位宽度抖动**

### 真根因
`main` 是唯一纵向滚动容器（`app-shell.tsx:66` `min-h-0 flex-1 overflow-y-auto`）。
- 内容矮的 tab（通用配置）**不出**滚动条
- 内容高的 tab（AI / 通知 / MCP）**出** 5px 滚动条
⇒ 内容区可用宽在两 tab 间相差 5px ⇒ `PageContainer` 的 `mx-auto` 居中位置随之偏移 2.5px
⇒ 观感「切一下 Tab 画面横向跳一下」。

### 修法
`tokens.css` 给 `main` 加 `scrollbar-gutter: stable`（槽位恒预留，不改变视觉风格）。
**作用域限定 `main`** —— 全局加会让所有滚动容器（侧栏 nav / 抽屉 / 表格）都预留槽位，
在窄容器里反而吃掉有效宽度。

### 关键判据
切各 tab，`main.clientWidth` 极差 = 0、`PageContainer.x` 极差 = 0、`Card.x/w` 极差 = 0。

## 三、诉求③：IM 页「字体大小、型号不一致」——根因是**`<strong>` + `font-weight:bolder` 相对计算**

### 真根因
Tailwind preflight 有 `strong{font-weight:bolder}` —— **`bolder` 是相对值**。
`SetCardHead` 的标题容器已是 `font-semibold`(600)，其内部的 `<strong>` 计算为
`bolder(600)` = **900**；而其它 tab 的标题是纯文本 → 保持 600。
⇒ IM 页卡片标题 900 vs 其它 tab 600 = 「型号不一致」。

同页还有**第二套设计体系**残留（`notify-widgets.tsx` 的 Card/Field 是旧 CSS 时代私有实现，
内联 `borderRadius:10` / `fontSize:12`；且 `Field` 的 `className="inp"` 指向 v0.43.16
已删除的类 ⇒ 输入框退化为浏览器默认样式）。该部分已于早前收敛为转调 `SetCard` 族。

### 修法（本次）
去掉卡片 title 里多余的 `<strong>` 包裹（容器已 semibold，无需再加粗）：
- `AuthorizationCard.tsx:50` `<strong>远程操作授权</strong>` → `远程操作授权`
- `NotifySection.tsx:208` `<strong>启用通知</strong>` → `启用通知`
- `NotifySection.tsx:283` `<strong>{title}</strong>` → `{title}`

### 关键判据
真实浏览器扫各 tab 的 `font-weight>=600` 元素：**`fw=900` 计数 = 0**（修复前 5 处）。

### 一类缺陷扫描（区分两种用法）
全站 `<strong>` 共 16 处，其中**卡片标题内**的只有 3 处（缺陷，已修）；
其余 13 处是**正文行内强调**（`<b>`/`<strong>` 在段落里），父级非 `font-semibold`
⇒ `bolder` 解析为 700（合理），**保留不动**。
