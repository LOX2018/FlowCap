## 一、缺陷 ①：扫码后无回执（**跨事件循环 + GC 回收**，双因）

### 现象
用户扫码成功，但程序未在等待 ⇒ 无回执、凭证不落盘。

### 根因链（实测取证）

| 层次 | 缺陷 | 证据 |
|---|---|---|
| **A** | 出码与等待是**两次独立 `asyncio.run`** ⇒ Camoufox context 的传输随前一个事件循环销毁而关闭 | 首轮探针：出码后 **0s** 即 `'NoneType' object has no attribute 'send'` |
| **B** | 即使同循环，`AsyncCamoufox`（PlaywrightContextManager）被挂到 `context.__dict__["_camoufox_ctx_mgr"]` 后**无强引用** ⇒ 等待用户扫码期间被 **GC 回收** ⇒ 触发其 `__aexit__` ⇒ context 关闭 | 同循环但无强引用：稳定 **40s** → t+45s `TargetClosedError` |

### 对照实验（决定性）

| 写法 | 存活 |
|---|---|
| 跨 `asyncio.run` | **0s** 断 |
| 同循环、无强引用 | **40s** 断 |
| **同循环 + 模块级强引用** | **150s 稳定** ✅ |

### 修复
| 文件 | 改动 |
|---|---|
| `vbrowser_camoufox.py` | 新增 `_CAMOUFOX_KEEP` 池 + `_keep_camoufox_alive()` / `_release_camoufox()`；**在 context 创建点统一登记**（全路径生效：桥/短信/截图兜底） |
| `auto_dm/login_remote.py` | 新增组合协程 `bridge_qr_login_and_wait()`（出码 + 等待同循环）；删除该模块内重复的强引用池（避免两处实现漂移） |
| `api/accounts.py` | `_rpa_scan_login` 改为**单次** `asyncio.run(_lr.bridge_qr_login_and_wait(...))` |

### 修复后实测
```
出码 ok=True via=bridge png=True
等待 124.6s 全程稳定，正常超时（status=new，无人扫码）
断连迹象：0 次   ✅
```

## 二、缺陷 ②：短信登录死锁（**同步阻塞事件循环**）

### 根因（代码事实，两文件对读得出）
| 位置 | 事实 |
|---|---|
| `api/accounts.py` `_make_code_provider` | provider 是**同步函数**，内部 `ev.wait(timeout=300)` **阻塞** |
| `auto_dm/login_remote.py` `do_sms_login` L1578 | 在 **async 协程里直接调用** `code_provider()` |

⇒ 同步阻塞**整个事件循环 300s** ⇒
1. Playwright 传输停摆 ⇒ 页面卡死、context 被关；
2. **同一循环上的 `/sms-code` 端点无法被调度** ⇒ 用户提交的验证码**永远送不进来**（死锁）；
3. 现象：**点「更新凭证」疯狂转圈 30–50s，最终拉有头浏览器**。

### 修复
```python
if inspect.iscoroutinefunction(code_provider):
    code = await code_provider()
else:
    code = await asyncio.to_thread(code_provider)   # ★ 同步 provider 放 worker 线程
```
（async provider 语义不变；判据由 `inspect` 决定，不改行为契约。）

### 修复后实测
```
provider 阻塞 6.0s 期间，心跳正常 12 次（期望 12）
★ 事件循环未被阻塞 ✅
```

## 三、同类缺陷全仓扫描（修一类，而非一处）

用 AST 扫描「async def 内的同步阻塞调用」：
- `time.sleep` 命中 5 处 ⇒ **全部在同步函数/子线程内**（无害）✅
- `join/wait` 命中 27 处 ⇒ 剔除 `os.path.join` / `"".join` 误报后，剩
  `core/auto_dm.py:960`、`core/dispatch.py:399` ⇒ **均为 `asyncio.Event.wait()`**（返回协程、被 `asyncio.wait_for` 包裹）⇒ 误报 ✅
- **真实阻塞缺陷仅 `code_provider` 一处，已修**

## 五、教训

1. **「正确的原则」不等于「正确的归因」**：API 短 TTL 与指纹无关（另案已证伪），
   而本次的「无回执」真因是**事件循环/GC 生命周期**，与抖音无关。
2. **同一类缺陷要一次扫完**：`code_provider` 的阻塞与桥的跨循环，本质都是
   「**异步边界处理错误**」——一个在调用侧、一个在等待侧。孤立看会漏。
3. **对照实验不可省**：0s / 40s / 150s 三档差异，直接锁定 GC 一层；
   若只试一种写法就会误判为「Camoufox 不支持长等待」。
4. **强引用必须配对释放**：`_keep` 与 `_release` 成对，防内存泄漏。
