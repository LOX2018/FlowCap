## 一、最终结论速览

| # | 现象 | 真根因 | 修法 | 实测证据 |
|---|---|---|---|---|
| 1 | 取址只拿到 CDN 直链 → 403 | `play_addr.url_list` 前两位是**会话签名直链**（`tk=webid`/`signature`/`policy`），绑定取址会话，脱离即 403 | 优先选**无签名入口** `/aweme/v1/play/?video_id=`，跟随 302 取真实地址 | 302 → 200 / `video/mp4` / 49,821,029 字节 / `ftyp isom` |
| 2 | 拿到真实地址**仍播不了** | Tauri webview 里 `<video src="CDN">` 是**跨域请求**，受 CORS/Referer 约束 —— 与 Python 侧能否 200 **是两件事** | 方案 B：后端反向代理流（`/media/stream`），前端只请求本机同源 | HTTP **206** + `content-range bytes 0-2047/99025030` + 2048 字节真实 MP4 |
| 3 | 合集内作品恒 0 条 | 接错接口：用了**短剧专用** `get_series_aweme`（`series_id`），普通合集需 `/aweme/v1/web/mix/aweme/`（`mix_id`） | 新增 `get_mix_aweme` 并按 `is_serial_mix` 分流 | **15 条**真实作品，`status_code: 0` |
| 4 | `mix/aweme` 仍 403 | 该接口在 **secsdk webSign 保护清单**内，**缺 `x-secsdk-web-signature`** | 移植上游 `secsdk_web_sign.py` + `Params.signed_url()` | 签名后 `status_code: 0` |
| 5 | 收藏夹恒空 | 账号**没有收藏夹文件夹**（实测 0 个），但收藏作品有 19 条 | 新增 `/favorite` 端点直接取收藏作品；前端不再要求文件夹 | **19 条**，`status_code: 0` |
| 6 | 粉丝/关注「拿不到」 | **接口本身可用**，是前端此前没有入口 | 前端接 `relationList` | **5 条**真实 follower |

**最关键的两次认知翻转**：
- ①「Python 侧 200」≠「浏览器可播」——跨域是独立的一层，方案 A 不够。
- ② 403 不是参数错、不是 UA/Referer/cookie/IPv6，而是**缺一类专门签名**。

## 三、踩过的坑（供后人避让）

### 1. HEAD 探测会**谎报**（最危险的一条）
`resolve_playable` 初版用 `requests.head()` 探测地址可用性 ——
抖音 CDN **对 HEAD 与 GET 校验不一致**：HEAD 返 200，**同一 URL 的 GET 返 403**。
实测 6 个作品里 **3 个因此被误判为"已解析可播"**。

⇒ **必须用与播放器同方法（GET）探测**，`Range: bytes=0-0` 只取 1 字节省流量。
这正是「修误报时不能用谎报换误报」的实例。

### 2. 告警判据按 host 判断 = 把成功报成失败
初版判断"解析结果 host 是 `douyinvod.com` 就告警 CDN 会 403" ——
但**解析成功后的真实流 host 同样是 `douyinvod.com`**，导致 6 条成功日志全被标红。
改为按 `how == "passthrough"`（**解析是否生效**）判断。

### 3. `download` 档是音频不是视频
`pick_quality` 降级链末尾的 `download` 档，对**图集作品**是 `.mp3`。
降级到它会返回一个"能 200 但播不了"的地址。
⇒ 视频降级链**排除 `download` 档**，仅在无任何视频档时才兜底。

### 4. 收藏夹 ≠ 收藏
`get_collect_list`（文件夹）与 `get_user_favorite`（收藏作品）是**两个不同接口**。
账号可以"0 个文件夹 + 19 条收藏"。UI 不该强迫用户先建文件夹。

### 5. 测试被自己的注释绊倒
`test_frontend_login_gate.py` 检查门控段不得引用 `ready`，
而门控段**注释里**写着「**不得引用 ready**：它需要登录」→ 假红。
⇒ 断言前必须**剥离注释**，只看代码。

## 六·补 流缓存（用户追加要求，2026-09-21）

用户：**「流代理缓存保留 30 分钟」**。

实现：`api/platform.py` 内存 LRU（`_cache_get` / `_cache_put` / `stream_cache_stats`）。

| 项 | 值 | 理由 |
|---|---|---|
| TTL | **1800s（30 分钟）** | 用户指定 |
| key | `(target_url, range_spec)` | 按片段分键；拖进度条会重复请求同一片段 |
| 上限 | 64MB / 200 条 | 防内存撑爆（单作品可达 400MB，实测 401,673,127 字节）|
| 落盘？ | **否** | 整片落盘会撑爆磁盘；只缓存 ≤8MB 的 Range 片段 |
| 无 Range 整片 | 边收边转，不入内存 | 否则一次播放就打满内存 |

实测：首次 `MISS`（1MB 片段）→ 重复同 Range **`HIT` 4ms**（内容逐字节一致）→
不同 Range `MISS`（分键语义正确）；`stats.stream_cache` 暴露 items/bytes/ttl 供观测。

**明确不做**：清晰度切换（用户 2026-09-21 明示「不需要」，保持死状态）。
