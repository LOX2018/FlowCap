# 案例：双击部署副本登录 401 —— 数据根误解析为空根（v0.45.106）

> 归档时间：2026-09-29 ｜ 版本：v0.45.105 → v0.45.106 ｜ 类型：缺陷（误导性失败）｜ 严重度：error（阻塞使用）

## 一、症状（用户原话）

> 「为什么登录门禁的账号 LOX2018 和密码 LOX2018 登录不进去了」

表现：会员门禁（MemberGate）输入 `LOX2018 / LOX2018` 始终失败，提示**「用户名或口令错误」**。
误导点：用户会以为**口令错了**，实际口令完全正确。

## 二、取证链（先证据，后结论；三项硬证据）

| # | 判据 | 实测结果 |
|---|---|---|
| 1 | 口令哈希比对（用注册表 salt 独立做 PBKDF2-600k，**只输出布尔**） | **MATCH 'LOX2018'**（`registry.json` iterations=600000）|
| 2 | 活体接口 `POST http://127.0.0.1:8000/api/member/login {LOX2018,LOX2018}` | **HTTP 401 `{"detail":"用户名或口令错误"}`** |
| 3 | 运行进程命令行 | `dyautodm-backend.exe --port 8000` —— **无 `DY_APP_ROOT`**；父进程 = 桌面端 exe（非脚本） |

矛盾：**哈希匹配**却 **401** ⇒ 后端读的**不是**那份注册表。

补充取证：
- `%LOCALAPPDATA%\DYAutoDM\` **存在**，创建时间 **22:46**（正是本次启动），其 `members\` **为空**（无 registry.json）、`data\dyautodm.db` 为新建空库。
- 正确根 `C:\temp\dyautodm_design\members\registry.json` 含 LOX2018；`.session.json`（token，age 0.52h < 12h TTL）**仍有效**却**未被恢复**。
- `logs/run_20260929_220916.log`（22:21，经 `dev.ps1`/`start_dev.ps1` 启动）有「**登录成功**」；本次启动日志只有「未登录：启动预对齐」，**无**恢复/失败行。

## 三、根因（执行链，非终末症状）

```
桌面端 exe 被**直接双击**（父进程非脚本；sidecar 无 DY_APP_ROOT）
   → vbrowser.app_root() 走 frozen 分支
   → 落到 _default_data_root() = %LOCALAPPDATA%\DYAutoDM（空根）
   → member_store._load_registry(): 文件不存在 → 返回空表（**不写日志**）
   → authenticate(): 找不到 username → 401「用户名或口令错误」  ← 表面症状
```

`app_root()` 的 frozen 默认根是**安装版**（MSI/NSIS，可能装到只读 Program Files）的正确语义；
但 `deploy.py` 产出的**测试副本**是「双击即用」的，一旦启动器未注入 `DY_APP_ROOT`，
同一解析即落到空根。**判据取决于「进程环境里恰好有没有变量」——违反显式配置原则。**

## 四、修复（方案②，用户拍板：副本自描述）

1. `backend/vbrowser.py`：新增 `_deploy_declared_root()`，解析顺序变为
   **`DY_APP_ROOT` > 副本声明（exe 同目录 `dyautodm_app_root.txt`）> 安装版默认根 > 源码根**；
   声明目录**不存在**时回退默认根（**不静默迁根**）。
2. `scripts/deploy.py`：部署成功后写 ①`dyautodm_app_root.txt`（单行数据根绝对路径）
   ②`启动.cmd`（显式 `set DY_APP_ROOT=%~dp0.`）。
3. **为什么不做「frozen 无 `DY_APP_ROOT` 就 fail-loud」**：会**误伤真正的安装版**
   （它本就该用默认根、也没有该变量）。判据因此是「副本是否**声明**了数据根」，
   而非「变量是否缺席」。

## 五、验证（可证伪，非「编译通过」）

`python scripts/verify_app_root_resolution.py` → **PASS=5 FAIL=0**：
- P1 frozen+声明(存在) → 声明目录（**修复生效**）
- P2 `DY_APP_ROOT` 优先于声明
- N1 frozen+**无**声明 → 默认根（**复现原缺陷**）
- N2 声明失真（目录不存在）→ 回退默认（不迁根）
- **C1 负控**：打桩禁用修复 ⇒ P1 场景变红（判据跟着修复走，非恒绿）

机械门禁 **R14**（`check_iron_rules.py`）：声明文件名与 SSOT（`vbrowser._DEPLOY_ROOT_MARKER`）
一致；`--selftest` 注入不一致样本必报红。

## 六、教训（可迁移）

1. **同一文案覆盖多个失败原因时，不能据文案定因**：401「用户名或口令错误」同时覆盖
   「用户名不存在」。必须取**独立证据**（哈希比对、注册表文件事实、数据根时间戳）。
2. **「口令错」类投诉先验口令本身**：一次 PBKDF2 比对即可排除/坐实，成本极低，
   却能避免整轮错误的排查方向。
3. **数据/配置落点必须可解释**：凡是「取决于进程环境里有没有某个变量」的行为，
   都要问「变量缺席时会发生什么、用户能否看见」。此处缺席的代价是**静默落空根 +
   误导性报错**，是最坏组合。
4. **修在契约层，不逐点打补丁**：让**副本自描述**，而不是要求每个启动入口都记得 export。

## 七、端到端验证（v0.45.107，已回填）

- **产物级**：`dyautodm-backend-*.exe` 的 PYZ 中 `vbrowser` 模块**确认含**
  `_deploy_declared_root` 与常量 `dyautodm_app_root.txt`（用 PyInstaller 归档读取，
  非明文 grep —— 压缩 PYZ 里明文 grep 会假阴性）。
- **实机（经 `启动.cmd`）**：`/api/version` → `{"backend":"0.45.107",...}`；
  `run_*.log` 出现 **`[member] 已恢复上次登录会话: LOX2018`** 与
  `[db] SQLite 已初始化: ...\members\m17db0f8209156f26\data\dyautodm.db`（**正是此前失败的那一步**）；
  `GET /api/member/state`（携 `.session.json` token）→ `200 {"loggedIn":true,"username":"LOX2018"}`；
  且 `%LOCALAPPDATA%\DYAutoDM` **未再被创建**（数据根解析正确）。
- **双击 exe（无环境变量）路径**：由「PYZ 含修复」+「frozen+声明 → 正确根」的解析测试共同证明。

## 八、次生修复（同轮发现，避免静默错误）

`deploy.py` 生成 `启动.cmd` 时复用了**被 sidecar 循环改写**的 `dst_exe`
（该变量在 3 处被赋值：主程序 / 平铺 sidecar / 子目录 sidecar）⇒ 启动器**指向 recv-daemon**
（错误 exe）。已改为固定 `dst_main_exe`；并给 `write_text` 加 `newline=""`
（否则 CRLF 被文本模式再转换一次成 CRCRLF）。
**教训**：长函数中**跨段落复用变量名**会静默改变下游用途 —— 需为「贯穿函数生命周期的关键值」单独命名。

## 九、关联处置

- 误建的空默认根 `%LOCALAPPDATA%\DYAutoDM`（22:46，members 为空、232K）已**改名**为
  `DYAutoDM.stray_empty_20260929`（**可回滚，未硬删**）⇒ 默认根名释放，应用不再命中它。
- 同轮：高价值关键词权重表**设置页重复入口**已移除，只保留直播页弹窗入口（v0.45.107）。
