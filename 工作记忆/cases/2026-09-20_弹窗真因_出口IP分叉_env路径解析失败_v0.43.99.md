# 调试案例归档：抖音「安全风险…已阻止此次访问」弹窗真因 = 出口 IP 分叉（v0.43.99）

**日期**：2026-09-20
**版本**：v0.43.99（design/better-douyin，运行实例 `C:\temp\dyautodm_design`）
**严重度**：fatal（登录三通道全被拦 → 凭证无法更新 → 业务停摆）
**状态**：根因已定位并修复，出口分叉已实测消除；**最终需用户扫码确认弹窗消失**

---

## 一、设计意图（Design-First）

`vbrowser` 环境门阀契约（用户两次澄清的设计理念）：

> 环境模式**完全由配置显式决定**（`DY_PROXY_MODE = node / system / direct`），
> 判断条件**不依赖本机等外部可变状态**；浏览器与项目恒同一套出口环境，
> 杜绝中途 IP 跳变触发风控。

## 二、观测偏差

- 扫码 / 验证码 / 密码**三条登录通道全部被拦截**；
- 弹窗为**网页内元素**（非浏览器原生对话框），出现在**交互时刻**
  （填完手机号、扫码授权瞬间），首屏渲染正常 —— 故只看首屏会误判"正常"；
- 清缓存、新建 profile、改注入脚本**均无效**。

## 三、根因（RCA）

### 直接根因：会员空间 .env 路径解析失败 → 代理配置从未被读取

`vbrowser._env_path_of_account()` 为避免反向 import 造成循环导入，**自行硬拼**：

```
<app_root>/auto_dm/accounts/<name>/.env          ← 硬拼的路径
```

而**会员体系下的真实路径是**：

```
<app_root>/members/<member_id>/auto_dm/accounts/<name>/.env   ← 真实路径
```

⇒ 在会员环境**恒返回 `None`**。

### 后果链（本次弹窗的完整成因）

```
_env_path_of_account() = None
  → parse_proxy_config() 读不到 DY_PROXY_MODE
  → mode 落到缺省 "direct"
  → 浏览器强制 --no-proxy-server（走【国内直连 IP】）
  → 而用户用 Edge 时跟随【系统代理】，出口 23.191.200.205（境外）
  → 同一抖音账号在「境外 ↔ 境内」之间跳变 = 异地登录
  → 抖音弹「您正在尝试访问的网站存在安全风险…已阻止此次访问」
```

### 决定性实机证据

| 项 | 修复前 | 修复后 |
|---|---|---|
| 系统代理 | `ProxyEnable=1`, `127.0.0.1:10808`（在监听） | 同左 |
| 代理出口 IP | `23.191.200.205`（境外） | 同左 |
| Edge 出口 | `23.191.200.205` | 同左 |
| **本项目浏览器出口** | **国内直连 IP** ❌ | **`23.191.200.205`** ✅ |
| 环境门阀日志 | 「不走代理 → 本机 IP 直连」 | 「系统代理 → http://127.0.0.1:10808」 |
| `_env_path_of_account()` | `None` | 正确返回会员路径 |

浏览器出口经 BCC `/exec_js` 在页面内 `fetch('https://api.ipify.org')` 实测取得。

## 四、为什么前几轮都判错（教训）

1. **误判为「注入/环境泄漏」**：对照实测注入前后 `tampered 0→0`、
   `webdriver/HeadlessChrome` 均 false、自动化对象 0，已证伪；
2. **误判为「环境跳变风暴」**：确有无效重建，但非弹窗主因；
3. **关键漏检**：抓包已拿到 `GET /aweme/v1/web/get/user/risklevel/` →
   `{"risk_level":"no_risk"}` —— **服务端明确说无风险**，
   结合「用户用 Edge 没事」，两个信号都已指向**浏览器之外（网络出口）**，
   却仍在浏览器内部找了四轮。

**规则沉淀**：出现「某浏览器被拦而本机常规浏览器正常」时，
**第一步应比对两者出口 IP**，而非先查注入/指纹/profile。
