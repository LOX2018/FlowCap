# 实测 · API 扫码「二维码 65 秒过期」—— 三轮复现与指纹灌注对照（v0.45.147）

- **日期**：2026-10-01 03:47–04:03
- **分支**：`design/better-douyin`
- **账号**：四川工伤张老师（真实账号，design 根 `C:\temp\dyautodm_design`）
- **结论一句话**：**API 通道能出码（3.5s）但码只活 65 秒 ⇒ 当前不足以完成登录；
  灌注真实浏览器指纹（fpk1 等）无任何改善 ⇒ 65 秒与指纹无关。**

---

## 一、现象

用户在桌面用抖音 App 扫 API 出的二维码，**App 端提示「二维码过期」**。

## 二、三轮复现（非偶发）

| 轮次 | 时间 | 出码耗时 | 码寿命 | 判定来源 |
|---|---|---|---|---|
| 1 | 03:48（编排层 `_rpa_scan_login`） | — | ~70s | 服务端 `status=expired` |
| 2 | 03:51（**用户实扫**） | 3.0s | ~64s | 同上 |
| 3 | 03:55 复现实验 A | 3.5s | **65.0s** | 同上 |
| 4 | 03:56 复现实验 B | 3.5s | **65.0s** | 同上 |

- 正常二维码有效期应为 **5 分钟** ⇒ 实际被压缩到约 **1/5**。
- 判定来自**服务端响应**（`login_qr_api_runner.py:203` 读 `data.status == "expired"`），
  **不是本地超时**（本地 `timeout_s` 传的是 180/300）。
- 全程 `poll_err=None` ⇒ **未被限频、未被拦截**，是会话被"降级"。

## 三、指纹灌注对照实验（用户设想的验证）

设想：用真实浏览器（Camoufox）生成真实指纹，灌注给 API 通道使用。

### 步骤 1：从真实浏览器抓素材（实测可得）

| 素材 | 长度 | 来源 |
|---|---|---|
| **fpk1** | **88** | cookie ✅ |
| fpk2 | 32 | cookie ✅ |
| ttwid | 127 | cookie ✅ |
| s_v_web_id | 52 | cookie ✅ |
| msToken | 176 | cookie ✅ |
| UIFID / UIFID_TEMP | 384 / 224 | cookie ✅ |
| `security-sdk/*`（含 `/s_sdk_sign_data_key/login`） | 存在 | localStorage ✅ |

### 步骤 2：对照

| 组 | 出码 | 码寿命 |
|---|---|---|
| 基线（不灌注） | 3.0s | **65.013s** |
| **灌注 fpk1+fpk2+ttwid+s_v_web_id+msToken** | 3.5s | **65.013s** |

⇒ **完全无改善**（差值 0.0005 秒）。

### 结论

1. **65.0 秒在两组中几乎完全相同（±0.0005s）** ⇒ 是**固定值**，不是"按会话质量浮动"。
2. ⇒ **65 秒是抖音对「纯协议 / 非浏览器会话」下发的短 TTL**，与 fpk1 无关。
3. 上游告警「未捕获 fpk1，已用 fixture 纯算」**不是**导致短 TTL 的原因（灌注后不变）。

## 四、抓不到的素材（实测）

| 素材 | 结果 |
|---|---|
| `dtrait`（`x-tt-session-dtrait`） | ❌ **请求头里 8 秒监听未捕获到任何一次** |
| `window.__ac_nonce` / `byted_acrawler` / `_dtrait` | ❌ 全部 `undefined` |
| window 中名字含 dtrait/fpk 的变量 | ❌ `[]` |

⇒ dtrait **不在 DOM/JS 可见层**，由混淆 SDK 在原生层生成（与上游注释"无法纯算复现"一致）。
且抖音页面自身的常规请求也**不带**该头 ⇒ 它是 passport 登录流程专用素材。

## 六、教训

- **"出码快" ≠ "能用"**：API 出码 3.5s vs 桥 25~30s，但码活不过 65s ⇒ 快而无用。
  判成功必须看**全流程**（出码 → 扫码 → confirmed → 凭证有效），不能看单一指标。
- **灌注类设想必须先做对照实验**：对照组（不灌注）与实验组同跑，
  本例正是对照才证伪了"缺 fpk1 导致短 TTL"这个想当然的因果。
- **固定值 vs 浮动值**是强判据：两组都精确 65.0s ⇒ 常量；若会浮动才可能是质量评分导致。
