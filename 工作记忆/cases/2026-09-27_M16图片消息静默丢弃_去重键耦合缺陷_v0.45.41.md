# 案例 · 图片消息静默丢弃 —— 去重键与契约变更的耦合缺陷

> 日期：2026-09-27　分支：`design/better-douyin`
> 严重度：**高**（静默数据丢失，潜伏 2 天，无任何日志/告警）
> 编号：M-16　发现方式：全量回归失败根因追查 → git worktree 逐版探针

---

## 1. 设计意图（Step 1）

**模块**：`backend/auto_dm/conversation_capture.py` —— `parse_init_protobuf()` 首包解析。

**设计契约**：
- 输入：`get_message_by_init` 原始首包（cmd2043 包裹，protobuf）
- 输出：`[{conversation_id, peer_uid, sec_uid, messages:[{role,text,ts,msg_id,skey,thumb,...}]}]`
- **不变量**：首包中出现过的**每一条真实消息**都必须被解析出来；去重只允许去掉**同一逻辑消息的重复承载**（同一 msg_id 出现在多个容器层）。

**设计假设（被违反的那条）**：
> 「`(conv_id, text[:50])` 足以唯一标识一条消息」。

这个假设在 **H-25 统一落库契约（`a10ac1f`, v0.45.3，2026-09-25）** 之后**不再成立**——
该契约把图片消息的 `text` 从 `"[图片] <签名URL>"` 统一为语义标签 `"[图片]"`，
**剥夺了文本作为判别依据的能力**。

---

## 2. 观察到的偏离（Step 2）

`test_replay_capture_parse` 持续失败：
```
AssertionError: 16 != 18 : roles_me: 实测 16 ≠ 清单 18
AssertionError: 17 != 19 : total_msgs: 实测 17 ≠ 清单 19
```

初判（**错误**）：以为清单过期、属契约变更的预期副作用。
**推翻依据**：按 `msg_id` 逐条比对前后版本，发现丢的不是「文本显示差异」，而是
**整条消息记录消失**——`7682095679238161957`、`7682289942861628965` 两条
（均带独立 `skey`）在新解析器里**完全不存在**。

⇒ **`a10ac1f`（H-25 media-contract）引入**。

## 4. 根因分析（Step 4）

`conversation_capture.py:622`（修复前）：

```python
key = (mcid, txt[0][:50])
if key in seen_msg:
    continue
seen_msg.add(key)
```

**缺陷机理**（三段式）：

- **Source**：去重键把「文本前 50 字符」当作消息标识的一部分。
- **Propagation**：H-25 契约把所有图片消息 `text` 归一为 `"[图片]"`（4 字符）
  ⇒ 同一会话的多张图 **`txt[0][:50]` 完全相同** ⇒ 被判定为重复。
- **Terminal**：`continue` 跳过 ⇒ **消息整条不进 `messages`** ⇒ 静默丢图。

**这不是 H-25 的错**，是**去重键选了易变字段**。H-25 只是把这个潜伏缺陷
从「不触发」变成「必然触发」——**耦合缺陷的标准形态：一个模块的契约变更，
引爆另一个模块的脆弱假设**。

**实测丢失量**：修复后 28 条 vs 修复前 19 条 ⇒ **旧键一直丢 9 条**
（不止图片；任何 `text[:50]` 相同的多条消息都会被误去重）。
修复后 **零重复 msg_id、零 None**（逐条复核）。

## 6. 教训（可迁移判据）

### 🔴 教训 A：**清单里的「期望值」也可能固化着一个缺陷**

原以为是「实现退化了」，实际是**期望值本身是带缺陷的读数**——
`19` 是**缺陷版本的读数**，`28` 才是真相。
⇒ **判据**：当「实现 ≠ 期望」时，**不要默认期望正确**。
必须按**语义**判断（此处 = 「消息有没有丢」），而不是按「谁写在清单里」判断。

### 🔴 教训 B：**去重键/缓存键绝不可选「会被契约变更的字段」**

`text[:50]` 是展示语义字段，天然会随落库契约演进。
⇒ **判据**：任何去重键、缓存键、幂等键，必须选**标识类字段**（id / hash / 序数），
**禁止选内容类字段**（text / 名称 / 展示文案）。

### 🔴 教训 C：**契约变更必须扫「所有依赖该字段的消费点」**

H-25 改了 `text` 的生成规则，但没有扫到「有人拿 `text` 当去重键」这个消费点。
⇒ **判据**：契约变更（Canonical Contract Law 意义上的）落地时，
必须 grep **该字段的全部消费点**，而不只是生产者。

### 手法：单文件加载失效时用 git worktree

用 `importlib` 加载历史单文件在**模块拆分提交之后失效**
（`attempted relative import with no known parent package`）。
⇒ **判据**：跨模块拆分点做历史对比，必须 `git worktree add <path> <sha>`
检出**完整树**再跑，不要试图单文件加载。
