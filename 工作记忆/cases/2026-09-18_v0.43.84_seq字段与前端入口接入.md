## 问题背景

上游 `TeamBreakerr/douyin-chat-export` v2.0.0 对比分析完成后，规划了 13 个前端入口接入项（E1–E11，E4 已取消）。

## 根因分析

### 1. 会话详情缺 seq 字段 → 前端无法做选区渲染

**Source**: `get_conversation` 返回的消息对象没有 `seq` 字段。`/render/png` 的 `fetch_range` 依赖 seq 做区间过滤，前端拿不到就无法精确指定起止消息。

**Propagation**: 前端只能按索引猜测 → 与后端过滤口径不一致 → 选区错位/导出错误内容。

**Terminal**: 长图导出功能只能做"全量导出"，无法支持用户框选部分消息。

**Fix**: 在 `get_conversation` 的消息构建循环中增加 `seq = enumerate(msgs, start=1)`，与 `fetch_range` 使用完全相同的过滤+排序口径，确保前后端 seq 一致。

### 2. 测试 DB schema 缺少 short_id/avatar 列 → 新增测试报错

**Source**: `_mkdb()` 创建的内存数据库缺少 `short_id` 和 `avatar` 列，但 `get_conversations` 的 SQL 查询包含这两列。

**Propagation**: 任何调用 `get_conversations` 或 `get_conversation` 的测试都会报 `no such column: short_id`。

**Terminal**: `TestConversationSeq` 测试 ERROR，全量测试 failures+1。

**Fix**: 在 `_mkdb()` 的 `CREATE TABLE dm_conversations` 中补充 `short_id TEXT DEFAULT ''` 和 `avatar TEXT DEFAULT ''`。

### 3. 测试断言路径错误

**Source**: 测试代码用 `res.get("messages")` 取值，但 `get_conversation` 返回结构是 `{"ok": True, "conversation": {"messages": [...]}}`。

**Propagation**: `msgs` 为 None → `len(msgs)` 抛 TypeError。

**Terminal**: 测试 ERROR。

**Fix**: 改为 `msgs = (res.get("conversation") or {}).get("messages")`。
