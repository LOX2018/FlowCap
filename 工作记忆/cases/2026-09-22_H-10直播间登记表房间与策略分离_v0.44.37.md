## 一、问题（设计契约层面，非「代码写错」）

2026-09-19 用户定调「**没有『目标直播间』体系**，直播策略自足、只含发送参数、零身份字段」，
并据此在 `api/live_config.py` 注释写下「删除策略**无任何跨模块解绑副作用**」。

2026-09-22 用户要求引入**直播间管理**（填链接 → 解析房间 + 备注 + 绑定策略 + 脱敏开关）
⇒ **部分逆转**旧定调。这不是「旧代码有 bug」，而是**架构前提变了**：单层「策略=自足」模型
无法表达「在哪发」（身份）与「怎么发」（参数）的正交关系。

**如果只在策略层塞回身份字段**：会重演 2026-09-19 已清理的「一房一配置」脏数据 ——
实测存量 `live_room_configs["992931212705"]` 带 `room_id`/`live_url`/`name`，
读取时被 `_normalize_stored()` 主动 `pop` ⇒ 这些信息**已 orphan、UI 无从恢复**。

## 二、决策（用户拍板，ADR-003）

**房间与策略分离**：

| 层 | 载体 | 内容 |
|---|---|---|
| **策略**（怎么发） | kv `live_room_configs`（**契约不变**） | 发送参数，零身份字段 |
| **房间**（在哪发） | **新增** kv `live_rooms` | 身份 + `strategy_id` **引用** + `allow_desensitized` |

⇒ 一份策略可被多个房间**引用** ⇒ 触发新不变式：**禁止悬空引用**
（同族先例：删除 Agent 必须自动解绑引用账号）。

## 五、方法论要点（可迁移）

1. **「部分逆转旧定调」必须就地改旧注释**：本项目多处历史断言写在 docstring 里，
   不改则后续会话读到旧结论会**产生分叉**（比不改代码更贵）。
   ⇒ 做法：保留旧定调原文 + 加「⚠️ 已被 ADR-00X 部分逆转」段落，写清**哪部分仍有效**。
2. **引用完整性 = 删除路径的一等职责**：新增「A 引用 B」关系时，**B 的删除路径必须同步处理**，
   并在响应里**显式返回处理数量**（`unbound: N`），禁止静默。
3. **迁移必须默认干跑**：`POST /migrate {dry_run:true}` 先报告，`apply:true` 才写；
   且**幂等**（第二次零新增），返回形状**稳定**（干跑也返回空列表键，调用方无需猜）。
4. **D-07 失败态自证**：把 `unbind_strategy` 注入为 no-op → 悬空引用 = 1、`unbound` = 0
   ⇒ 证明判据真的在测行为，不是恒真断言。
5. **真机 CDP 验证 Tauri WebView2**：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 必须含
   `--remote-allow-origins=*`，否则握手 403；导航到目标页要点**侧栏 `button span.truncate`**
   文本恰为「直播」的元素（点含「直播」的任意元素会命中任务页的「直播」列头）。
6. **改 UI 后「接口真值」与「界面渲染」要分别取证**：删除后接口已无该行，但 React 列表
   仍显示旧渲染 —— 判据以**接口/DOM 重载后**为准，截图需在重载后再拍。

## 六、遗留（诚实标注，未做）

- `allow_desensitized` 的**运行时消费**（引擎检测到脱敏时真的「仅统计」）**未接线** ——
  当前只做登记与持久化；消费点在 ADR-002（多账号并发）落地时接入。
- 房间层与直播页输入框的联动仍是「选用回填」，尚未把「选房间 → 自动带出绑定策略」
  做成单一入口（可用性优化，不影响本 ADR 判据）。
