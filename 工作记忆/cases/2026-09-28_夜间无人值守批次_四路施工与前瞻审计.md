## 四、本批做了什么

### N1 · F4 定时任务中心三处运行时缺陷（提交 `c56babc`，v0.45.60）

**改了什么**（`services/task_scheduler.py` +78/-9；`test_task_scheduler_gates.py` +319/-0）：
- **TS-5**：`run_task_now` 复用既有 `_lock`+`_running`（未自造新锁），锁内完成「判重入→置位→执行→状态写回→复位」；被重入返回 `{ok:False, rejected:True, busy:True}`，不排队不静默。
- **MC-2**：`_tick` 与 `run_task_now` 的 `last_run_at` 由「本轮扫描开始时刻 `now`」改为 `finished = time.time()`（执行完成时刻），长任务不再被连续重复调度。
- **TS-4 另一半（派工未列、实测发现）**：`_tick` 的 `finally` 原无条件 `_running=False` —— 提前 return 的 `_tick` 会抹掉正在执行者的重入保护；改 `entered` 标志，只有抢到的一方才复位。

**证据（父会话收尾亲跑）**：
```

→ Ran 11 tests — OK
→ 合计 10 项（B1~B10），通过 10，未通过 0
→ 负控 7/7 如期报红（新增 3 组：B8/B10 去保护 → ['B10','B8']；
   B10b TOCTOU → ['B10','B8']；B9 改回开始时刻 → ['B9']）
→ 还原后复跑 exit = 0
```

**三条诚实标注（已在提交信息写明）**：
1. D 项超出派工清单 —— 但不修则 A 项保护可被外部撤销，属同一缺陷面的另一半。
2. 🔴 **原门禁 `python -m unittest` 收集到 0 个用例却 exit 0**（脚本式门禁，最危险的假绿形态）。本次新增 unittest 桥接后命令才有 11 个用例。
