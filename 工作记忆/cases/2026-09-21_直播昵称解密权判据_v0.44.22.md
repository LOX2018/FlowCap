# 2026-09-21 「凭证更新了但直播监听没有用凭证解密」根因与修复（v0.44.22）

> 错误码：`LIVE-034`（会话态未知）、`LIVE-035`（无解密权）、`LIVE-036`（探测失败）、
> `LIVE-037`（带凭证进房回落匿名）；域契约：`DOMAIN_DESIGN["LIVE"]`（本次补齐，此前整域缺失）
> 分支：`design/better-douyin`　环境根：`C:\temp\dyautodm_design`
> 用户原话：「张老师凭证更新了，但直播监听没有用凭证解密」

---

## 一、结论（先说答案）

**不是「没用凭证」——凭证确实进去了；是「张老师这个会话没有解密权」。**

服务端把该账号当**非登录观者**处理，于是直播帧里直接下发**脱敏数据**
（`uid=111111` + 昵称 `威***` + `sec_uid` 空）。这与「完全不带 cookie 的真匿名」
现象**逐字相同**。

**另一件必须说清的事**：全仓**没有任何「直播昵称解密」的实现**（`解密/decrypt/
desensitized` 在 `core/`、`dy_live/`、`dy_apis/` 里只出现在注释与**私信图片** AES
链路）。所以「没解密」**不是回归**，是该能力从未实现过；上一版只做了
「连不上流」的解耦（ENG-017），没有也不会做算法解密。

## 二、取证（三组对照，同一房间 / 同一时刻 / 只换 cookie）

`scripts/diag/diag_live_cred_ab.py` —— 零浏览器，直接建真实 WS 收帧：

| cookie | 弹幕样本 |
|---|---|
| 四川工伤张老师 | `uid=111111` `sec_uid=''` `三***` ❌ 脱敏 |
| 尚进工伤小助理 | `uid=63676672247` `sec_uid=MS4wLjABAAAA…` `幸运星语` ✅ 正常 |
| （无 cookie·真匿名） | `uid=111111` `sec_uid=''` `三***` ❌ 脱敏 |

⇒ 张老师**带 cookie ≡ 不带 cookie**。故「有非空 cookie」是**代理信号**
（判据为真、能力为零），被判据认定为「会话未被承认」。

### 第二证据：直播间页 HTML 登录态标记

同一 URL 只换 cookie：张老师页面渲染「登录」文案 **4 处**（与真匿名**完全一致**），
尚进 **0 处**。⇒ 服务端把张老师按**未登录**渲染。

### 第三证据：cookie 字段差集 + 主站 `user/profile/self/`

- 差集：张老师**独缺** `passport_assist_user`（live 域登录态字段）、`is_dash_user`、
  `FOLLOW_LIVE_POINT_INFO`；张老师**独有**一批 `live_*` 浏览态字段（是**观者**足迹，
  不是账号登录态）。
- 主站 `profile/self`：张老师 → `status_code=8 "用户未登录"`（323 字节）；
  尚进 → `status_code=0` + 完整 user 对象（16255 字节）。

### 🔴 判据自检（先证伪自己的探针）

`profile/self` 说未登录，而 `query/user` 同时返回真实 uid ⇒ 两者矛盾，
必须先排除「探针缺签名参数（msToken/a_bogus）导致的假阳性」：

`scripts/diag/_diag_probe_selftest.py` 四条路径对照（同 cookie 同时刻）：

```
四川工伤张老师
  A 裸 GET                    → status_code=8  ❌
  B 项目既有 get_my_sec_uid   → 同样 status_code=8（811854 字节页面取不到 secUid）
  C 裸 GET + msToken          → status_code=8  ❌
  D 裸 GET + web_id + a_bogus → status_code=8  ❌
尚进工伤小助理
  A/B/C/D 全部 status_code=0 + sec_uid ✅
```

⇒ **与签名参数无关**，判据不是假阳性。**两个独立业务面同时否定**该账号
（主站 `profile/self` 未登录 + imapi `cmd609 unexepcted session length` 只读态）。

## 三、根因（设计契约层面的错）

**判据错误**：`_has_credential()` 原文是「auth 带非空 cookie」。
张老师 cookie **70 个字段齐全**（`sessionid`/`sid_tt`/`ttwid`/`uid_tt` 全在）
⇒ 判据为真 ⇒ 用**未被承认的会话**去建 WS ⇒ 只能收到脱敏弹幕。

这正是本项目明令禁止的**代理信号当结论**（§〇·己·3）：
「资源存在（cookie 有值）」只证明资源被创建过，不证明**资源当前被接受**。

## 四、修复（v0.44.22 / ENG-018）

| 落点 | 改动 |
|---|---|
| `auto_dm/accounts.py` | 新增 `probe_live_identity(name, auth, force, ttl)` —— 判据落在**真实业务通路**（主站 `profile/self` 是否承认会话：`status_code==0` 且含 `sec_uid`）；缓存 300s；异常一律转 `(False, 可读原因)` 且带「结论未知」标记 |
| `core/live_hook.py` | `_has_credential()` 升级为**会话态三态**判据（接受 `session_ok`）：`True`=服务端承认 / `False`=已确认未承认 / `None`=取不到证据（**诚实降级**，保留原行为并留 `LIVE-034`）；`LiveChatHook.__init__` 新增 `session_ok` 参数（只消费，不自创判据） |
| `core/auto_dm.py` | 启动时探测并写 `self._live_session_ok`；**重扫路径（`rescan_and_rebuild`）重新探测**（用户症状正是「重扫后仍不解密」）；无解密权时 `status_msg` 透出「昵称脱敏·账号无解密权，请重新扫码」 |
| `dy_live/server.py` | 无解密权 ⇒ **不再用账号 cookie 建 WS**（改匿名 ttwid，避免用未被承认的会话）；`_room_info_with_credential()` 带凭证取信息失败/无 room_id 时**显式回落匿名**（`LIVE-037`） |
| `errcode_data.py` | 新增 `LIVE-034~037` 六段契约；**补齐 `DOMAIN_DESIGN["LIVE"]`**（此前整域缺失，域内全部码审计恒报缺 design） |

### 顺手修掉的既有缺陷

`_anon_cookie()` 内部返回的是 `ttwid=<值>`，而原调用点又拼了一次
⇒ **`ttwid=ttwid=<值>` 双前缀**（用真实抓包对照发现）。改为 `_anon_ttwid_from(info)`
返回**裸值**，前缀只由调用方拼一次；同时**复用已取得的 ttwid**，不再为组 cookie
多打一次网（原来每个任务多一次请求，且可能拿到**不同** ttwid 会话）。

## 七、遗留与边界（诚实标注）

1. **本修复不「解密」任何东西**——它做的是**正确判定 + 诚实降级 + 可归因**。
   要真正拿到真实昵称，唯一路径是**账号会话被服务端承认**（重新扫码建有效会话）；
   本次实测：一个刚在浏览器里完成真实扫码的账号（张老师）**依然**被判未登录，
   ⇒ 说明光「扫码」不保证拿到解密权。
2. **尚有未定论的第三种可能**：`uid=111111` 也是**直播间级**开关
   （外部证据：`saermart/DouyinLiveWebFetcher` issue #98 —— 主播开启「隐藏观众信息」
   时，所有观众 uid 均为 111111）。但**对我们不是分歧点**：尚进账号读**同一房间**
   能拿到真实 uid/nickname，⇒ 该房间此刻**未**被脱敏，差异只可能来自账号。
   文案已按此写成「重扫；若重扫后仍如此，可能是该直播间开启了隐藏观众信息」。
3. **解密权缺失的更深根因未定论**（只读态 cmd609 + `profile/self` 未登录同时出现）。
   已排除了「探针缺签名」「出口 IP 分叉」；未排除的有：账号侧服务端标记、
   会员空间与全局空间的 `.env` 差异、该账号是否被系统性降权。
