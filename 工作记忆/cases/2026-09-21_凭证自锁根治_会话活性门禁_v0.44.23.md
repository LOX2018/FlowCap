# 案例 · 凭证自锁根治：`.env` 被固化为「扫码瞬间旧会话」→ 会话活性门禁（v0.44.23）

> 日期：2026-09-21　分支：`design/better-douyin`　环境根：`C:\temp\dyautodm_design`
> 触发：用户报「张老师凭证更新了，但直播监听没有用凭证解密」，排查中先后证伪两个错误结论，
> 最终定位到 `.env` 写入链的**自锁**并根治。
> 关联：`live_monitor_failure_handling.md` §二·甲（判据与配方）、`02_指纹浏览器与凭证.md`

---

## 一、设计意图（回归设计理念）

| 模块 | 契约 |
|---|---|
| `dy_apis/login_api` 扫码/重捕 | 抓到的凭证应是**被服务端承认的、当前生效的会话**，而不是扫码瞬间的旧快照 |
| `daemon/browser_daemon.refresh_cookie_to_env`（保活回写） | 只能把**被服务端承认的会话**写进 `.env`；坏会话绝不落盘；且**失败必须响亮** |
| 判据体系 | **一个判据只覆盖一类失效**：身份一致（query/user）≠ 会话活性（profile/self）≠ IM 写（create_conversation） |

## 二、当前状态偏差

- 现象：监测账号带 cookie 建直播 WS，帧仍脱敏（`uid=111111`、`nick='威***'`、`sec_uid` 空），与**完全无 cookie** 逐字相同。
- 但同账号 `/api/version` 正常、`query/user` 探活返回**正确的** uid。

## 三、执行链溯源（实测，非推断）

```
扫码/重捕 → context.cookies() → save_credential → .env(.enc) → 直播监听读 .env → WS 带 cookie → 服务端判「非登录观者」→ 脱敏帧
                                                        ↑
                                          BCC 保活回写本应刷新它，但被自锁卡死
```

## 四、根因（RCA）

### 4.1 直接根因：`.env` 里是「扫码瞬间的旧会话快照」

| 证据 | 内容 |
|---|---|
| A/B/C 只换 cookie（同房间同时刻） | 张老师 `.env` → 脱敏 ❌ / 尚进 `.env` → 真实昵称 ✅ / 无 cookie → 脱敏 ❌ |
| 结构比对（**整套会话家族**） | `.env` 与 profile 的 `sessionid/sid_tt/uid_tt/uid_tt_ss/sid_ucp_v1/sid_guard` **全部不一致**（`24f1ba95` vs `55dccaf8`）；而尚进两处**逐字节一致** |
| 时序 | `.env` 写于 `13:04:08`；浏览器真正被承认的 `sessionid` 生成于 `13:04:23`（**晚 15s**） |
| 服务端判据 | `.env` 凭证 `profile/self = 8`（未登录）；**profile 凭证 `= 0` 且建 WS 拿到真实昵称** ⇒ 账号本人有解密权，坏的是 `.env` 那套 |

### 4.2 结构性根因：判据超载（已证伪两个错误结论）

1. ❌「账号无解密权」——被「profile 凭证能拿真实昵称」证伪。
2. ❌「探活 uid 与历史 conv_id 一致（AUTH-050）= 有解密权」——被 `run_20260921_130901.log` 证伪：
   `13:04:38` 探活已回到 `3887506227210423`（AUTH-050 消失），`13:09:37` 弹幕仍 `uid=111111`。
   ⇒ `query/user` **容忍陈旧会话**，`profile/self` **严格**；用身份判据覆盖会话活性判据 = 方向相反的结论。

### 4.3 自锁形态（**本问题在 09-08 就遇到过，只修了一半**）

- `3b20635`（09-08）事故：profile 残留 **4175** 凭证 → 保活回写写进 `.env` → 探活恒 4175 → keepalive 每轮判漂移 → **无限 scan_login 重启**。
  那次只加了**门禁 1.5（拒写）** —— **只拦截、无恢复**。
- 09-21 同型复发：探活返回漂移 uid `3119773958541104` → `BCC-014`/`BCC-016` **拒绝写入** → `.env` 永不刷新 → 下轮仍坏 → **继续拒绝**（自锁）。
  叠加 `cred_mode=observe` + `BCC-057`（有头观测态禁止重扫）⇒ 自动路径全关，人工重扫走的又**正是**会写错快照的 `recapture_from_profile`。

### 4.4 为何「另一个账号没事」（不对称的真相）

| | 账号甲（无自愈） | 账号乙（有自愈） |
|---|---|---|
| `.env` 写入路径 | 只有扫码/重捕的**一次性快照** | BCC **保活回写**（每 30min 用 profile 实时态覆盖，写前先确认登录态正常） |
| 「登录态正常」分支命中（实测） | **0**（该分支从未成立） | 多次 |
| 「保活回写」命中（实测） | 全量仅 **1** 次 | 多次 |
| 净效果 | 坏快照被**永久固化** | 抓取缺陷被每次覆盖**掩盖** |

⇒ **自愈回路会让故障「不发作」，也就会让故障「不被发现」。**
⇒ 排查纪律：先数 `登录态正常` / `保活回写` 的命中数，任一为 0 = 该账号 `.env` 是静态快照。

## 五、修复（v0.44.23）

| # | 改动 | 位置 |
|---|---|---|
| 1 | 会话活性判据抽为**三态** `live_session_state`（True/False/None），`probe_live_identity` 保持二元兼容 | `auto_dm/accounts.py` |
| 2 | 保活回写加**门禁 1.6**（会话活性）：只有**明确被拒**才拒写；未知**保守放行**（三态铁律） | `daemon/browser_daemon.py` |
| 3 | 被拒时**就地刷新页面再复验**（不再直接放弃）——解自锁 | 同上 + `_refresh_page_for_session` |
| 4 | keepalive 对 `session_ok=False` **立即重试一轮**（不等 30min），两次仍失败响亮告警 | 同上 |
| 5 | **源头根治**：抓取口拿到 cookie 后**复验会话被承认**，未承认则等一拍重读（最多 3 次） | `dy_apis/login_api.py` |
| 6 | 🔴 **自锁另一半（关键）**：keepalive 的 uid 取自 `.env`（`_load_uid_from_env`）⇒ 坏 `.env` 时 uid 为空、**永远进不了回写分支**。改为把回写抽成 `_sync_env()`，**门控用页面登录态**；并在「探活异常」分支加：**页面登录态正常 ⇒ 用 profile 实时态回写 `.env`，本轮不触发重扫** | `daemon/browser_daemon.py` |
| 7 | 新错误码六段契约：`AUTH-053` / `BCC-071` / `BCC-072`（**注意 BCC-058 已被 Camoufox 占用**，原稿重号已改） | `errcode_data.py` |

### 不变式（守卫测试钉住）

1. 探测失败（None）**不得**折成 False（否则网络抖动 → 误拦 → 与门禁 1.5 同型死锁）。
2. 会话未被承认时**绝不写 `.env`**，且返回 `retry_now`（否则自锁永续）。
3. 既有门禁 1.5（幽灵 uid）不被绕过。
