## 一、现象（用户报告）

1. **张老师账号**能正常唤醒有头模式并完成更新；**小助理账号**始终提示"唤醒异常"。
2. 张老师账号唤醒有头浏览器、**成功拉取后**仍提示"同 profile 反复激活"，造成**重启风暴**。
3. 用户补充的关键事实：**"并不是凭证好就被放行、凭证坏就被拦截"** —— 两个账号凭证都过期时，
   先启动小助理失败 → 再启动张老师也失败 → **过一会儿又一切正常**。
   ⇒ 明确指向**竞态 / 残留**，而非凭证本身。

## 二、设计意图回归（Step 1）

| 模块 | 设计契约（pre/post-condition、invariant） |
|---|---|
| `close_camoufox_context()` | **post-condition**：关闭返回后，该 profile 目录下不应残留任何持有它的浏览器进程 |
| `_wait_profile_released()` | **pre-condition**：等待其释放；**invariant**：超时 ≠ 已释放，不得把"等够了"当成"可以进" |
| `/show`（切换可见性） | **invariant**：同一目标态的重复请求应幂等，不得重复冷启动 |

## 三、当前状态与偏差（Step 2）

| 项 | 期望 | 实测（修复前） |
|---|---|---|
| profile 退净耗时 | 秒级 | **60s 未退净，alive=2** |
| 等待超时后行为 | 明确失败/重试 | **打印一行 warning 后放行** → 必撞 BCC-058 |
| `/show` 重复请求 | 幂等返回 | 每次都冷启动 |

**偏差类型**：timing + resource 复合。偏差点：`close_camoufox_context` → `_wait_profile_released` → `/show` 调用链。

## 四、执行链追踪与 RCA（Step 3-4）

```
/show 请求
  └─> 判定需切换 → 冷启动 Camoufox（成本高）
        └─> 启动前 _wait_profile_released(profile_dir, 10s)
              └─> 上一轮 close_camoufox_context() 未真正杀掉进程
                    ⇒ 10s 超时 → 【盲进】→ 撞 BCC-058「同 profile 反复激活」
                          ⇒ 重试循环 = 重启风暴
```

**Root Cause**：
1. `close_camoufox_context()` 依赖 Camoufox 自身关闭语义，在 context 已异常
   （`'object' object has no attribute 'close'`）时**静默失败**，遗留进程仍持有 profile 锁。
2. `_wait_profile_released` 把"等待超时"错误地实现为"放行"，用时间耗尽冒充资源已释放。
3. `/show` 缺少切换中去重，同目标态重复请求叠加冷启动。

**为何"小助理失败→张老师也失败→过会儿正常"**：
残留进程持有 profile 锁是**有时效的竞态**；先启动者的残留会拖垮紧随其后的启动者，
等残留进程自行退出后就"又正常了"。与凭证好坏**无关** —— 这解释了用户的反直觉观察。

## 五、修复（三处）

### 修复 1 · 根因：profile 残留清扫
新增 `_reap_camoufox_processes(user_data_dir, grace=3.0)`：按 profile 路径精确匹配
（terminate → 超时 kill），接入 5 个调用点。

### 修复 2 · 兜底：等待超时不再盲进
`_wait_profile_released` 超时后**主动清扫 + 重新判定**；仍被占则显式抛错（**BCC-077**），
而非带着必败的启动去撞 BCC-058。

### 修复 3 · 架构整改：`/show` 切换中去重
`_switching` 期间同目标态的重复请求直接幂等返回。

## 六、⚠️ 自引回归与修复（本轮最重要教训）

修复 1 初版**引入了真实缺陷**并被机械门禁捕获：

```
[BCC-071] [camoufox] 关闭后仍残留 8 个进程占用 profile，开始清扫（grace=3.0s）: guard
```

**误杀**：探针的 `_profile_dir="GUARD"` 太短太通用，needle="guard" 命中了
**8 个无关进程**（含测试宿主自身 PID）→ `startup_single_fire` 从 3 OK 退化为 2 failures。

**已加两条硬保护**：
1. 路径必须是**绝对路径**且**长度 ≥ 20**，否则拒绝清扫 —— *不能可靠识别目标时拒绝行动，
   而非"尽力一试"*。
2. **绝不杀自身 PID** —— 误杀宿主比残留严重一个量级。

**判据化表述**：清扫类操作的 needle 必须可唯一锚定目标；否则宁可不作为。

## 八、未能做到理想态的部分（如实记录）

**修复 3 只做到"去重"，未做到"零冷启动"**。
原本计划让 `/show` 完全不重建 context。实机否决：`_set_window_state` 走 CDP，
而 Camoufox 是 **Firefox 内核走 juggler**，实机返回 `False`。
⇒ **每次切可见仍会有一次冷启动**。已在代码注释中写明，未包装为"已解决"。

## 九、过程中的两个坑（可复用判据）

1. **错误码撞号**：最初用 BCC-071~073，但已被"cookie 会话/保活回写/登录态探针"占用。
   ⇒ 新增错误码前**必须查 `errcode_data.py` 现有占用**，改为 BCC-074~077。
2. **`patch` 工具规范化行尾**：首次改 `errcode_data.py` 时整文件从 LF 被改成 CRLF
   （`diff numstat` 1061 行 vs 实质 6 行）。⇒ 已回滚，改用**字节级插入**，`numstat = 4/0`。
   **判据**：`git diff --numstat` 与 `git diff --ignore-all-space --numstat` 不等 ⇒ 有纯 EOL 差异。
