## 一、设计意图（Design Intent）

内容板块（`frontend/src/components/platform/platform-page.tsx`）应展示本人/目标账号的
点赞、收藏、作品、合集、收藏夹等真实内容列表；"关注"为写操作入口。

- 设计契约（DbC）：
  - 前置：用户已登录、账号凭证有效、目标 sec_uid 合法。
  - 后置：各列表端点返回 `ok=True` + `items[]`（真实数据）或 `unavailable=True`（身份态缺失时**如实降级**，而非崩 502）。
  - 不变式：所有走 secsdk webSign 保护清单的端点必须带 `uifid` + `x-secsdk-web-signature`，否则被 Argus 网关拦截。
- 预期行为：板块内容真实可见、可交互。

## 二、观察偏差（Observed Deviation）

| 端点 | 修复前 | 偏差类型 |
|---|---|---|
| `/liked` `/favorite` | HTTP **502**「获取自身 sec_uid 失败」 | data / 错误语义 |
| 点赞/收藏/作品/合集/收藏夹 | 前端**恒空**（板块"残缺用不了"） | data |
| `/action/follow` | HTTP **501**「关注写操作尚未实现」 | 功能缺失（假入口） |

- 偏差点：5 个列表端点撞 Argus 403；`liked/favorite` 缺 sec_uid 时抛 502；`follow` 基座无写方法。

## 三、错误码（DSSCC 格式）

```
ERR-PLT-SECUID-001  content-panel broken   severity=error
ERR-PLT-ARGUS-403    secsdk sign missing     severity=fatal  (功能根本不可用)
ERR-PLT-FOLLOW-501   follow unwired          severity=warn   (假入口)
```

## 四、RCA（根因，非症状）

1. **主因（C-02 secsdk 签名断链）**：`/aweme/v1/web/aweme/favorite/`、`/aweme/v1/web/aweme/post/`、
   `/aweme/v1/web/aweme/listcollection/`、`/aweme/v1/web/mix/listcollection/`、`/aweme/v1/web/collects/list/`
   全部在 `utils/secsdk_web_sign.PROTECTED_PATHS_GET` 保护清单内。原实现把 `params.get()` 交给
   requests 的 `params=`——既无 `uifid` 也无 `x-secsdk-web-signature`，服务端恒返
   **HTTP 403（46 字节非 JSON）`Blocked by ArgusSecurityPlugin Uifid Not Found`**。
   （上游确证：`utils/secsdk_web_sign.py` 的 `PROTECTED_PATHS_GET/_POST` + `signed_url()` 实现完整，
   但基座调用点**未接线**——属 C-02 契约"签名接线"缺口，`.known-gaps.json` 已登记。）
2. **次因（错误语义）**：`/liked`、`/favorite` 取不到本人 `sec_uid` 时原实现抛 502，前端只能弹
   "请求失败"，用户无法区分"功能坏了"还是"登录态问题"。实测 `profile/self` 在高频访问后返
   `status_code=8 用户未登录`（同期 `feed` 仍 200/6 条 ⇒ cookie 有效，是服务端对该凭证的
   **临时降权**，非账号失效）——属 `get_my_sec_uid` 缺缓存+无退避的真实缺陷。
3. **关注写操作**：基座 `dy_apis` **无 commit/follow 方法**（仅 follower/following 两个读接口）
   ⇒ `/action/follow` 恒 501，前端 `platform.ts` 虽有定义但**页面无调用** ⇒ 永远失败的假入口。
