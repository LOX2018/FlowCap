## 问题一：软停止卡死 50 秒（ENG-016）

### 复现与实测证据

`scripts/diag/diag_soft_stop_state.py` 用真实 `AutoDM` + `DispatchCenter` 精确复现：

```
③ stop() 返回      state=stopping  msg='监听已停止（私信发送中）' q=1 pending=1
④ +0.5s           state=stopping  q=0 pending=1   ← 队列空了，pending 被 _loop 持着
④ 0.5~50s         state=stopping 恒定格            ← ★ 卡死 50 秒
④ +50.0s          state=stopping  q=0 pending=0   ← 延迟窗口睡满，_do_send 才清 pending
④ +52.5s          state=stopped                    ← 才收尾
```

**卡死时长 = 那条记录的随机延迟窗口**（`delay_range` 50~120s）。

### 根因：两条收尾路径被同一条记录同时堵死

| 收尾路径 | 触发条件 | 被堵原因 |
|---|---|---|
| `_on_dispatch_idle` | `queue.empty() and not pending` | pending 非空 → 永不触发 |
| `_wait_dispatch_done` | `wait_done()` 的 `while ... or self.pending` | 同一原因永等 |
| 而清 `pending` 的只有 `_do_send` | 它在 `sleep(send_at - now)` **之后** | 软停止不打断该 sleep |

且软停止后 `_accept_new=False` 使该记录**必然走不到发送**（闸门拒收），
纯粹空等 —— 这不是「等存量发完」，是「等延迟窗口睡满」。

### 修复

| 文件 | 改动 |
|---|---|
| `core/dispatch.py` | 新增 `_stop_signal: asyncio.Event`；`_loop` 把 `sleep(send_at-now)` 改为 `wait_for(_stop_signal.wait(), timeout=...)`；被唤醒则丢弃该目标并 `pending.pop`；`stop_hard`/`stop_soft` 均置位；`start()` 清除 |
| `core/dispatch.py` | `_stopped` 分支丢弃时也补 `pending.pop`（原本只 continue，同样会残留） |

**实测：50s → 2.5s 内收尾。**

## 问题二：直播流连接与凭证解耦（ENG-017）

### 用户的架构判断（本轮回合确认成立）

> 抖音直播支持**匿名连接查看**；凭证是为**部分直播间昵称加密**服务的。
> 不能因为凭证失效就连直播流都无法连接。

### 实测取证（`scripts/diag/verify_anon_live_decouple.py`，零账号凭证）

```
场景：凭证已失效（cookie 空 / 无 ticket / 无私钥）
① _has_credential() = False
② 匿名进房 room_id=7687656644544645894  status=2  ttwid=127字符   ✅
③ 匿名 WS 握手成功                                                ✅
④ 收到帧数 = 6                                                    ✅

⇒ 凭证失效不影响直播流连接 —— 用户判断成立。
```

### 修复前的耦合点（4 个 return）

`core/auto_dm.py::_run` 在 AUTH-018/019/020/021 四处**直接 return 并置 IDLE**：

```python
if not getattr(self.monitor_auth, "cookie", None):
    logger.error("[AUTH-018] 监测账号未获取到登录 cookie，无法监听。")
    self.status_msg = "监测登录失败"
    self.state = EngineState.IDLE
    return          # ★ 连流都建不起来
```

⇒ 凭证失效 → 引擎回 IDLE → `LiveChatHook` 从未创建 → `/api/live/stream` alive=false。

### 修复：监听线 / 发送线解耦

| 线 | 凭证要求 | 缺失时行为 |
|---|---|---|
| **监听线**（进房 + WS 收弹幕） | **不需要** | 走匿名（ttwid）继续监听 |
| **增强线**（昵称解密 + 私信发送） | 需要 | 降级「只听不发」：`enable_send=False`，捕获记录仍入库 |

改动落点：
- `core/live_hook.py`：新增 `_has_credential()` / `_anon_live_info()` / `_anon_cookie()`
- `core/auto_dm.py`：4 个 `return` 改为 `_send_ok=False` 降级；`check_room_live` 支持匿名
- `dy_live/server.py`：`start_ws` 进房与 WS cookie 均支持匿名分支

## 踩坑（务必别重犯）

### 1. `DouyinAPI.get_live_info(auth_=None)` 会 AttributeError

该函数第 84 行 `cookies=auth_.cookie` —— **传 None 直接崩**。
我第一版实现就踩了（实测 `AttributeError: 'NoneType' object has no attribute 'cookie'`）。
正解：匿名路径**自建请求**（`LiveChatHook._anon_live_info()`），不要复用该函数。

### 2. `client_live.py` 是并发写者的文件 —— 叠加改动被撤回

`client_live.py` / `builder/params.py` / `utils/dy_util.py` 三处当时都有**未提交的
并发改动**（a-bogus 子域签名 `LIVE_HOST`，HEAD 里没有）。我一度在 `client_live.py`
上叠加了 ENG-017 的改动，发现后立即撤回（用字节级首尾标记定位，避免误删）。
**教训：动手前先 `git diff --quiet <file>` 判「是否 HEAD 就有」——**
`git diff --stat` 看到 M 不等于「是我的」。

### 3. 探针自身缺陷会伪造结论

诊断脚本连续踩 `sys.path` 路径算错、`room_id=None` 导致参数为空 —— 两次「匿名不通」
的结论都是假的。**探针返回意外值时，先验证探针绑定再怀疑被测系统。**

### 4. 反向验证必须做

`test_live_anon_decouple.py` 的 10 项全绿**不等于**它在守不变式。
实测：临时回退解耦（插回 `IDLE + return`）→ 立刻红 1 项 → 还原绿。
**这一步是「测试有效」的唯一硬判据。**
