# 案例：知识库语义检索开启 + 命中库通用性门槛 + 存量审计（v0.45.78）

- 日期：2026-09-28
- 关联：ADR-025、`services/ai_reply.py`、`services/reply_kb.py`、`services/reply_purify.py`、`api/ai.py`
- 前序：ADR-024（v0.45.77）遗留「未覆盖」三项 → 本案例逐项闭环

## 1. 起因（用户指令：「都处理」）

ADR-024 诚实标注的三项遗留：
1. `sem_enabled=False` ⇒ pro_kb 注入非相关性检索；
2. 命中库 81 条 auto 碎片（40 条仍生效）存量未清；
3. 断言护栏是形态匹配，非知识依据。

## 2. 取证（先测后改，全部真机 + 镜像根零写活库）

### 2.1 语义检索开关的实际影响

| 配置 | kb_mode | 注入条目 | prompt 字 |
|---|---|---|---|
| off（现状） | fallback_decay | 赔偿标准 / **流程与维权 / 常见疑问** / 赔偿项目 / 赔偿标准 | 3261 |
| on | semantic | 赔偿标准 / 赔偿标准 / 赔偿项目 / **评残依据** | **1303** |

embedding 链路体检：`ai_sem` 链 → `llama-nemotron-embed-vl-1b-v2`，**2048 维**（直连 31415
无 key 401 属正常；model_hub 带 key 成功）。⇒ 开语义**有益无害**（全相关 + 字数减半）。

### 2.2 发现的结构性漏洞：命中库**绕过出口护栏**

`_generate_reply`(L1628) / `generate_dm_for_live`(L1970) 对命中**直接 return**，不过 `validate_reply`。
库内可用条目含「能确定上九级吗？→ **你的伤情就是 9 级水平的**」⇒ **断言原件直发客户**。

### 2.3 命中库语义级沿用宽松阈值会**张冠李戴**

实采（29 条可用条目）：`陈旧性骨折还能认工伤吗` 在阈值 0.40 下命中
「工伤认定书还能销毁吗？」@ **0.502**（错）；0.55 起无命中（该库确无对应条目）。
⇒ 命中库「命中即回」风险等级远高于知识库 RAG，**必须独立开关 + 严格阈值**。

## 3. 决策与实现

| # | 决策 | 落地 |
|---|---|---|
| D1 | 开 pro_kb 语义 | `sem_enabled=True`（配置）|
| D2 | 命中库语义**独立开关 + 严阈值** | `reply_sem_enabled`(默认 False) / `reply_sem_threshold`(0.78)；`_sem_ready` 双开关 |
| D3 | 命中库通用性门槛 | `_entry_usable`：个案/寒暄/等级断言 → 失效（复用 `reply_purify` 判据，**单点**）|
| D4 | 存量审计（可逆） | `reply_purify.audit_legacy_auto` + `POST /api/ai/replies/audit_auto` → 移入候选区 |
| D5 | 断言护栏定位 | 形态护栏保留为「绊」；知识依据由 D3 + pro_kb 提供；**不**升级为 LLM 判别 |

## 4. 实机验证

- pro_kb 选条：off→on 全相关且 3261→1303 字。
- 命中库可生效条目：**40 → 29**（新门槛挡下 9 个案 + 2 断言；41 条原门槛已挡）。
- 审计干跑（镜像）：扫描 81 → **移出 52**（41 占位碎片 / 9 个案 / 2 断言）→ 候选区 52，正式库 29，**全可逆**。
- 门禁：`test_reply_kb_generality` **9/9**；合计 **42 项全绿**；前端 `npm run build` ✓。

## 5. 过程中的自我纠错（诚实记录）

- 自造了个案正则（含裸「伤」）→ 把「工伤怎么认定」误判个案，**测试当场抓住**（2 != 3）。
  改为**只复用** `reply_purify.is_case_specific`（单点判据），删除自造正则。
- 测试断言一度写错（2 条误记为 3 条）→ 按实际语义修正并加注释说明每条归属。

## 6. 未覆盖

1. 命中库语义级**默认关**（需人工确认库干净后再开）。
2. `audit_auto` 需**部署后手动触发**（未改写用户活库）。
3. pro_kb 语义缓存键与链实际模型名不一致（换模型需 `sem_cache_invalidate`）。
