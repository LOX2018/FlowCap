## 一、设计意图（Step 1）

凭证职责 = **「部分直播间昵称加密时的解密权」**；有解密权 ⇒ WS 帧下发真实
`uid/nickname/sec_uid`；无解密权 ⇒ 脱敏（`uid=111111` + 昵称 `三***` + `sec_uid` 空）。

**监听链路另一条独立契约**：`TaskConfig.live_url`（可能是分享/关注链接）必须先
**解析**成合法纯数字 `web_rid`；进房第一步不得因可选 cookie 缺失而中断。

## 三、执行链溯源（Step 3）

```
用户粘贴 https://www.douyin.com/follow/live/992931212705?anchor_id=…
  → api/engine.py POST /start(TaskConfig.live_url)
  → AutoDM.start()  (core/auto_dm.py:481)
       resolve_live_id(raw)
         ├─ _LIVE_RE     只认 live.douyin.com/<id>          ✗ 未命中
         ├─ 无 www.douyin.com/follow/live/<号> 识别           ✗ 未命中
         └─ reflow / 浏览器兜底 → 失败 → **except: live_id = 整段 URL**（静默兜底）
  → self.live_id = "https://www.douyin.com/follow/live/992931212705?anchor_id=…"
  → DouyinLive.start_ws → self._room_info_with_credential()

         → url = "https://live.douyin.com/" + 整段URL   ✗ 400/404
         → res.cookies.get_dict()['ttwid']              ✗ KeyError（无 ttwid 响应）

         → [LIVE-031] 匿名进房失败 HTTP 404
  → [LIVE-023] 进房失败 → 任务秒停「已停止」
```

## 四、根因分析（Step 4）

1. **静默兜底 = 故障隐藏层**：`except Exception: self.live_id = config.live_url`
   把「解析失败」当成「可继续」，于是一个**不可能成功**的 URL 被拿去进房。
   它吞掉了唯一的失败信号（用户看不到「链接解析失败」，只看到「已停止」）。
2. **快速路径覆盖面缺口**：抖音「直播页」有两类域名，`live.douyin.com/<id>` 被识别，
   而 `www.douyin.com/**/live/<id>`（关注/分享页）没有 —— 后者实测与前者**同源**
   （follow/live/992931212705 进房 room_id=7688251038101556006，逐字一致）。
3. **可选响应头被硬下标**：`res.cookies.get_dict()['ttwid']` 在无 ttwid 响应上抛
   `KeyError`，把「一个建连用设备级 cookie 缺失」升级成「整条进房链崩」。
