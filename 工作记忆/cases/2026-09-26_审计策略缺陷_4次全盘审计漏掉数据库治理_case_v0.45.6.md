# 审计策略缺陷：4 次全盘审计均未发现数据库治理问题

> 归档日期：2026-09-26 · 触发：用户原话
> 「这个项目我至少经历过 4 次全盘审计，都没有发现数据库治理的问题」
> 关联：ADR-012（数据契约三层治理）· 提交 `edca340`（v0.45.6）

---

## 一、结论先行

**不是问题太隐蔽，是审计策略缺了一个持久维度。**

4 次审计（含 3 份报告）的维度**全部是「代码结构」视角**，没有一个是「数据契约」视角。
其中**增量审（逐条 diff）是最致命的一类** —— schema 从未改动 ⇒ 天然不在视野。

> **核心命题：「没变化的危险」永远不会被增量审计发现。**

---

## 二、证据：3 份报告的维度实测

| 报告 | 维度 | 为何看不见 DB 治理问题 |
|---|---|---|
| 09-21 架构审计 | 入口分裂 / 分层依赖逆行 / 大组件行数 / 死面 | 不看「字段被几种语义混用」 |
| 09-23 一致性审计 | 符合项评分 / 跨模块耦合 / 技术债净增 | 同上 |
| 09-24 累积补丁审计 | 逐条 diff（45 条按 severity 判真假） | **增量审**：schema 从没改过 ⇒ 自然缺席 |

机械门禁同样如此：`check_iron_rules.py` R1~R6 全是**目录/文件卫生**
（数据根位置、版本齐平、明文凭证、不得 kill 浏览器），没有一条查字段语义。

---

## 三、修复：新增 R8「数据契约」为第八个持久维度

落盘 `scripts/audit_data_contract.py`，**委托**接入 `check_iron_rules.py`
（委托而非重写 —— 避免同一判据两套实现漂移，SSOT）。

| 判据 | 内容 |
|---|---|
| R8-1 | 写入出口收敛（dm_messages 不得裸写列名元组） |
| R8-2 | 类型注册表完整（出现的 msg_type 字面量必须已登记） |
| R8-3 | 语义字段纯度（text 不得承载 base64 / URL） |
| R8-4 | 语义标签 SSOT（禁业务文件硬编码 `[图片]`） |
| R8-5 | 前向兼容（未知类型必须降级 + 门禁在位） |
| **R8-6** | **同一语义不得多名字**（禁 `msg_type IN('a','b')` 并列） |

**R8-6 是本次根因的直击判据** —— 「同一语义两个名字」正是「字段无规划」的可测量形态。

## 四、R8 上线当天就抓出的两个真问题（自证有效）

1. **`msg_type='image'` 未登记** → 发送图片会被降级成 `kind=unknown`、
   text 变为 `[未知类型]image`。这是 **v0.45.5 引入的回归**（我加 Schema 时
   没想到这个别名）。已按**方案 B** 修：调用点统一 `"27"`，Registry 不收别名。
2. **`dm_search` 用 `IN('8','video')` 容忍不存在的别名** —— 实测
   **没有任何写入点**产生过 `msg_type='video'`，纯属防御性猜测。已移除，
   并给 `"8"` 登记为 `media`。

## 五、踩坑记录：审计工具造假红比漏报更危险

初版 R8 跑出 **4+3+1 = 8 处假红**，逐条核实后修正判据：

| 假红 | 原因 | 修法 |
|---|---|---|
| R8-1 ×4 | 正则不区分表，命中 `dm_conversations`（会话表，非消息表） | 先定位 `INSERT INTO dm_messages` 再在其后窗口内找元组 |
| R8-3 ×3 | docstring 里的格式说明（`data:image/webp;base64,<inline_pic>`）被当真实载荷 | 加 `_strip_comments()` 剥离注释与 docstring |
| R8-3 ×1 | `_extract_thumb_data_uri()` 产出的是 `extra.thumb`（给前端渲染），不写 text | 回溯上下文，命中 thumb 相关则跳过 |
| R8-2 ×1 | schema **注释**里提到历史别名 `image` 被当未登记字面量 | R8-2 也走 `_strip_comments` |

> **教训**：审计工具一旦制造假红，人会开始忽略它 —— 那时的门禁比没有更坏。
> 故每次新增判据必须**逐条人工核实命中行**，不能看红就信。

另：写负控正则时我曾**连续两次**被自己的断言骗（模式命中已修好那行本身）。
**负控正则必须锚定「行首缩进后紧跟 `(`」**，否则会把修好的代码判成没修好。

## 七、可迁移判据（给其它项目）

1. **审计维度清单必须显式维护**，且至少含一个**存量扫描**维度；
   纯 diff 审计必然漏掉「从未改动的危险区」。
2. **「同一语义多名字」是可机械测量的债务形态**（`IN('a','b')` / `OR` 并列），
   应作为常设判据。
3. **新增数据字段前先登记**，否则写入侧会自发产生别名 → 别名扩散 → 补丁式容忍。
4. **审计工具必须自带负控**（注入违规样本断言报红），否则只是装饰。
5. **假红逐条核实**，未核实的红 = 噪音 = 门禁被绕过的前奏。
