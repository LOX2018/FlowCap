## 二、两个真实踩坑（本轮新发现）

### 坑 1：后台 `terminal` 里的**超长多步 one-liner 会被 shell 打断**

首次构建命令把「mkdir + 三段构建 + 退出码捕获」全塞进一条 `&&` 链，
后台进程 `exit_code=1` 且**日志文件 0 字节**（连 `mkdir` 都没跑成），
但手动复现同一条 `mkdir -p ../../artifacts/build` **exit=0** —— 说明不是路径问题，
是那条超长命令串在该 shell 里中断。

⇒ **规则：多步构建写成 `.sh` 脚本文件再 `bash <script>`**，
每步 `S=$?; [ $S -ne 0 ] && exit` 短路，日志 `: > "$LOG"` + `>>` 追加。
（脚本形态还能复跑、能留档，比 one-liner 稳得多。）

### 坑 2：`npx vite build --config frontend/vite.config.ts` 从项目根跑必失败

```
error during build:
Could not resolve entry module "index.html".
```

根因：vite 的入口 `index.html` 解析**相对 cwd**，而 `index.html` 在 `frontend/`。

⇒ **规则：`vite build` 必须在 `frontend/` 目录下跑**（`cd frontend && npx vite build`），
不要靠 `--config` 指路径来跑；`tauri build` 则在项目根跑（它自己找 frontendDist）。
