> 「首先这些发送的话术有很大问题，部分弹幕已经说了骨折，生成回复还让别人说伤情。

## 1. 设计意图（Step 1：回归设计契约）

| 模块 | 设计契约（应然） | 违反的条款 |
|---|---|---|
| 直播首触话术 | 直播间观众只发了一句话 → **信息量不足以判等级** ⇒ 职责是**引导补材料**（部位/诊断/手术/省市/劳动关系），不是下结论 | 违反「无依据不得断言」（`_RE_ASSERTIVE` 的立论），且 Agent prompt 第 ① 条**主动要求**给等级口径 |
| 命中库 | 语义 = 「对方消息符合库内案例 → 直接回复」。契约隐含前提：**库内是经核实的通用话术** | 库内 28 条**全为 auto 学习碎片**，且它是**绕过全部出口护栏**的最短路 |
| 投递状态 | 「已发送」应能回答「服务端是否确认送到」（Live-Instance Verification Law） | `RecordStatus.SENT` 只表示**入池**，送达证据（M-5 标记）**从未回写调度记录** |
| 诊断层（弹幕列表） | 界面必须让**全部**已捕获记录可见（可观测性前提） | `slice(0, 12)` 硬截断且无纵向滚动 ⇒ 第 13 行起**永不可见** |

## 3. 执行链溯源（Step 3~4）

### 3.1 话术三处断点（沿 `generate_dm_for_live` 的调用图）

```
AutoDM._gen(target)                     core/auto_dm.py
  → ai_reply.generate_dm_for_live(...)  services/ai_reply.py
      ├─ ① reply_kb.find_match(text)     ← 断点 A：命中即 return，绕过全部护栏
      ├─ ② build_system_prompt(cfg)      ← 断点 B：与私信共用，规则方向相反
      ├─ ③ AIClient.chat_failover(...)
      ├─ ④ validate_reply(raw, cfg)      ← 断点 C：无场景判据（只查长度/违禁词/专业准确性）
      └─ ⑤ fallback_reply(cfg)           ← 断点 D：承接型话术，在首触场景像客服
```

**RCA**：不是「模型不行」。① 使**模型根本没参与**（原件直发）；② 使模型**收到相反的指令**；
③ 使「有依据的方向性口径」与「无依据的断言」在出口**不可区分**；④ 使最需要引导的时刻发出承接型空话。

### 3.2 送达缺口（沿发送链溯源）

```
core/dispatch.py:_do_send
  → dm_dispatch.submit_by_uid(...) → accepted=True（**已入池**）
  → rec.status = RecordStatus.SENT        ← 此处把「受理」写成「SENT」
  （真正送达证据在 recv_daemon 侧写 [投递验证] 标记，**不回写** dispatch.records）
```

**RCA**：两个口径（**调度受理** / **服务端送达**）在数据模型上**只表达了一个**
⇒ 前端无法区分。平台拒收回执（`msg_type='text'` 的 system_notice）落库了，
但**没有任何读侧把它关联到该条记录**。

### 3.3 弹幕列表（前端）

`live-page.tsx`：`{rows.slice(0, 12).map(...)}`，外层 `overflow-x-auto`（**横向**）
⇒ 纵向无滚动容器 ⇒ 第 13 行起不可达。

## 7. 可迁移判据（写入知识库）

1. **「短路径」必须单独审计护栏**：任何「命中即回 / 缓存直回 / 模板直发」的分支
   都绕过出口护栏。给出口加护栏时，先列全「最终外发文本的产生点」。
2. **共用 prompt 不能承载单场景约束**：场景规则要在**系统侧覆盖式追加**（放 last +
   声明覆盖），不要去改共用的用户资产 prompt。
3. **两个语义（受理/送达）不能只表达为一个字段**；缺口要么补字段，要么**不显示**——
   显示成另一个语义就是「假成功」（与 H-20 同族）。
4. **`msg_type='7'` 不是「我方发送」的指纹**：它是**双方共用**的类型码，
   判「我方外发」必须同时看 `role='me'`。
5. **同一对端两种 `conv_id` 方向并存**：解析对端一律走 SSOT `conv_identity.peer_uid`，
   匹配时两种规范形态都要覆盖。
6. **诊断层的硬截断 = 缺陷掩盖**：列表 `slice(0, N)` 且无滚动容器时，
   N 之后的记录既看不见也查不到（与「测不到的假绿」同源）。
