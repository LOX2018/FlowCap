## 1. 设计意图（Design-First）

**模块**：iLink（个人微信 Bot）入站长轮询 `_run_ilink`。

**设计契约（DbC）**：
- 前置：`getupdates` 在会话有效期内返回 `{ret:0, msgs[], get_updates_buf}`；会话过期时返回 `ret:-14`。
- 不变量：① 检测到 `ret=-14` 必须**停止**对过期 token 的持续轮询（不空轮询）；② 会话态（token/sync_buf/ctx）必须被**持久化清空**（重启仍清空，不自动续轮询）；③ 用户必须被明确告知「需重新扫码」；④ 不应 crash 退出（issue #6901）。

**预期行为**：iLink 会话过期 → 自动清会话态 → 重推二维码 → 用户扫码后自动恢复收消息。

**假设**：`ret=-14` 是 iLink 官方定义的「会话过期」语义（Open-Source Provenance 锚点，非推测）。

## 5. 根因分析（RCA）

**为什么在这一点断链**（非「在哪里报错」）：
原实现把 `getupdates` 的所有非 0 返回统一视为「瞬时/可重试错误」，忽略了 `ret=-14` 的**语义特殊性**——它是会话级失效（需重新登录），而非额度/参数错误（L-13 的 `ret=-2`）。两类错误被混在同一 `sleep(5); continue` 分支，导致：
1. 过期会话永不进入「重新登录」路径；
2. 用户侧零感知（被 L-13 preflight 的逻辑挡在门外，无独立提示）；
3. 过期 token 持续打流量（资源浪费 + 潜在风控）。

---

## 6. 修复（Fix）

**A. 重构 `_run_ilink` 为双层循环**（外层 token 生命周期 / 内层 getupdates）：
- 内层首轮响应判定：
  - `ret == -14` → 调 `_handle_session_expired()` → 置 `token="" sync_buf=""` → `break`（回到外层「无 token → 扫码」分支，**自动重推二维码**）；
  - 其它 `ret != 0` → 维持原 `sleep(5); continue`（兼容瞬时错误，不误清登录态）。

**B. 新增 `_is_session_expired(data)`**（独立可测）：只认 `ret == -14`（int 或 `"-14"` 字符串），**严格区别于 L-13 `ret=-2`**。容忍 `"-14.0"` 等形态；对 `None`/无 ret 字段/`0`/`-1`/`-2`/正数 `14` 一律返回 False（防误判）。

**C. 新增 `_handle_session_expired(cid, cfg)`**（独立可测，顺序至关重要）：
1. **先**发 critical 通知（`notifier.emit(level="critical")`）—— 此刻 `bot_token` 仍完好，可绕过 L-13 `preflight` 的 ctx 拦截送达「需重新扫码」；
2. `save_config_file` 持久化清空 `token`/`sync_buf`/`context_tokens`/`context_sent_counts`（重启仍清空）；
3. 同步内存态 `cfg` 的对应键（防本循环残留引用）；
4. KV `notify.ilink.session_expired` 标记 `need_rescan=True`（设置页展示）。

**决策（待你拍板项已定）**：采用设计意图的**自动重推二维码**路径（契合 H-30 远程登录主题），满足 issue #6901「不 crash / 不空轮询」。

## 9. 复用与教训（Institutional Memory）

- **「未证明会拒绝的门禁 = 假门禁」在本项目反复生效**：`_is_session_expired` 必须同时覆盖「-14 真」与「-2/无ret/其它ret 假」——只测前者会漏掉「把额度错误误判为会话过期」的对称缺陷。
- **顺序陷阱（后清 token 则通知被拦）**：critical 通知必须在清 token **之前**发出，否则被 L-13 preflight 的 ctx 拦截吞掉（假成功族教训）。
- **双层循环优于单循环 break 山**：把「token 生命周期」抽成外层后，「过期→重扫码」成为自然状态转移，不再需要在内层做复杂 goto 式重入。
- **`ret=-14` 与 `ret=-2` 语义不同**：
  - `-2` = 外发额度/参数错误（L-13，普通重试无意义但**会话仍有效**）；
  - `-14` = 会话过期（L-14，必须重新登录）。
  二者绝不能共用一个错误处理分支。
