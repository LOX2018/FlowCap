# 内容中心「播放视频时评论区一直刷新/加载不出」——末级链路分叉修复

> 案例类型: 前端链路分叉缺陷（非后端故障）
> 版本: v0.45.68 → **v0.45.69**
> 日期: 2026-09-28
> 触发词: 内容中心、评论区、一直刷新、加载不出、comments/full、采集页正常、末级链路分叉

---

## 1. 用户报告（原始症状）

> 「当选项目我的内容中心，播放视频显示的采集评论区一直在刷新状态，
> 而单独的采集页面，采集评论是正常的，需要进行移植」

用户当场给出**修复方向**（2026-09-28 追加指示）：
> 「不用做那么多测试了，**直接照搬一级目录**」

---

## 2. design_intent（设计意图）

| 项 | 内容 |
|---|---|
| 模块 | 内容浏览页（`platform-page.tsx`）播放器浮层右侧「评论区」（`comment-panel.tsx`） |
| 设计契约 | 点开作品 → 播放器取址 **与** 评论采集**并发**进行；评论展示后可对评论者手动私信 |
| 期望行为 | 评论在播放器打开后**一次性**取到并渲染（与「采集」页同一数据语义） |
| 设计假设 | ① 两页评论是同一件事；② 评论采集是「一级评论」这一超集/等价的读取 |

---

## 3. 偏差与定位（Execution-Chain Traceability）

### 3.1 枚举末级链路（关键取证：两页**不是同一个实现**）

| 维度 | 内容中心（异常） | 采集页（正常） |
|---|---|---|
| 组件 | `components/platform/comment-panel.tsx` | `components/crawl/crawl-page.tsx` |
| 前端取数 | `useQuery` → `platformApi.commentsFull(...)` | `useState` → `api.crawlComments(...)` |
| 端点 | `POST /api/platform/comments/full` | `POST /api/crawl/comments` |
| 基座方法 | `DouyinAPI.get_work_out_comment` 翻页 **+ 逐条串行 `get_work_all_inner_comment`（楼中楼）** | `features.work_comments()`（**一级评论**） |
| 实测耗时 | **27.9s**（`with_inner=true`；items=50 / inner=52） | **16.5s**（items=100） |
| 实测结果 | `ok=true`，数据正常 | `ok=true`，数据正常 |

### 3.2 排除项（避免误修）

- **后端两条链路都健康**（实测，账号「尚进工伤小助理」，作品 `7605486694263016719`）：
  - `/api/crawl/comments` → 16.5s / 31792B / 100 条 ✅
  - `/api/platform/comments/full`（`with_inner=true`）→ 27.9s / 33108B / 50 条 + 52 楼中楼 ✅
  - `/api/platform/comments/full`（`with_inner=false`）→ **8.3s** / 18062B / 50 条 ✅
- **楼中楼翻页无死循环**（定向微复现，取会员加密凭证真调上游）：
  - `cid=7610826333677962020`（reply_total=14）：游标 `0→5→10→15→20` 正确推进，4 页终止 ✅
  - 基座 `get_work_all_inner_comment` 的 `while True` **未被触发空转**（服务端 `has_more` 会归 0）。
- **不涉及的风控面**：与 BCC/昵称红线无关；昵称仍只取评论自带字段。

### 3.3 根因（RCA）

**末级链路分叉**：同一业务（取一个作品的评论）在项目里存在**两条不同实现**。
内容中心那条多了「逐条串行补楼中楼」这一**放大链**：
- 耗时随一级评论数线性增长（N 条 → N 次串行网络往返）；
- 叠加播放器取址（`media/stream-ticket`）并发执行；
- 浏览器侧长时间拿不到可渲染数据 ⇒ 用户观感即**「一直在加载 / 一直刷新」**。

> 这正是「同一业务重复触发」类体系缺陷的又一实例：分叉的最后一公里
> 与其余环节截然不同（`crawl_*` 走 `features` 封装，`platform` 走直连基座）。

## 4. 修复（用户决策：照搬一级评论实现）

**改动范围：仅前端 2 个文件 + 版本号；后端零改动。**

- `frontend/src/components/platform/comment-panel.tsx`
  · 数据源由 `platformApi.commentsFull(with_inner=true)` 改为 `api.crawlComments()`
    （与采集页**同一端点、同一字段契约**：`cid/text/nickname/uid/ip/digg/ts/replyTotal`）；
  · 移除 `useQuery` + 楼中楼渲染分支（本页诉求是「播放时同屏看评论并可私信截流」，
    楼中楼非其诉求）；
  · 保留「挂载即取、与播放并发」语义；保留风控红线（昵称只取自带）与
    D1（仅手动点按发私信，无自动/批量）；
  · 失败态如实呈现（采集失败 ≠「暂无评论」），并新增手动「刷新」按钮。
- `frontend/src/components/platform/platform-page.tsx`
  · 挂载点补传 `api={props.api as never}`（评论组件改由采集 API 取数）。

**未改动（保守）**：后端 `/comments/full` 及其 `commentsFull` 客户端定义**保留**
（ADR-018 F3 记录在案、可能有楼中楼用途），**不删除**，以免越权改动他人在建能力。
