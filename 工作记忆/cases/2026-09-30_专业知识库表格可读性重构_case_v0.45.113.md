# 专业知识库表格可读性重构

- **日期**：2026-09-30
- **版本**：v0.45.112 → v0.45.113
- **提交**：`ad4e19c`
- **触发**：用户截图反馈「专业知识库的表格分布太丑了」

## 一、问题诊断

用户截图显示专业知识库表格存在以下布局问题：

| 症状 | 根因（源码定位） |
|---|---|
| 主题/子分类/总结列硬切无省略号 | 单元格用 `<input>` 单行框，超长横向裁掉 |
| 正文只显示 2-3 行被垂直裁 | `<textarea rows={2}>` 固定行数 |
| 正文右下角有拖拽柄却拖不动行高 | `resize-y` 暗示可拖，实际行高由表格行约束 |
| 每行都有绿线 = 视觉噪声 | `borderTop` 只加在第一个 `<td>` 上，且单行组也画线 |
| 6 列无分隔线、没列感 | 表头无 `border-l`，行无 `border-l` |
| 操作列 64px 只放一个"删" | 列宽分配没按信息密度走 |
| 行内基线不齐 | 正文顶对齐、短文本 input 居中 |

## 二、设计约束（知识库 §8.1）

- 前端**只有表格视图**，树是后端数据视图，前端不渲染
- 单元格直接编辑 = 改树（`onBlur` → `PATCH /api/ai/prokb/{id}`）
- 不加视图切换，不破坏上述两个不变量

## 三、修复方案

### 3.1 单元格：`<input>` → 自适应 `<textarea>`

新增 `AutoGrowCell` 组件：
- `useLayoutEffect` 自动撑高（`scrollHeight` → `height`）
- 空闲时无框（`border-transparent`），聚焦才显框
- `maxRows` 参数控制上限（正文 5 行，其余 3 行），超出转内部滚动
- 去掉 `resize-y`（消除"能拖却拖不动"的假承诺）

### 3.2 分组线：整行 + 仅成组时绘制

- 统计同主题行数（`topicCount` Map）
- `borderTop` 从 `<td>` 移到 `<tr>`（`border-t-2 border-t-[var(--color-accent)]`）
- 仅 `r._groupSize > 1` 时才画（单行组不画线）

### 3.3 网格线：恢复浅色分隔

- 表头 `border-b` + `border-l`
- 行 `border-b` + `border-l`
- 全部走 `var(--color-border)`，深浅主题自适应

### 3.4 列宽：按内容密度重新分配

| 列 | 旧宽 | 新宽 | 理由 |
|---|---|---|---|
| 主题 | 130 | 136 | 长标题需更多空间 |
| 子分类 | 110 | 132 | 部分值被截断 |
| 总结 | 190 | 240 | 几乎每行都截断 |
| 正文 | 弹性 | 弹性 | 吃余量 |
| 状态 | 96 | 84 | 只需放"命中N" |
| 操作 | 64 | 56 | 只放一个"删" |

### 3.5 对齐：统一 `vertical-align: top`

所有 `<td>` 加 `align-top`，消除行内基线不齐。
