## 4. 真机复验暴露的两个新缺陷（v0.45.76 引入）

### 缺陷 A：截断后未复核 → 残句泄漏（AI-066）

- **现象**：真实 DM 链路问「陈旧性骨折还能认工伤吗」→ `[AI] 很难`（2 字外发）。
- **trap**：单独调 `validate_reply("很难")` **确实拦截**，故初看像"护栏正常"。
- **根因**：`validate_reply` 里 `min_reply_len` 检查在**截断之前**；`max_reply_len`
  截断（取第一句）在**之后**且**未复核**。长回复若首句极短（「很难。陈旧性骨折要…」），
  截断后**又变成残句**外发。**post-condition 与实际外发文本解耦**。
- **确定性复现**（零网络）：
  `validate_reply(("很难。"+ "陈旧性骨折要证明…"*4))` → 输入 65 字 → 输出 `"很难"`（2 字）。
- **修复**：截断后复核 `len(reply) < min_len` → 返回 None 走兜底（记 AI-066）。
  回归固化：`TestTruncationResidualGuard`（负控 + 正控）。

### 缺陷 B：断言正则过宽 → 误伤正确回答（AI-065 误报）

- **现象**：AI 一条**很专业**的回答被拦成兜底 →
  「先认工伤，才能评残。**旧伤能不能认**，看的是**证据链**，不是医院那张片子。」
- **根因**：`_RE_ASSERTIVE` 第 2 条 `(能认|…)…(陈旧性骨折|旧伤)` 中，`能认` 是
  **「能不能认」的子串** → **疑问句被当断言**。正则不区分疑问/陈述。
- **修复**：改为只匹配**陈述式断言** —— 肯定词前 `(?<![不否])`、尾部 `(?!(吗|呢|？))`；
  删除"肯定词在前"的第二方向。正控补入**实测误伤原文**。
