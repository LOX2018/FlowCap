# 案例 · ENG-020：同一机制下「尚进正常 / 张老师失败」的根因（v0.44.25）

> 日期：2026-09-21　分支：`design/better-douyin`　环境根：`C:\temp\dyautodm_design`
> 用户原话：「目前选用张老师进入 live.douyin.com/992931212705?camera_id=0 直播间依旧昵称依旧是加密态！」
> 及关键质询：「**为什么同一个机制小助理正常，但张老师失败**」——本案例即对该质询的回答。
> 前置：`2026-09-21_凭证自锁根治_会话活性门禁_v0.44.23.md`（只修了一半）
> 证据：`artifacts/证据_2026-09-21_直播弹幕脱敏_帧级对照.md`

## 一、结论（直接回答质询）

**不是「账号有没有权限」的区别，而是「谁的容器被 wp_recv 钉在 `/chat`」的区别。**

- `main.py` 只给 `list_accounts()[0]`（实测 = **尚进**）起 WP 接收循环，
  而 `capture_wp_messages()` **每次调用都把该容器的主 page 导航到 `/chat`**。
- ⇒ 尚进容器**每 3 秒被导航一次**，永远停在 `/chat` → 其页面级探针正常 →
  保活回写正常运行（`保活回写成功` 全量 52 次全是尚进）。
- ⇒ 张老师容器**无人驱动** → 页面停在自己最后所在页（`places.sqlite` 实证：
  最后访问 `www.douyin.com/jingxuan`）→ 页面级探针经 `exec_js` 触发
  `goto('/chat')` → 在重 SPA 页上**挂满 25.0s 超时**（日志实证：14:57:00→14:57:25…）
  → 返回 `{}` → 被判「页面级登录态失效」→ `cred_mode=observe` ⇒ `continue`
  ⇒ **保活回写分支永不进入** ⇒ `.env.enc` 凝固在坏会话（mtime 停在 13:04）
  ⇒ 引擎 WS 用它 ⇒ 服务端不承认 ⇒ **帧/接口全体脱敏**（`uid=111111`）。

### 「单例」假设早已过期（代码病根）

—— 该假设成立于 2026-09-05，但 **2026-09-20（`81b5cfa`）Camoufox 已改为
每账号独立容器 + 独立端口**（张老师 10042 / 尚进 11231）。代码没跟着改。

## 三、根因链（三层，全部实证）

```
① main.py 只驱动 list_accounts()[0] 的 wp_recv
        ↓ （每 3s 一次 /wp_messages）
② capture_wp_messages / exec_js 在「主 page 不在 /chat」时直接 goto('/chat')
        ↓ （观测动作产生了「改写被观测页面」的副作用）
③ 张老师容器停在重 SPA 页 → goto 挂满 25.0s 超时 → 页面探针返回 {} →
   回写分支被 continue 跳过（**回写被错绑到页面证据上**）
        ↓
④ .env.enc 凝固坏会话 → 引擎 WS 用它 → 服务端不承认 → 帧/接口全体脱敏
```

## 四、修复（v0.44.25 / ENG-020，四层一起根治）

| # | 改动 | 位置 |
|---|---|---|
| 1 | WP 接收循环**遍历全部账号**（与「每账号独立容器」对齐） | `main.py` |
| 2 | 新增统一原语 `_ensure_nav_tab()`：观测取数一律走**独立导航 tab**，主 page 不动；`exec_js` / `capture_wp_messages` 均改用它（沿用 `resolve_url` 2026-09-06 先例） | `daemon/browser_daemon.py` |
| 3 | **凭证回写与页面证据解耦**：`_sync_env()` 在「uid 有效」与「uid 空」两分支均**无条件**调用；页面 `conv` 判据降级为「页面操作可用性」，不再充当回写前置 | `daemon/browser_daemon.py` |
| 4 | 页面探针**三态**：取不到证据返回 `{"unknown": True}`（不再返回 `{}`），不得折成「页面失效」 | 同上 |
| 5 | 新错误码 `BCC-073`（页面级探针无证据） | `errcode_data.py` |

### 不变式（守卫测试钉住）

1. 页面探针取不到证据 ⇒ `unknown`，**不得**折成「失效」。
2. 回写 `.env` 的依据是**账号级** `live_session_state`（门禁 1.5/1.6 自证），
   **与页面位置无关**。
3. 观测动作**不得**改写被观测页面的位置（无主 page `goto`）。
4. WP 循环必须覆盖全部账号。
5. 门禁 1.6 仍有效：会话确未被承认时**绝不写盘**。

## 六、判据（可直接复用）

1. **脱敏判据 = `uid == 111111` 且 `sec_uid` 为空**。
   `desensitized_nickname` / `is_anonymous` / `mystery_man` **全不可作判据**
   （实测 A/B 两组 `desensitized_nickname` 都非空且等于各自昵称；`mystery_man` 三组恒为 1）。
2. **「有 cookie」≠「有解密权」**。
3. **三类失效互不代替**：身份一致性（`query/user`）/ 会话活性（`profile/self`）/
   页面操作可用性（`conv` 等 DOM 判据）。把它们串成一条链，任一环抖动即全链停摆
   —— 本案就是把第 3 类绑成了第 2 类的前置条件。
4. **同机制下 A 正常 B 失败 ⇒ 先找「环境/驱动差异」，不要先怀疑账号权限**
   （本次差异 = `list_accounts()` 下标）。
5. **观测不得有副作用**：任何「读一下状态」的动作，不得改变被观测对象的位置/形态。
