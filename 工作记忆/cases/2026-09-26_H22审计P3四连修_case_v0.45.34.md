## 1. P3-① `client_live.py` — REST `browser_version` 字段类型不一致（idx10）

### 设计契约（ADR-016 D4）
「同一浏览器身份**单一来源**」：出站浏览器身份字段一律取档案（内核感知）。
`browser_version` 的语义是**短版本号**（如 `"152.0"`），全仓 REST 参数 **30+ 处**
统一取 `get_profile()["browser_version"]`。

### 根因（**自我引入的反向不一致**）
`client_live.py:379` 上一轮 ADR-016 修复把「硬编码旧 Chrome UA」替换成了
`get_profile()["ua"]` —— **完整 UA 串**（`"Mozilla/5.0 (Windows NT 10.0; ...) Firefox/152.0"`）。
而该字段在**同一文件 250 行**及全仓 30+ 处都是短版本号 ⇒ 同一请求内自相矛盾。
**审计意见精准命中**：这不是「漏改」，是「改错方向」。

### 修复与订正
回改为 `get_profile()["browser_version"]`（短版本号）。

> **订正要点**：`builder/proto.py:53` 确实把「UA 去掉 `Mozilla/`」当作 `browser_version`
> —— 但那是 **IM protobuf 的独立约定**（客户端 `navigator.appName/appVersion` 语义，
> 见该处注释 L49-51），**REST 参数不适用**。判定：**REST 短版本号 / protobuf UA 语义**，
> 两套并存是既定设计，不是不一致。此处仅修 REST 一侧。

### 验证
门禁 G1 断言「不得取 `["ua"]` + 必须取 `["browser_version"]`」（负控判红）。

## 2. P3-② `link_resolve.py` — `_reflow_resolve` 出站 UA 缺省硬编码（idx13 + idx13相关）

### 设计契约
ADR-016：本文件出站 UA **一律走档案** `_ua()`（内核感知）。文件内 L113/L235 已统一。

### 根因
`_reflow_resolve(room_id, sec_user_id, auth=None, ua="Mozilla/5.0")` —— 缺省值仍是
**硬编码 UA**；该 `ua` **同时进入 X-Bogus 签名 payload（L162）与请求头（L168）**；
**唯一调用点（L251）未覆盖该缺省值** ⇒ 本函数的出站身份与档案不一致（含签名），
恰是 ADR-016 要根除的「同一账号不同链路不同身份」。

### 修复
签名改 `ua=None`，函数体首行 `ua = ua or _ua()` —— 显式传入仍可覆盖，缺省即与全文件一致。

### 验证
门禁 G2 断言「签名 `ua=None` + 函数体回落 `_ua()` + 无硬编码 UA 缺省」（负控判红）。

## 3. P3-③ 前端 — 取流失败无重试入口（idx22）

### 设计契约（既有的降级范式）
同项目 `AuthedVideo`（`authed-video.tsx:100-108`）取流失败时展示原因 +
**重试按钮**；`AuthedImg` 有 `onError` 降级。**失败必须可恢复，不能只作死提示。**

### 根因（两处叠加）
1. `player-media-stage.tsx:66` 把取流失败（`resolvedUrl === null`）折叠为 `url: ""`，
   落到 L192-199 分支显示「无可播放地址」—— **无任何重试控件**。
2. `authed-media.ts` 的**负缓存**（`FAIL_TTL_MS = 30_000`）命中时直接返回 `null`，
   组件不重取 ⇒ 令牌瞬时过期或后端暂不可用时，用户**必须重开播放器**才能恢复。

### 修复
- `useAuthedMediaUrl(src, bust = 0)` 新增 `bust` 参数：`bust > 0` 时**先清该 src 的负缓存**
  并回收旧 objectURL，再重取 ⇒「点击重试」立即生效，不被 30s TTL 挡住。
- `player-media-stage.tsx` 失败分支：文案改「视频已解密但取流失败」（与 `AuthedVideo` 一致），
  补**重试按钮**（`setFailed(false)` + `retryRef.current = 0` + `setBust(n => n+1)`）。

### 验证
门禁 G3 断言「失败分支有 `setBust` + 重试文案 + `useAuthedMediaUrl` 接受 `bust`
+ 重试清 `failCache`」；且 **`npm run lint`（`tsc --noEmit`）通过**。

## 4. P3-④ `repair_conversation_identity.py` — 退化分支误伤合法对端头像（idx24）

### 设计契约
脚本对**污染态/占位态**行做订正；项目为此专门计算了 `av_polluted`（L121）作为
「头像可否覆盖」的判据。**真值永不覆盖。**

### 根因（判据被弃用）
L126-129 退化分支（「本号身份冒充且无真值 → 退化裸 uid」）**无条件**把 `new_av = ""`；
而写库 L180-186 的 `WHERE` 只约束 `peer_name` 形态、**不约束 `avatar`** ⇒
当**仅昵称**属本号身份、而 `avatar` 是**合法对端头像**（`av_polluted=False`）时，
会把该有效头像一并写为 NULL —— **为头像专门算出的 `av_polluted` 在此分支被弃用**。

> 限制（审计自述）：需同时满足「IDB 无该对端真值」+「昵称=本号昵称」+「头像为合法值」，
> 属**代码层可发生缺陷**，不必然已发生。

### 修复
按 `av_polluted` 保护：`_na = "" if av_polluted else old_av`，写库用 `_na`。

### 验证（**行为验证，非仅静态**）
真跑脚本 `main(--apply)`，两组对照：

| 场景 | 输入 | 旧行为 | 新行为 |
|---|---|---|---|
| **S1** 合法对端头像 | `avatar=peer.jpg`（av_polluted=False） | 擦成 NULL ❌ | **原样保留** ✅ |
| **S2** 本号头像（污染） | `avatar=self.jpg`（av_polluted=True） | 清空 | **清空**（判别力）✅ |

两场景昵称均正确退化为裸 uid ⇒ 回退语义无回归。
（harness 需 `row_factory = sqlite3.Row` 以匹配真实 `get_db()` 的行访问方式。）

## 7. 教训（写入）

1. **「替换硬编码」不等于「用对字段」**：上一轮把 `browser_version` 从硬编码 UA
   换成了 `profile["ua"]`，字段名与值形态不匹配 ⇒ 制造了**新的**同类不一致。
   **替代值必须与字段语义（而非仅「非硬编码」）对齐**。
2. **同名字段在不同协议层可以有不同语义**：REST 的 `browser_version`（短版本号）与
   IM protobuf 的 `browser_version`（`navigator.appVersion`，含 UA）是**两套既定约定**；
   修不一致前先确认所在协议层，别把「跨层差异」当「不一致」。
3. **热缓存/负缓存旁的「失败态」必须有手动突破路径**：任何带 TTL 负缓存的失败分支，
   若不给用户一个立刻重取的入口，用户唯一出路就是重启组件 —— 降级范式必须配重试。
4. **为自己算出的判据必须在所有分支都用上**：`av_polluted` 算了却在一个分支弃用，
   等价于没有。**判据一致性**（同一谓词在所有决策点结论相同）是防御性脚本的基本功。
5. **脚本类改动的验证要真跑 `main()`**：静态 grep 只能证明「代码长什么样」，
   证明不了「写库后数据变成什么」。本次用真实 sqlite + 双场景对照坐实了行为。
