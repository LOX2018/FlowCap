## 1. 设计意图（Step 1：回归设计契约）

直播页的「发送弹幕 / 点赞」是**直播域写接口**，设计契约要求：

| 项 | 契约 |
|---|---|
| 端点 | `POST /api/live/danmaku`（发弹幕）、`POST /api/live/like`（点赞，本轮新增） |
| 上游接口 | `/webcast/room/chat/`（GET）、`/webcast/room/like/`（POST form），均在 `live.douyin.com` |
| 房间号 | 必须是**真实 room_id**（前端 `room_id_str`），**不是 URL 短号** |
| Origin / 证书 | 必须按 **`live.douyin.com`** 生成（上游 `sendMsgInRoom` docstring 明文） |
| 成败判据 | 上游 `status_code == 0`；其余一律失败（**不报假成功**） |
| 风控 | 写接口触红线 ⇒ **非必要不主动互动**；本项目原则是「用户显式选择」 |

## 2. 当前状态（Step 2：观测到的偏差）

用户报「发送弹幕和点赞异常」。实测（读代码 + 实测样本）得**四个**偏差：

| # | 偏差 | 证据 |
|---|---|---|
| ① | **点赞在前端是空壳** | `live-page.tsx:388` `const doLike = () => push("功能开发中：点赞")`；`doBatch` 同理；后端**根本没有** `/api/live/like` 端点 |
| ② | **弹幕不带 account** | `client.ts:sendDanmaku` 只发 `{content}` ⇒ 后端回落「当前账号」；多账号时可能用错身份 |
| ③ | 🔴 **房间号形态错（真根因）** | `link_resolve.resolve_live_id` 文档契约：「返回的 live_id 即为 **web_rid**（真实直播间号）」；而 `/webcast/room/{chat,like}/` 要 **真实 room_id**。实测同一房间两套标识：`follow/live/992931212705` 进房 `room_id=7688251038101556006`（见 `12_业务域_直播监听.md` §10.2） |
| ④ | 🔴 **点赞用主站 Origin 且无 bd-ticket 证书** | `client_live.py:578` `headers.set_header("origin", DouyinAPI.douyin_url)`；而同一上游的 `sendMsgInRoom` 明文写明必须用直播域 Origin（ADR-004 §4 已登记为「E 线同族残留」） |

### 3.2 再回溯本项目链路

```
前端「发送弹幕/点赞」
  → POST /api/live/{danmaku,like}
  → _room_id_for() ← kv config.live_id
  → 🔴 该值是 web_rid（link_resolve 只产 web_rid）
  → DouyinAPI.{sendMsgInRoom,diggLiveRoom}(auth, room_id=<URL短号>)
  → 🔴 上游业务失败；且响应里没有可读错误码（safe_json 降级为 {}）⇒ 静默失败
```

## 4. 根因（Step 4）

1. **两套「房间号」标识在链路里被混用**：解析层（`link_resolve`）契约只保证 **web_rid**，
   写接口只认 **room_id**，中间**缺一层显式归一化**。⇒ 上游静默失败
   （本地表现为「发了没反应」，不是报错）。
2. **点赞继承了主站 Origin 且缺 bd-ticket 证书**（上游明文否定该形态）。
3. **能力缺口**：点赞在后端**从未实现**，前端是「功能开发中」空壳。
4. **缺少「用户是否想要」的显式选择**：写接口只要凭证齐备就无条件外发 ⇒ 触风控
   （违反用户「显式配置原则」）。

**不是上游改接口**（§3.1 已证）；**不是凭证失效**（凭证链路本轮未动、既有测试全绿）。

### 5.1 🔴 实现期踩坑（门禁抓到的**真实缺陷**）

`count` 校验初版写 `int(body.count or 1)` —— `0` 是 falsy，被 `or 1` **静默吃成 1**
（用户传 0 却发出 1 次点赞）。门禁 `test_live_write_gates` 当场报红。
改显式三态：`None`（未传）⇒ 默认 1；其余一律 `int()`，非法 ⇒ 0 ⇒ 走拒绝分支。
⇒ **「越界显式拒绝、不静默夹取」必须写成代码而不是注释。**

另一处踩坑：D7 断言初版用 `assertNotIn("DouyinAPI.douyin_url", body)`，被**我自己写的
docstring 对比说明**触发（注释里出现了那个旧写法）——正是「守卫测试必须断言机制，
且注释里也不能留旧写法」那条铁律。改为剥掉 docstring 后只断言代码体。
