# 2026-09-18 · 登录门控循环依赖（卡「正在唤醒后端引擎」）修复 · v0.43.90

> 提交 `dc2184b` · 守卫测试 `backend/test_frontend_login_gate.py`（4/4 通过）
> 症状（用户原话）：「桌面端卡加载页面」→ 细化确认：**一直卡在「正在唤醒后端引擎」转圈，没有登录框**

## 一、根因：登录门控依赖了需鉴权的接口（循环依赖）

```tsx
// App.tsx —— v0.43.44 (ef3d31f) 引入
const { data: overview, isSuccess: ready } = useQuery({
    queryKey: ["overview"], queryFn: () => api.getOverview(),  // ← /api/overview 需登录
    refetchInterval: 3000,
});
...
if (!memberName) {
    if (!prealigned || !ready) return <BootSplash/>;   // ← ready 恒 false ⇒ 登录框永不可达
    return memberChecked ? <MemberGate/> : <BootSplash/>;
}
```

```
未登录 → /api/overview 401 → ready 恒 false → 登录框不渲染 → 无法登录 → 死循环
用户可见：只有「正在唤醒后端引擎」，永远等不到登录框
```

**正解依据（不是猜的）**：`/api/ready` 的 docstring 原文——
> 启动就绪度探针（免鉴权，前端 BootSplash 轮询）。
> 返回 backend 连通 + 账号基础设施状态。前端等 `daemons_ready=true` 才显示登录框
> —— 实现「前后端先对齐，登录后立即能用」。**内部已分未登录/已登录两条分支。**

⇒ 登录框就该认 `prealigned`（来自免鉴权的 `/api/ready`）；
`ready`（overview）只能用于登录**后**的业务 UI 与顶栏引擎状态。

## 三、为何 v0.43.44 当时验证「通过」却没暴露（最重要的一条教训）

v0.43.44 的 commit message 写着「[Live Verification]」，但**当时会员会话有效**
（`.session.json` 未过期 → 自动登录）→ `/api/overview` 成功 → `ready=true` →
登录门控看起来完全正常。

**只有「会话过期」或「首次安装（无会话）」这两条路径才会暴露此 bug。**

⇒ **规则：门控/守卫类改动必须把「被守卫对象处于不利状态」作为独立用例走一遍。**
修「用户要先能进来」这类逻辑时，测试环境必须**先让用户处于未登录态**，
否则测的只是「已经能进来的人能不能进来」——同义反复。
（与本仓既有教训「假成功族」「只测顺利路径」同源。）

**更强的地方**：这个缺陷是**静态可查的**——门控条件里引用了一个已知需要鉴权的
接口结果。故本次固化成自动化守卫（见下），不依赖人工记得测不利路径。

## 五、配套技术要点

### 版本递增：只改前端也必须重打 sidecar（否则全站 401→409 风格拒绝）
`main.py` 的版本中间件比对 `X-App-Version`（前端）与 `APP_VERSION`（sidecar 内嵌
`_build_version.py`），不一致即**拒绝全部 `/api/*`**。
「本次只改前端」≠「不用升版本」——升了前端就必须**同步重打 sidecar**
让编译期常量跟上。五处同步：`package.json` / `frontend/package.json` /
`tauri.conf.json` / `Cargo.toml` / `_build_version.py`。

### 抓「被遮挡的应用窗口」的正确姿势
`CopyFromScreen` 只截屏幕最上层，应用被浏览器挡住时**截不到它**。
改用 Win32 `PrintWindow(hwnd, hdc, 2)` —— 直接让窗口绘制到内存 DC，**不受遮挡影响**：
```powershell
[Cap]::GetWindowRect($h, [ref]$r); $bmp = New-Object Drawing.Bitmap ($r.R-$r.L), ($r.B-$r.T)
$g = [Drawing.Graphics]::FromImage($bmp); $hdc = $g.GetHdc()
[Cap]::PrintWindow($h, $hdc, 2)      # flag=2 = PW_RENDERFULLCONTENT（含 WebView 内容）
```

## 六、写入非法字节的坑（本轮自身踩到，已修）

用 Python 构造多行中文字面量做字节替换时，两处 `\xef`（全角标点首字节）被误写成
`\xff`，导致 `App.tsx` **整体 UTF-8 解码失败**。
- **发现方式**：写入后 `raw.decode('utf-8')` 报错（行尾 `\xffbc88` = `（` 的错编码）
- **风险**：这类损坏若没被拦住，前端会**直接构建不过或页面白屏**
- **修法**：`git diff --numstat` 确认改动行数正常（未整文件损坏）→ 定点修字节 →
  复验整体解码 + `npx tsc -b`
- **已固化为守卫**：新测试第 1 项就是「App.tsx 必须能无替换地解码且不含 U+FFFD」

⇒ 规则：**用 Python 写含中文的源码文件后，必须立刻 `decode('utf-8')` 自检**，
并核对 `git diff --numstat` 的行数是否符合预期（防整文件损坏被当成"改了"）。
