### 1.2 版本三代并存（定性混杂）

```
0.43.x   946 次   ← 中期（最大量）
0.44.x   301 次   ← 近期
```

## 四、根因分析：为什么会累积成这样

### 4.1 写入模式的问题

```
当前模式（现场描述式）：
  遇到问题 → 描述现场 → 追加进库 → 问题解决
                               ↓
                    新方案进库，旧方案**仍在库内**
                               ↓
                    下次 debug 搜到两套（旧的先命中，因为量更大）
                               ↓
                        被带回错误方向

应有模式（世界模型式）：
  遇到问题 → 判断「是世界变了还是代码错了」
           → 更新**假设基线**
           → **替换**旧定性（旧定性出库/进 cases）
```

### 4.2 三层分层的纪律未被遵守

库规范定义了三分（`工作记忆/` 现役 · `cases/` 历史 · `上游溯源/` 外部情报），但实测：

- `cases/` 的内容被大量抽进 `工作记忆/` 与 wiki 各层 → **历史现场混入现役知识**
- 结果：`工作记忆/` 不再是「全部当前有效」

### 4.3 缺失第一性文档（用户指出的根因）

全库 **839 页**，全部是「具体问题的具体描述」，**没有一页回答**：

> - 这是爬虫不是业务系统，意味着什么？
> - 契约会漂移时，debug 的第一个动作应该是什么？
> - 什么算"成功"？

没有这层，**每一页都只能是"当时对"**，无法被判定是否仍然有效。
→ 这正是「越积越乱」的结构性原因，**已补 `00_爬虫项目说明.md`**。

### 执行顺序理由

**S1 必须先做**（否则 S2-S5 完成后新内容又会按老模式堆积）。

## 六、测量口径（可复跑）

```python
# 陈旧信息命中
import os, re
WIKI = r"D:\文档\Biancheng   CK\DY v3\DY v3\wiki"
pages = {}
for dp,_,fs in os.walk(WIKI):
    for f in fs:
        if f.endswith(".md"):
            p = os.path.join(dp, f)
            pages[os.path.relpath(p, WIKI)] = open(p, encoding="utf-8", errors="replace").read()

for name, pat in {
    "fingerprint-chromium": r"fingerprint-chromium|vb_chromium|ungoogled",
    "im/user/info 被动hook": r"im/user/info|被动\s*hook|capture_userinfo_map",
    "移屏外":               r"window-position|移屏外",
}.items():
    hits = [r for r, t in pages.items() if re.search(pat, t, re.I)]
    print(name, len(hits), "页")

# 重复页对（规范化标题）
import collections
g = collections.defaultdict(list)
for r in pages:
    b = re.sub(r'^[\d\-]+', '', os.path.basename(r)[:-3])
    b = re.sub(r'--[a-z0-9]{6,}$', '', b).replace("-", " ").replace("_", " ")
    g[re.sub(r'\s+', ' ', b).strip().lower()].append(r)
print("重复组:", sum(1 for v in g.values() if len(v) > 1))
```
