## 三、主题系统（**曾有断链，已修复**）

`theme/ThemeContext.tsx` 通过 `<html>` 属性驱动样式，**取值必须与 CSS 选择器字面一致**：

| 属性 | 取值 | 说明 |
|---|---|---|
| `data-theme` | `"aerospace"`（默认深色）/ `"day"`（浅色） | ⚠️ **不是 `"light"`** |
| `data-glass-frost` | 存在 = 强磨砂；缺省 = 轻磨砂 | |
| `data-...` 主色 | JS 写 CSS 变量 | 见 §七 的变量名铁律 |

### 🔴 删除旧 CSS 暴露的三处断链（教训）

旧 `theme-glass.css` 里定义了 `[data-theme="day"]` 与 `[data-glass-frost]` 的整套规则，
**删除文件后主题系统静默失效**——因为 JS 的属性选择器引用不在任何 `className` 扫描里。

修复（现都在 `tokens.css` / `accents.ts`）：

1. `tokens.css` 补 `[data-theme="light"], [data-theme="day"]` 双选择器（兼容历史写法）
2. `tokens.css` 补 `html:not([data-glass-frost]) .glass-premium { backdrop-filter: blur(14px) }`
3. `accents.ts` **双写**两套变量名（见 §七）

**实机判据**：切 `day` → 底色 `#f5f5f7`；切回 `aerospace` → `#0e0e14`。

## 七、🔴 变量名双写铁律（本轮踩坑）

**问题**：`theme/accents.ts` 用 `setProperty` 写的是**旧变量名**（`--accent` / `--accent-bg`），
而重设计后的组件读**新令牌名**（`--color-accent` / `--color-accent-soft`）。
→ 用户改主色，界面**不变**（写进无人读的变量）。

**处置**：`accents.ts` 现**同时写两套**。

**推广**：任何由 JS 写 CSS 变量、再由组件读取的链路，**迁移时必须两端同步改名**，
或写入端双写。判据：改一次主题/主色，实机看 `getComputedStyle` 读回的值是否跟着变。

## 九、验证方法论（本轮沉淀，可复用）

| 教训 | 实例 |
|---|---|
| **测试自身会错** | 跨行正则 `[^"']*` 吞掉多行 JSX → 产出 285 条假「丢失文案」；改单行匹配才可信 |
| **自述 ≠ 证据** | 子代理报 schema 失败，实为「汇报格式不符」，活儿已干完 → 必须独立核验 |
| **谨慎的自述也要证伪** | 子代理 3 项「潜在缺陷」（`pt-4.5` 无效/`--muted-foreground` 未定义/`color-mix` 不兼容）实测**全不成立** |
| **判据要能分辨真伪** | 路由验证 404 有歧义（未注册 vs 账号未登记）→ 必须读响应体区分 |
| **真因 ≠ 表象** | 页面空白真因是 harness 缺 Provider，非页面缺陷 |
| **删旧体系 ≠ 删文件** | 旧文件里藏着**被 JS 引用的属性选择器**，删前必须枚举 `[attr]` 选择器并核对 JS 写入值 |
| **DOM 探测测不出 JIT** | 合成元素的 computed style 恒为空——Tailwind 只生成源码里出现过的类；必须查**构建产物 CSS** |
| **vision 只作线索** | 判「对比度不足」→ 实测 7.66:1 / 6.28:1（超 WCAG AA）；须以数值裁定 |

**专项验证证据**（本轮）：
- `npx tsc -b` → EXIT=0（全程多轮）
- 平台路由 `TestClient` → 6/6 通过；基座方法 `hasattr` → 14/14 全在
- 浏览器实测 14 页 → 0 渲染异常，DOM 25438~55988 字符
- 主题实机 → `day` / `aerospace` 双向切换生效
- `npx vite build` → EXIT=0，2407 modules
