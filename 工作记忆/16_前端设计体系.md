## 三、主题系统（**曾有断链，已修复**）

| 属性 | 取值 | 说明 |

### 🔴 删除旧 CSS 暴露的三处断链（教训）

旧 `theme-glass.css` 里定义了 `[data-theme="day"]` 与 `[data-glass-frost]` 的整套规则，
**删除文件后主题系统静默失效**——因为 JS 的属性选择器引用不在任何 `className` 扫描里。

修复（现都在 `tokens.css` / `accents.ts`）：

1. `tokens.css` 补 `[data-theme="light"], [data-theme="day"]` 双选择器（兼容历史写法）
2. `tokens.css` 补 `html:not([data-glass-frost]) .glass-premium { backdrop-filter: blur(14px) }`
3. `accents.ts` **双写**两套变量名（见 §七）

**实机判据**：切 `day` → 底色 `#f5f5f7`；切回 `aerospace` → `#0e0e14`。

## 七、🔴 变量名双写铁律（本轮踩坑）

**问题**：`theme/accents.ts` 用 `setProperty` 写的是**旧变量名**（`--accent` / `--accent-bg`），
而重设计后的组件读**新令牌名**（`--color-accent` / `--color-accent-soft`）。
→ 用户改主色，界面**不变**（写进无人读的变量）。

**处置**：`accents.ts` 现**同时写两套**。

**推广**：任何由 JS 写 CSS 变量、再由组件读取的链路，**迁移时必须两端同步改名**，
或写入端双写。判据：改一次主题/主色，实机看 `getComputedStyle` 读回的值是否跟着变。

## 十二、前端元素选择模式（Element Inspector，v0.43.93）

**背景**：Tauri 生产构建**没有 DevTools**（右键检查不可用），前端排查时无法把「界面上看到的
控件」映射回「源码里的哪个组件 / 哪个 `data-od-id`」。本项目已有 `data-od-id` 稳定锚点体系
（73 处），本工具即它的可视化取址入口。

**入口：全局顶层悬浮（左下角「◎ 元素选择」胶囊按钮）**。
> 2026-09-19 用户定调（勿回退）：原实现把按钮挂在 TopBar `topRight`，用户判为
> 「**这个入口不合理，把该入口设定为全局顶层悬浮**」。旧做法两个硬伤：
> ① 未登录时 `AppShell` 不渲染 ⇒ **登录框/闪屏阶段看不到入口**（而那正是最需要定位的时候）；
> ② 挤在状态徽章/退出/窗口控制之间，不像调试工具该待的位置。
> 现为 `position:fixed; left:14px; bottom:14px`，`z-index` 高于结果面板与所有业务层；
> **在 `App` 的登录门分支与主界面分支各渲染一次**（两处条件互斥，同时只存在一个实例），
> 因此闪屏 / 登录门 / 主界面三阶段入口恒可见。左下角是刻意的 —— 避开右下角的结果面板。
> 进入选择模式时按钮转为激活态（accent 描边 + 呼吸动画 + 文案变「退出选择」）。

**可拖动（2026-09-19 追加需求：「这个按钮设定为非固定位置可以长按拖动」）**：

- **长按阈值 `DRAG_HOLD_MS = 160ms`** 才进入拖动 —— 短按仍是「开关选择模式」，
  两种手势互不干扰。**关键判据：不能用 `onClick` 切模式**（拖一下就误切换），
  开关逻辑必须写在 `pointerup` 里按「是否移动过/是否进入拖动」分流。
- 实现：pointerdown 记基准 → 长按后 `setPointerCapture` 接管指针（移出按钮也不断）
  → pointermove 更新坐标（夹在可视区内）→ pointerup 落位并**记住位置**；拖动结束不触发短按。
- **位置记忆**：`localStorage["dy.inspector.pos"] = {x,y}`（**只存坐标**）——
  本工具唯一允许碰 localStorage 之处；守卫测试已显式豁免并**限制为单一键**。
- **防丢**：视口 resize 时把按钮夹回可视区；**双击复位**到默认左下角并清除记忆。
- `touch-action:none`（防浏览器把指针手势抢去做滚动）；拖动中禁过渡/位移（保证跟手）。

> 验证：`scripts/verify_inspector_drag.py`（**11 项**，真实鼠标 `mouse.down/move/up` 驱动）
> ——短按切模式 / 长按拖动跟随 / 松手不回弹 / 拖动不误触发 onClick / 写 localStorage /
> 刷新后位置保留 / 双击复位并清记忆 / 复位后短按仍可用 / 长按不移动不误切 / 无 pageerror；
> dev 与**生产构建**均 11/11 PASS。

**交互**：悬停高亮 → 点击选中 → 面板给出 CSS / XPath / Playwright / 组件链 / 结构 / 状态；
`↑↓` 父↔子、`←` 上移一层、`c` 复制、`Esc` 退出。面板「复制全部」产出可直接粘贴的取址报告。

**设计契约（未来同类需求照此办理）**：

1. **只选择、不触发** —— 必须三件事同时成立，缺一即静默破约：
   ① 拦截清单覆盖 `click/pointerdown/pointerup/mousedown/mouseup/contextmenu/submit` 等
   （**菜单类组件在 `pointerdown` 就展开**，只拦 click 无效）；
   ② 在 **window 捕获阶段**注册（`addEventListener(ev, fn, true)`），否则 React 委托根先收到；
   ③ `preventDefault + stopPropagation`。
2. **零业务耦合** —— 只读 DOM / React fiber，不读不写任何 API、store、localStorage；
   挂载点收敛为 TopBar 按钮 + App 根部面板两处，业务组件零改动。
3. **取址优先级**：`#id`（全局唯一）→ `tag.稳定类名`（root 内唯一）→ `tag:nth-of-type(n)`；
   **哈希类名永不入选择器**（构建期会变）。XPath 优先锚定最近 `data-od-id`。
4. **降级诚实**：fiber 属实现细节，生产构建压缩组件名 → 显示「不可用」，**绝不显示 `ep`/`t`
   这类压缩名**（误导性信息比不显示更糟）。React 组件按 PascalCase 约定过滤。

**实测捕获的 3 个真缺陷（都应进防线）**：

| 现象 | 根因 | 修法 |
|---|---|---|
| 能选中（高亮变）但**面板永不出现** | `swallow` 与 `onClick` 是 `click` 上**兄弟监听器**，`stopImmediatePropagation` 连自己的 `onClick` 一起吞 | 去掉 `stopImmediatePropagation` |
| 选择器/类名里混入 `ei-hover` | 工具自身悬停类被当业务类 | `classListOf` 过滤 `ei-` 前缀 |
| 点「复制全部」**毫无反应**（连提示都无） | `${(__APP_VERSION__ as string) \|\| "?"}`：**模板里的 TS 类型转换让 Vite `define` 常量替换失效** → 运行时未定义 → `ReferenceError` **被 async promise 静默吞掉** | 包 `frontendVersion()`：`try/catch + String(__APP_VERSION__)`（同 `api/client.ts` 惯例） |

**通用教训**：`define` 注入的常量一旦被包进类型转换/复杂表达式，替换即失效；且 **async
函数里的 `ReferenceError` 无 pageerror、无 console，静默消失** —— 排查必须直读**构建产物**，
不能只跑 dev server（dev 下 `__APP_VERSION__` 反而存在，问题只在产物暴露）。
