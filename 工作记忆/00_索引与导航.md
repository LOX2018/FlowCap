## 二、分类原则（与旧库的根本差别）

### 旧库的问题（实测）

```
按「问题」组织：00_架构 / 01_打包 / 02_指纹 / 03_私信 / ... / 16_前端
    ↓
每页都是「某个时间点对某件事的现场描述」
    ↓
世界变了，描述不再成立，但从未被替换 → 越积越乱 → debug 被干扰
```

实测证据：`fingerprint-chromium`（已弃内核）在库内 52 页/143 次；
`im/user/info` 被动 hook（已推翻方案）28 页/55 次；版本号 `0.43.x` 946 次与 `0.44.x` 301 次混杂。

### 新库的原则

> **按「知识的有效期」分层，而不是按「问题」分章。**
> 每页必带 `实测日期` + `判据` + `有效期/失效条件`；失效即**替换**，不追加。

| 层 | 目录 | 有效期 | 组织依据 |
|---|---|---|---|
| **L0 第一性** | `00_爬虫项目说明.md` | **永久**（爬虫本质不变） | 爬虫理论 + 项目定位 |
| **L1 现役知识** | `01_~09_*.md` | **天级**，必须全部当前有效 | 采集链路分层（见下） |
| **L2 历史现场** | `cases/` | 永久存档，**允许陈旧** | 按日期，检索时必看日期 |
| **L3 外部情报** | `10_上游源项目情报.md` | 随上游版本，**须标注针对版本** | 源项目逆向 |

**铁律**：L1 里任何一条失效，**就地改写或删除**；不允许「保留历史留痕」——
历史留痕属于 `cases/`。**这是防止再次腐化的唯一机制。**

## 三、L1 现役知识的组织：按「采集链路分层」

爬虫的通用链路（`00_爬虫项目说明.md` §3.1）：

```
采集目标 → 身份/会话语义 → 传输(HTTP/WS/浏览器) → 签名与凭证
  → 反爬对抗 → 解析(协议/结构) → 归一化 → 落库 → 效果度量
```

**本项目分册与链路的对应关系**（每层必须能独立回答「本层当前是否工作」）：

| 分册 | 对应链路层 | 回答的问题 |
|---|---|---|
| `01_铁律与红线.md` | 全局约束 | 哪些红线不可碰（风控/设备/启停） |
| `02_效果定义与探针.md` | **效果度量（M1/M3/M7）** | **「现在这个能力行不行？」** ← 缺失项，最优先 |
| `03_采集链路总览.md` | 全链路 | 五条业务链的地图 + 各层当前状态 |
| `04_身份与会话语义.md` | 身份/会话 | 账号身份、会话标识、方向判定的口径 |
| `05_端点与协议台账.md` | 传输/解析 | 逐条实测的端点与协议（**带实测日期**） |
| `06_凭证与签名.md` | 签名与凭证 | 凭证获取/校验/失效判据、签名机制 |
| `07_反爬对抗.md` | 反爬对抗 | 内核/指纹/代理/节流/行为 |
| `08_解析与落库.md` | 解析/归一化/落库 | 协议解析口径、去重、字段规范 |
| `09_环境与构建.md` | 工程支撑 | 数据根/构建/部署/版本 |
| `10_上游源项目情报.md` | 外部参照 | 源项目事实（针对其版本） |
| `cases/` | 历史现场 | 每次事故的完整取证链（按日期） |

## 四、每页的强制格式

```markdown
# <标题>

> 性质: 现役知识 / 历史现场 / 外部情报
> 实测日期: YYYY-MM-DD          ← 必填，无日期视为无效
> 判据: <怎么验的>              ← 必填
> 有效期/失效条件: <什么情况下本条作废>  ← 必填
> 状态: 有效 / 【未决假设】

<正文：一页一事实>
```

**缺任一必填项 = 违反库规范，不得提交。**

## 五、维护纪律（防止再次腐化）

1. **作废用替换**：方案被推翻 → **改写原页**（标注替代方案），**不新增解释页**。
2. **一页一事实**：不写「本轮做了 ABC」的流水账；流水账进 `cases/`。
3. **未验证的推测**必须显式标 `【未决假设】`，否则视为造假。
4. **数字必须现场重算**（正则扫描有系统性偏差，如本次体检初测 623 → AST 精确 340）。
5. **定期体检**判据：

| 检查项 | 健康判据 |
|---|---|
| 主题页数 | 单主题 ≤ 8 页 |
| 重复页对 | 0（规范化标题后同名必须合并） |
| 断链 | 0 |
| 已废弃方案名残留 | 0（仅 `cases/` 可保留，且须标「已作废」） |
| 每页必填项 | 100% 完整 |
| 现役版本号 | 「现役」语境下唯一 |

## 六、本库与「实时外界知识」的关系

用户明确的定位：

> 「真的没有那么多的参考信息，更多的参考的是**实时的外界知识**和**基本的爬虫理论**」

因此本库的**正确用法**是：

```
遇到问题
  ↓
① 读 `00_爬虫项目说明.md`（爬虫理论 + 纪律）—— 这层永远有效
  ↓
② 读对应链路分册的 L1 现役知识（带实测日期）—— 判断是否仍成立
  ↓
③ 若 L1 知识已过失效期 → **必须重新实测**，不得直接沿用
  ↓
④ 实测结果 → 更新 L1（替换）或写入 cases/（历史）
```

**禁止**：把 L2/L3（历史现场、外部情报）当 L1（现役）用。
**这正是旧库最大的失效模式**——把「以前定性」当 A 级证据（见 `00_爬虫项目说明.md` §3.3 数据可信度分级）。
