## 三、BCC 拉起的坑（本次实测教训）

1. **源码目录直接拉 BCC 二进制会找不到账号**：报「账号 .env 未登记」——`app_root()` 解析到源码目录而非部署目录。必须从**部署目录**（`C:\temp\dyautodm_design\binaries\`）spawn，或走后端 `ensure_bcc()`。
2. **⚠️ profile 锁未释放时拉 BCC = 浏览器无限新开窗口（抱死）**：查看模式有头 chrome 占着 profile 时，BCC `_launch` 启动失败 → `_ensure_alive` 判定 context 失活不断重启 → 无限开窗。**拉 BCC 前必须先释放 profile 锁**：`POST /api/accounts/<名>/stop-browser`（优雅，走守护自身 /quit）或确认 chrome 已全退（`tasklist | grep -c chrome` = 0）。**绝不 Stop-Process 强杀**。
3. 止损顺序：BCC `POST /quit`（优雅，context.close + os._exit）→ stop-browser → 确认 chrome 进程数归零。

## 五、用户搜索功能放弃（2026-09-07 决策）

- **结论**：采集页 `kind="user"` 入口彻底移除，**前端不再有"搜用户"UI**，后端保留原基座调用代码（不删，万一抖音放开即可恢复）。
- **根因**：基座 `DouyinAPI.search_some_user` 走 `/aweme/v1/web/discover/search`，抖音 2025-2026 对此接口全面加 `verify_check` 二次验证风控（status_code=0 但 user_list=[] / search_nil_type=verify_check）；基座项目在此功能上同样失效，不是 V2 实现 bug。
- **替代方案**：用户覆盖用例完全由「搜视频 → 取作品作者 / 评论区 → 评论用户」覆盖，**这两种路径均不触发 verify_check**（verified: 实测 16:43 / 17:10）。
- **修复点**：`frontend/src/pages/crawl.tsx` 删除 `CrawlMode` type、`mode` state、用户/视频切换器、user 行渲染分支，desc 文案「搜视频/用户」改「搜视频」；`kind: mode` 固定为 `"video"`。

## 六、视频封面为空（2026-09-07 修复）

- **症状**：采集页视频卡 thumb 区域全是渲染的 `linear-gradient` 占位图，无真实封面。
- **根因**：后端 `_map_video` 解析 `video.cover_url_list`（旧版字段），抖音 17.x 接口已**弃用**此字段为 `[]`；新结构是 `video.cover / origin_cover / dynamic_cover` 直接是 dict with `url_list[]`。
- **修复**：
  - `backend/api/crawl.py` `_map_video`：cover 解析顺序 `origin_cover > cover > dynamic_cover`，从 `dict.url_list[-1]` 取最后一档（通常最大）。
  - `frontend/src/pages/crawl.tsx` 视频 thumb：优先用 `backgroundImage: url(cover)`，无 cover 时回退到 gradient；评论抽屉 head 加 56x56 封面缩略图。
- **验证**：探针确认 `cover.url_list` 含真实 `https://p3-pc-sign.douyinpic.com/...` URL（`verified: 实测 18:37`）。
- **后续坑**：封面 URL 带 `~tplv-dy-resize-origshort-autoq-75:3` 缩放指令，**默认走抖音 CDN 防盗链允许直接 `<img>` 加载**（无需 Referer / 签名）；若以后发现加载失败优先看 `referrerpolicy="no-referrer"` 是否要显式设置。

## 七、新应用账号丢失（2026-09-07 现象）

- **症状**：重启 `dyautodm-v2.exe` 后采集页显示「无可登录账号」，`/api/accounts` 返回 `[]`；但 `accounts/<name>/.env` 文件磁盘上仍存在。
- **根因**：账号索引完全在 SQLite `kv_store["accounts_index"]` key 里（不是文件系统扫描），新 backend 进程内存里无索引；**`accounts.json` 已被废弃**，代码里看 `accounts.json` 找不到任何东西。
- **修复**：调 `POST /api/accounts {"name": "..."}` 把磁盘上已有的 .env 重新注册进索引（**幂等**）；之后 `/api/accounts` 即返回完整列表。
- **铁律**：改 `auto_dm/accounts.py` 看到 `accounts.json` 关键词要意识到是历史命名，实际已迁 SQLite kv_store。
