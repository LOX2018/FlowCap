## 〇、一句话总览

> 抖音 Web 现役签名以 **`a_bogus`**（bdms 1.0.1.19-fix.01，SM3 + 魔改 RC4，**已有纯 Python 实现且实机通过**）为核心，
> 配 `msToken` / `ttwid` / `verifyFp` / 设备指纹 `dtrait`，
> 并对**部分接口叠加 `x-secsdk-web-signature`(Uifid)** 与 `_signature`；
> **`X-Bogus` 在抖音端已基本废弃**（仅 TikTok / 部分直播留存）；
> **IM（imapi.douyin.com）走 protobuf + cookie，与 Web 签名体系完全不同**——
> 读路径**无需签名**，写路径以**会话级 ticket** 为主，仅企业号侧才见 `ts_sign`/`sdk_cert`/ECDSA `request_sign` 这套 TicketGuard 体系。

## 一、现役签名参数全表

| 参数 | 域 | 生成方式 | 状态 | 关键事实 |
|---|---|---|---|---|
| **`a_bogus`** | web | **纯 Python 可行** | ✅ current | 当前 Web 数据接口**主签名**。源头 `bdms.js v1.0.1.19-fix.01`（字节码 VM，程序 `fn150`），**非** webmssdk/secsdk 产物。常量 `aid=6383`、`page_id=6241`、**SM3 二次哈希（盐 `dhzx`）**、**魔改 RC4**、自定义 base64（表 `s3`/`s4`），输出 180~192 字符含随机噪声。**服务端解密校验而非重算**。evil0ctal 已于 2026-09-09 纯 Python 重写并 **24/24 live 通过** |
| **`msToken`** | web | 纯 Python / 第三方 | ✅ current | 两路：①本地伪造 `genFalseMsToken`（长度 126 抖音 / 146 TikTok，字符集含 `+-`，尾部 `==`，多数接口可用）；②真实申请 `mssdk.bytedance.com/web/report`（payload `{magic:538969122,version:1,dataType:8,strData,spyFromClient}`，从 Set-Cookie 取，真实长度 120/128） |
| **`ttwid`** | web | **纯 Python** | ✅ current | 游客 cookie。`POST https://ttwid.bytedance.com/ttwid/union/register/`（`aid=1768` 抖音 web / `6383` 直播 / `1128` 西瓜），有效期约 **365 天**。**缺它直接 403** |
| **`x-secsdk-web-signature`** | web | **纯 Python** | ✅ current | **secsdk API 签名保护层**：`sig = md5(f"{uifid}_{timestamp}_{SALT}_{query}")`，`SALT='A96D855A08C0A9707F8BEF0D9A527E4E'`（源自 `lf-security.bytegoofy.com` 的 `runtime_bundler_34.js`，`@byted/secsdk-strategy v1.0.40`，project-id=34）。随请求发 `uifid` / `x-secsdk-web-signature` / `x-secsdk-web-expire` 头。缺失即 **403 `Blocked by ArgusSecurityPlugin Uifid Not Found`**。**仅部分路径被保护**（14 个 GET：`aweme/detail/`、`aweme/post/`、`favorite/`、`mix/aweme/`、`tab/feed/` 等）；2026-09-08 实测纯 Python 24/24 通过 |
| **`_signature` / `__ac_signature`** | web | **必须浏览器/JS** | ✅ current | webmssdk 路径产物（`SignatureAlgorithm._signature`）。**native 不产**，必须 browser-rpc 或抠 JS 补环境。`__ac_signature` 47 字符，`byted_acrawler.sign('', __ac_nonce)`，写 cookie 后 reload，用于视频页临时身份 |
| **`x-tt-session-dtrait`** | web | JS 采集 + Python 加密 | ✅ current | Passport/login **设备指纹头**。RSA-2048 包裹 (AES key‖iv) + AES-128-CBC 加密指纹 payload（源库 `uc-secure-dtrait-core`，87KB JSVMP），段长形如 `d0_<b64>_<b64>`。**关键：必须每次请求现场生成，复用旧值必被 `error_code 2156` 拦** |
| **`x-tt-passport-aid-sign` / `sign` / `qs` / `enc`** | web | **纯 Python** | ✅ current | Passport 网关（`login.douyin.com/passport/web/*`）专用。`enc = hex(utf8(s) XOR 0x05)`；`sign = sha256(params排序前10 + '&' + body全部 + '&app_key=' + APP_KEY)`，**`APP_KEY=163e7ce78d58971a41f5b969996d85c2`**（aid=6383）；`qs = enc(前10键名)`；`x-tt-passport-aid-sign = HMAC(HKDF-Expand(HMAC(ts,appKey)), 'aid=…&path=…&ts=…')`，**ts = 当天 12:00 UTC**（整天不变）。均已逐位对齐抓包 |
| **`bd-ticket-guard-client-data`** | web | ECDH+RSA/ECDSA | ⚠️ current（**无纯 Python 实现**） | **TicketGuard / 风控层**，用于创作者**写接口**（`/web/api/media/aweme/create/`、`commit/item/digg/` 等）。从浏览器 localStorage 取 `security-sdk/s_sdk_crypt_sdk` 的 `ec_privateKey` 与 `security-sdk/s_sdk_sign_data_key/web_protect` 的 `ts_sign` 算出。配套头：`Bd-Ticket-Guard-Client-Data` / `-Iteration-Version` / `-Ree-Public-Key` / `-Version` / `-Web-Sign-Type` / `-Web-Version`。**uncertainty：公开明文结构与算法（ECDSA vs RSA-OAEP）互相矛盾，须现场抓包** |
| **`X-Bogus`** | web | 纯 Python / JS | ❌ **deprecated** | **抖音 Web 已被 a_bogus 取代**（MediaCrawler #297「抖音 x-bogus 已彻底失效，更换了 a-bogus」；B1gM8c/X-Bogus #12「xb 不可用了」）。**仅 TikTok Web 与部分抖音端点/直播仍接受**（webmssdk 1.0.0.20 的 `byted_acrawler.frontierSign` 仍产 16 字符，用于直播等） |

## 二、IM 侧签名（`imapi.douyin.com`）—— **与 Web 完全不同**

### 2.1 机制

```
imapi.douyin.com 使用 protobuf（application/x-protobuf）+ cookie(sessionid, HttpOnly) 鉴权
与 Web 的 a_bogus / msToken / x-secsdk 体系无关
```

| 路径 | 是否需要签名 | 证据 |
|---|---|---|
| **读**（`get_by_conversation` cmd301 / `get_message_by_init`） | ❌ **不需要** | 实测 URL 无 `a_bogus`/`msToken`，请求体内无 `ts_sign`/`sdk_cert`/`req_sign`，**纯 cookie 即可 POST，且可无头**。creatorhub 与 my-jxy/douyin-im-export **两处独立实现互相印证** |
| **写**（`send` cmd100 / `create` cmd609） | ⚠️ **以会话级 ticket 为主** | `ticket` 来自会话信息 protobuf `field 1..4` 的 `id`/`short_id`/`type`/`ticket`。creatorhub 2026 抓包**未见** `req_sign` 与额外安全头，仅 cookie + ticket |
| **写（企业号侧）** | ⚠️ 可能携带完整签名套件 | CSDN 企业号 IM 逆向（2026）显示发送体含 `token`/`sdk_cert`/`ts_sign`/`req_sign`，其中 `req_sign` 为基于 EC 私钥的 **ECDSA(SHA256, DER)** 签名，对 `conversation_id`/`short_id`/`content`/`timestamp` 明文签名；`ts_sign` 形如 `ts.1.`/`ts.2.`+hex；`sdk_cert` 为证书 |

### 2.2 参数清单

`ticket` · `ts_sign` · `sdk_cert` · `reuqest_sign`(ECDSA/SHA256-DER) · `token` · `sequence_id` · `conversation_short_id` · `client_message_id` · `device_platform` · `channel` · `auth_type`

### 2.3 对本项目的意义

- ✅ **印证**：本项目 IM 读路径纯 cookie + protobuf 是**正确且已被两个独立开源项目验证**的
- ⚠️ **待验**：写路径是否需 `req_sign` **依账号类型而定**（普通号 vs 企业号）→ 须按本项目账号类型现场抓包
- ⚠️ 本项目已知的 `ticket`/`ts_sign`/`sdk_cert` + `bd-ticket-guard-*` 头，与 **TicketGuard / Passport 网关同源**

## 五、待验问题（uncertainty，须现场抓包定论）

1. **`a_bogus` 盐值**：`'dhzx'`（evil0ctal/hanzheng，对 bdms 1.0.1.19-fix.01 实证）vs `'cus'`（creatorhub 自述同版本）→ 疑为**不同版本或不同索引字段**
2. **creatorhub 的纯 Python abogus 是否真与线上对齐**：常量子串与 evil0ctal 不同，需用同一 `(query, UA, fp)` 与真浏览器/Node 签名器**对拍**后才能判定可用
3. **`mssdk.bytedance.com/web/report` 是否仍有效**：f2 issue #438（2026-04）称已无法触发，而 creatorhub（2026-09 仍更新）仍在使用 → 真实 msToken 申请路径可能已迁移
4. **是否已对部分接口强制 `x-secsdk-web-signature`(Uifid) + `a_bogus` 双校验**：受保护路径 14 个，须按本项目实际打的端点核对**保护名单是否漂移**
5. **imapi 发送（cmd100）是否真不需 `ts_sign`/`sdk_cert`/`req_sign`**：creatorhub 说没有，企业号逆向说有 → **按本项目账号类型现场抓包分别验证**
6. **`ts_sign` 与 `ec_privateKey` 生成算法无公开纯 Python 实现**：是否只能靠读 localStorage + 自算 ECDH/ECDSA，未证实
7. **TicketGuard 明文结构与算法公开说法冲突**：`{ts_sign,req_content,req_sign,timestamp}` vs `{ticket,ts_sign,client_cert}`；ECDSA vs RSA-OAEP → 须 base64 解码 + 逐字段对标
