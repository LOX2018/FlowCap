## 五、交接卡纪律：**编号制 + 单活跃 + 归档不冗余**（2026-09-22 用户定）

> **用户原话**：「使用交接卡新开的会话时需要清理陈旧交接卡，不能冗余。交接卡也需要命名代码，
> 方便我直接用 XX 交接卡指定交接卡，避免使用混乱」

### 5.1 命名规范（用户可直接用编号点名）

```
交接卡_HC-<NN>_<主题关键词>_<YYYY-MM-DD>.md
        ^^^^^^  例：HC-01、HC-02 …
```

- **`HC-<NN>` = 交接卡唯一代号**，创建时分配、**永不复用、永不重排**（改了会让人认错卡）。
- 用户可用「**HC-01 交接卡**」直接指定，不必说长文件名。
- 卡**正文首行**必须回写编号 + 状态（`🟢 活跃 / ⚪ 已完成 / 📦 已归档`），
  使「打开文件即知它是哪张、还活着没」。

### 5.2 三条铁律

| 铁律 | 判据 |
|---|---|
| **单活跃** | `artifacts/` 顶层**同时最多 1 张** `交接卡_HC-*.md`。开新会话 → 先把旧卡归档，再新建 |
| **不冗余** | 归档不是堆积：卡里**尚未完成**的事项必须先抽到本台账（§一~三），抽完才归档；台账已完成项就地删行 |
| **不静默删** | 归档**而非删除**（历史需可回捞）。**唯一例外**：从未入库（`??`）且事项**已全部闭环**的卡可直接删，无需留档 |

### 5.3 归档流程

```
artifacts/交接卡_HC-NN_….md        ← 活跃（顶层，最多 1 张）
        ↓ 开放事项已抽入本台账 + 状态置 ⚪/📦
artifacts/handoff_archive/交接卡_HC-NN_….md   ← 归档
```
