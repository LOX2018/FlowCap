## 一、为什么拆（以及为什么不是「按标题归类」）

原 `05_端点与协议台账.md` 是 **4 份文档拼接**，主体是原 `08 私信列表及会话详情捕获方案`
（**225KB / 4715 行 / 55 个二级节**）。它**不是**按主题组织的，而是**按时间顺序的修复实录**
（「2026-08-29 实测」「v0.31.2」…），同一主题被时间切成多段，且存在**重复节号**
（`三十一` / `三十八` 各出现两次）。

⇒ 因此**不做跨区段重排**（那会在 4715 行里手工搬运、极易丢内容），
而是**按连续区段拆分**：零内容损失、可逐字节校验，且每份都降到网关可摄入的体积。

## 三·甲、路由登记（增量，2026-09-22）

### 3·甲.1 直播间登记表（房间层，ADR-003）—— 新增 `api/live_rooms.py`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/live/rooms` | 列出全部已登记房间 |
| GET | `/api/live/rooms/{rid}` | 取单条（`rid` = 记录 id `lr_<epoch_ms>`） |
| POST | `/api/live/rooms` | 新建/更新（按 `id` upsert；空则生成） |
| DELETE | `/api/live/rooms/{rid}` | 删除**房间记录**（不动任何策略） |
| POST | `/api/live/rooms/migrate` | 一次性迁移存量「房间形」旧策略记录（**默认干跑**；`apply:true` 才写） |

**存储**：kv `live_rooms`（ADR-003 §3.2 契约）。与策略层 `live_room_configs` **物理分离**：

```
live_room_configs（策略：怎么发，零身份）  ← strategy_id 引用 —  live_rooms（房间：在哪发）
```

**引用完整性（新增不变式）**：`DELETE /api/live/config-tags/{sid}` 现在会**自动解绑**
所有 `strategy_id == sid` 的房间，并在响应里返回 `unbound: N`（悬空引用 = 0）。
⚠️ 该端点原有注释「删除无任何跨模块解绑副作用」**已作废**（被 ADR-003 部分逆转）。
