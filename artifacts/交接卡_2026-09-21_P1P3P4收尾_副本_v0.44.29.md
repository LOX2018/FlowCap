### 昵称归零根因修复（v0.44.29，本次核心收获）

**关键事实**：探针报 `failed 0.0` 是**假失效**，不是链路真挂。

| # | 发现 | 证据 |
|---|---|---|
| 1 | DB 里 `peer_name` 98.9% 真实昵称（87/89）是**历史遗留**，不反映当前链路 | DB 直查 |
| 2 | 09-14 → 09-21 共 **86 次**写库，**全部** `uid关联=0`，但**真实链路**（浏览器路径）实测 `uid关联=44/44` | 手动 `capture_all(with_browser=True)` 实机验证 |
| 3 | 根因：`recv_daemon._safe_capture(name, with_browser=False)` 启动时移抓一次，**按设计不抓昵称** | `daemon/recv_daemon.py:1183` + 日志时序 |
| 4 | 另一根因：`main._nickname_sync_background`（带浏览器的后台自动捕获）**从未运行**（日志 0 条） | 日志全库搜；后查明是 `DY_AUTO_CAPTURE_ON_START` 门控（用户 08-29 风控决策） |
| 5 | 探针判据只取「最新写库完成行」，不区分路径 → 把「按设计不抓昵称」当失效 | `services/probe.py` 原逻辑 |

**修复（v0.44.29）**：

| 改动 | 位置 | 向后兼容 |
|---|---|---|
| 日志行追加 `with_browser={1|0}` | `conversation_capture.py:2021` | ✅ |
| `_RE_WRITE` 正则增可选组 `(?:\s*with_browser=(?P<wb>[01]))?` | `services/probe.py:182` | ✅ 旧行组为 None |
| `latest_capture_facts(..., with_browser=None)` 过滤参数 | 同上 | ✅ |
| 时间戳比较取代「文件顺序覆盖」 | `services/probe.py:275` | ✅ |
| 判定分流：`with_browser=0` 若无带浏览器证据 → **unknown（而非 failed）** | `services/probe.py:421` | ✅ |
| 新增 4 个单测（含「只有首包」反例防回归） | `test_capability_probe.py` | ✅ 35/35 PASS |
| 案例归档 | `工作记忆/cases/2026-09-21_昵称关联归零实为探针误报_v0.44.29.md` | ✅ |
